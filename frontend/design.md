# Akashic 前端设计合同（design.md）

本文件是所有前端工作的唯一设计入口：修改 `frontend/**/src`、插件 web UI（`frontend/plugins/`）或 `plugins/*/web_module.*` 前必读。它规定可观察的几何、token 和反模式；品牌理由与迁移历史见 [0043](../docs/decisions/0043-paper-brand-tokens-replace-material-visual-semantics.md) 与[纸张品牌系统](../docs/design/akashic-paper-brand-system.md)，窄屏行为细节见[共享 Web 窄屏阅读设计](../docs/design/web-narrow-reading.md)。规则冲突时以本文件的几何合同为准，以决策记录的理由为准。

写法约定：每条规则必须可以观察或测量（"输入文字左缘 == 消息正文左缘"），不写主观词（"干净""高级感"）。评审中重复出现的视觉纠正，落成这里的一条规则、一个 token 或一个脚本检查，而不是逐处手调。

## 1. 品牌原则：克制的纸感

页面是一张连续纸面。纸感只由四件事承担：排版、留白、墨色层级、细规则线。

- 允许：纸面层级 `--ak-paper-*`、墨色层级 `--ak-ink-*`、规则线 `--ak-rule-*`、阅读/技术字体对比、充足且一致的留白。
- 禁止用装饰冒充纸感：位图噪点、`feTurbulence`、随机纹理图、持续动画、拟物阴影。去掉所有装饰后，阅读层级和交互状态必须仍然完整。
- 克制优先：不为了"更像纸"增加任何元素。一个分割线、一个底色层级，只有在它回答"这里是什么结构"时才存在。拿不准就不加。

## 2. Token 合同

组件只消费语义 token，不写裸色值、裸字号、裸阴影。

| 轴 | 前缀 | 用途 |
|---|---|---|
| 纸面 | `--ak-paper-*` | canvas / editing / quiet / sheet / raised |
| 墨色 | `--ak-ink-*` | primary / secondary / muted |
| 规则线 | `--ak-rule-*` | subtle / default / strong / focus |
| 字体 | `--ak-type-*` | reading / technical |
| 状态 | `--ak-color-status-*` / `--ak-sys-color-*` | success / warning / error / trace / info |
| 动效 | `--ak-sys-motion-*` / `--ak-sys-duration-*` | 曲线与时长 |

布局几何同样只有一个 owner：

| 值 | owner | 消费者 |
|---|---|---|
| 阅读列宽 | `.chat-main` 的 `--chat-column` | 消息正文、composer、回到底部按钮 |
| 阅读列内边距 | `.chat-main` 的 `--chat-dock-inset` | 消息区 padding、窄屏 composer inset、短屏 margin |
| 用户气泡上限 | `.chat-main` 的 `--chat-bubble-max` | `.user-bubble` |
| 输入卡文字 inset | `.chat-main` 的 `--composer-text-inset` | composer padding、stats 行 |
| 侧栏留白 | `--chat-rail-inline` | 侧栏所有行的左竖线 |
| 浮层遮罩 | `:root` 的 `--ak-scrim-overlay` | 设置弹窗、模型弹窗、窄屏侧栏与模型/思考强度抽屉（`--chat-scrim` 转接） |
| 浮层阴影 | `:root` 的 `--ak-elevation-overlay` | 设置弹窗、模型弹窗、配置确认弹窗 |

遮罩只压暗、不提亮：基于 `--ak-color-shadow`（深色主题为黑），不得用墨色混色——深色主题的墨色是浅色，会把背景刷灰。深色底需要更高不透明度（22% / 45%，`light-dark()`，不支持时 28%）。浮层阴影同样基于 `--ak-color-shadow`，深色主题不产生浅色光晕。

新组件不得新增 `--md-sys-*` 直接依赖（旧 namespace 是迁移期 transport alias）；不得为设想中的组件提前发布 token；同一几何值出现在两处时，先收进上表的某个 owner。

混色一律 `color-mix(in oklab, …)`，不用 `in oklch`：Chromium 混两个近中性色（暖灰墨色、纸色、透明）时把结果色相记成 `none`，按 0° 渲染，暖灰被染成粉（浅色引用条曾渲染成 242,233,235，深色发丝线偏品红）。oklab 不插值色相，与透明混、浅色调的结果与设计意图一致；真要在两个高彩度色之间保彩度时再单独评估。

强制颜色（Windows 高对比度，`@media (forced-colors: active)`）下背景色会被系统统一替换：只靠底色表达的状态必须另有表达。规则集中在 styles.css 末尾一个块里：品牌标记、会话状态点与旋涡、轮次刻度、后台任务点用 `forced-color-adjust: none` + `CanvasText`（当前轮刻度 `Highlight`）保留形状；当前会话行、当前项目、选中的模型用 `Highlight` 内描边；用户气泡加 `CanvasText` 细边框；输入卡内层不再画第二圈描边，聚焦由外框的 `Highlight` 描边表达。新增只靠底色区分的状态时同步加进这个块。

## 3. 布局与对齐合同

### 3.1 阅读竖线

宽屏（>820px）下阅读列偏左 1/4 留白。下面几条竖线必须重合，误差 0：

- 消息正文左缘 == composer 输入文字左缘。实现方式：composer 卡片以阅读列为中心、两侧各宽出 `--composer-text-inset`，使 1px 边框 + 15px padding 之后文字正好落在阅读竖线上。stats 行用 `padding-inline-start: var(--composer-text-inset)` 跟随同一条线。
- 用户气泡右缘 == 阅读列右缘。
- 用户气泡最高 12 行（`12lh`）：超出时末两行渐隐，下方一行次级文字"展开全部 / 收起"（不是按钮外观）；收起时把开关留在视口内。粘贴的日志、整段代码不再把回复挤出屏幕。视口外的用户气泡占位按同一上限（含开关行）截断，升级为完整行时不塌陷。是否超出只对可能超出的气泡（≥12 行估算、含图片/代码/表格）判断，并观察折叠框与里面不限高的内容层：富渲染会把源码逐步换成高亮代码块，挂载时量到的高度不是最终高度（曾让 1 行代码也显示"展开全部"）；恰好 12 行的正文再晚到一张图时框高不变，只有内容层变。气泡按内容收缩，含代码块、表格、块公式时直接占满允许的最大宽度——这些块的宽度跟着容器走，互相依赖会让只有代码的气泡塌成一条缝（实测桌面 76px、窄屏 26px）；末块（段落、列表、引用、代码、公式）的下外边距在气泡里清零，不在内边距外再叠一段空白。
- "回到底部"按钮对阅读列居中，不是对容器几何居中。
- 输入卡展开（多行、附件、引用、排队、窄屏聚焦）后比紧凑态高出的部分写进 `--composer-grown`，消息区底部留白与回到底部按钮一起让开；贴底阅读时跟着露出最新一条，往上翻着读时不动。最新回复任何时候都不该被盖在输入卡下面。
- 矮视口（含安卓键盘弹起后的 resizes-content 视口）里输入卡要能放下引用＋附件＋草稿并露出发送钮：附件托盘本来就只占一行 64px（见 3.20），正文框最多 3 行后内滚。窄屏引用条四周等距内嵌、圆角与卡片同心。
- 输入卡里的图片、视频缩略图都垫一层"类型图标＋文件名"：能解码时首帧或图片盖住它；浏览器解不了（HEIC、损坏文件）时撤掉 img，不露破图图标和溢出卡片的 alt 文本。
- 宽屏 `--chat-dock-inset` 为 2rem：主区窄于阅读列（侧栏展开的 820–1180px）时，正文离边 32px、输入卡离边 16px，仍保持文字同线；不再出现 12px 贴边。

窄屏（≤820px）下屏幕内边距即阅读边界：composer 卡片左右缘 == 消息正文左右缘 == `--chat-dock-inset`，卡片内部文字有自己的 inset（卡片是独立编辑面，不要求卡内文字与正文同线）。

### 3.2 侧栏一条左竖线

侧栏所有行的图标/文字左缘落在 `calc(var(--chat-rail-inline) + 10px)` 一条线上：工具行、搜索框、分组标题、目的地、会话行、底部动作。嵌套会话的缩进从这条线起算。 搜索框有输入时右端出现清除钮（24px 图形，触屏热区向外扩到约 44px，不撑高搜索框）：触屏没有 Esc，清完焦点留在框里接着搜；与 Ctrl K 提示同一位置，两者不同时出现。

### 3.3 断点只改 token

断点（820px / 36rem / 30rem 高）只允许重定义 `.chat-main` 上的变量值，不允许在 media query 里重写消费方的 padding/margin/width 硬编码。新增断点值前先确认现有三个不够用。确实需要逐断点覆盖几何（如窄屏 composer inset）时，覆盖规则必须写在被覆盖规则之后——同特异性下 CSS 靠源码顺序生效，media query 不提供额外优先级。

### 3.4 safe-area 全覆盖

凡是贴屏幕边缘的条形区域（顶部 band、会话标题行、抽屉、composer、底部动作），水平 inset 一律写成 `max(设计值, env(safe-area-inset-*, 0px))`。不允许只处理 composer 而漏掉标题行或抽屉。

### 3.5 光学对齐惯例

- 图标与文字同行时用 flex `align-items: center`，不用 `line-height` 数值法凑居中。
- 非对称 Lucide 图标沿用现有的亚像素 `translate` 补偿体系（0.5px 级，见 `styles.css` 末尾"光学对齐"区）；新图标按同一方式补，不用 margin 凑。
- 触控目标：窄屏可点区域 ≥44px；桌面行内图标按钮 40px。hit area 的视觉中心必须与图形中心重合。
- 滚动容器不得私自添加 `scrollbar-gutter`、`padding-inline` 或额外的 `%` 基准——阅读列的百分比基准必须与 composer 相同（这是曾导致两侧竖线错位 7.5px 的真实事故）。

### 3.6 次要操作显现合同

消息操作等次要操作默认 `opacity: 0`，父消息容器 `:hover` / `:focus-within` 时在 `--ak-sys-duration-short` 内显现。时间戳与操作同属一条元信息行：有悬停的宽屏只有最新一条消息常驻，更早的消息整行随悬停/聚焦显现；该行固定 28px，40px 操作热区上下透明溢出，显隐只改透明度、不推动正文。窄屏（≤36rem）同理只留最新一条，点按消息显示该条。触控断点（≤820px 或 `hover: none`）hover 不存在，次要操作常驻可见。透明状态不得把按钮移出 Tab 序（禁用 `visibility: hidden` / `display: none`），键盘 Tab 到达时经 `focus-within` 必然可见。键盘焦点统一是 2px `--ak-rule-focus` 墨线、外偏 2px：`styles.css` 开头有一条 `:where()` 零特异性兜底，没写焦点样式的控件也不会落回浏览器默认的 1px 蓝环；组件需要别的焦点形态时自己写 `:focus-visible` 覆盖。

用户自己的提问额外有"放回输入框编辑"（排在引用、复制之前）：原文接在已有草稿之后（空行分隔），不覆盖正在写的内容；聚焦到末尾并按溢出展开输入卡。它不改写历史、不分叉会话，只是"改一改再问"的快捷方式；回复与工具结果不提供。键盘等价物：输入框为空（且无附件）时按 ↑ 取回当前会话最后一条提问，光标置于末尾；有内容时 ↑ 仍是移动光标。选了"引用此消息"后焦点直接进输入框（触屏弹出键盘），引用条显示"回复 Akashic / 回复 你"，内部角色名不外露；引用目标与草稿一样按会话保留（切走再切回仍在，发出或取消后清除，不跟到别的会话）；针对一句追问：鼠标在同一条消息里选中文字后，选区上方浮出墨色反白的"引用"小药丸，点击把选中内容转成 Markdown 引用块（`> `）接到草稿后面并聚焦输入框；跨消息、在可编辑区域里选中不出现，滚动、Esc、选区清空即隐藏；高亮代码在 shadow DOM 里，选区经 `getComposedRanges` 取回真实端点（兼容旧的剩余参数签名）、越过 shadow 边界找所属消息；代码块连着后面正文的跨树选区按树切段（shadow 内剩余部分、宿主之间的文档、另一 shadow 的开头）分别量行，两端都滚出视口的长选区也能定位；按钮落在选区可见部分——标题条之下、输入卡之上（按两者实际几何扣除），优先首个可见行上方，放不下就到末个可见行下方，再压回可见区；触屏有系统选择菜单，不叠加。所有 `:hover` 样式（底色、颜色、显隐）都写在 `@media (hover: hover)` 里：触屏的 hover 会粘在最后点过的元素上；按下反馈用 `:active`，与 `:focus-visible` 一起留在媒体块外；靠悬停才显出的控件（附件移除钮等）在 `(hover: none)` 下常显。生成中焦点在输入框时按 Esc 停止本轮（与停止按钮同一入口，排队内容随之退回）；输入法组合中的 Esc 属于输入法；停止按钮的提示与 `aria-keyshortcuts` 标明该快捷键。

全局快捷键不依赖常驻侧栏可见：紧凑断点（平板竖屏接键盘）下 `Ctrl/⌘ + Shift + O` 与 `Ctrl/⌘ + /` 照常生效，`Ctrl/⌘ + K` 打开导航抽屉并聚焦其中的搜索框；关上抽屉回到按快捷键前的焦点（输入框里的光标位置不丢），原处在打开期间被隐藏（拉宽离开断点）时退到打开按钮、再退到输入框。快捷键集中列在一个面板里（`Ctrl/⌘ + /` 或侧栏底部主题行右端的键盘图标打开；键盘图标只在 `(hover: hover) and (pointer: fine)` 出现）。不用 `?` 打开——阅读时直接打字会把它送进输入框。面板没有固定触发按钮：打开前记下焦点与光标区间，关闭后放回原处（从输入框打开就回到原光标位置接着写）。新增或改动快捷键时同步更新面板，按键用发丝线小方块（技术字体），不做彩色胶囊。"引用此消息""放回输入框编辑"与选区引用写入草稿时走浏览器编辑命令（`execCommand("insertText")`）整段替换，进原生撤销栈：误点后 Ctrl+Z 撤回、Ctrl+Shift+Z 重做；已有草稿时追加在后，不覆盖。焦点在输入框时 PageUp/PageDown 翻对话（参考 Slack、Discord）：发送后焦点留在输入框，不必先点进消息区才能往回读；一页是标题条与输入卡之间的可见高度减 48px 重叠；往回翻先解除贴底跟随；草稿本身长到能滚动时仍交给输入框；输入法组合中（`isComposing` 或 `keyCode === 229`）PageUp/PageDown 翻的是候选页，不接管。

### 3.7 遥测收纳合同

composer 统计行浮在输入卡下方的底距里（绝对定位，不占流）：出现与淡出都不把输入卡顶起再落下；窄屏与矮屏触屏底距放不下，也为了克制，视觉上不显示（停止钮与"运行中"已说明在生成），但只做 1px 裁切、不用 `display:none`：开始与终态的 aria-live 播报仍留在无障碍树里。composer 统计行活动期只显示静态文案（不逐秒更新可见文本；已请求停止、本轮还没停下时写"正在停止…"，与停止钮同一说法），结束只显示一条终态摘要（只对本页看着跑完的调用；打开旧会话不回放上一轮统计，读取失败静默不报错），并在 `--ak-sys-duration-short` 淡出后移出（`prefers-reduced-motion` 下直接隐藏）。`aria-live` 不得挂在逐秒轮询更新的元素上：live 区域只在活动状态切换时更新一次性文案，逐秒数据放 `aria-hidden="true"` 呈现层。

### 3.8 单行菜单即删除

动作入口菜单只含一个动作时，删除菜单层，触发钮直接执行该动作（如 composer 附件钮点击直接唤起文件选择器）；菜单项 ≥2 时才允许菜单存在。判断依据是可观察的菜单项数量，不是"将来可能会加项"的设想。

### 3.9 浮层单面板合同

弹出选择器默认单面板直达：首屏即完整可选项，跨来源分组平铺 + 顶部搜索框 + 「跟随默认模型」置顶项 + 收藏组（localStorage，行内悬停星标切换；触屏没有悬停，未收藏的星以 45% 不透明度常显、热区约 36px，点星只切收藏不选模型）；选中项所在来源组排最前。模型行承载能力徽标（多模态输入 / 可推理 / 上下文窗口大小）与 provider 名，信息密度服务于挑选；分组头只在有真实品牌图标时显示图标，不用首字母占位块。面板只承载"选一个模型"一件事，无标题条、无关闭钮、无来源筛选行（搜索已覆盖）；浮层重定位只跟随文档级滚动，列表内滚不打断。思考强度是工具行独立控件，与模型选择解耦：当前模型支持推理时显示档位钮，点击开小列表选择，选中即把该模型固定到会话；不支持推理的模型下整个控件消失。确需两级才能承载的内容，先证明单面板无法表达。窄屏（≤820px，且视口高于 30rem；横屏/软键盘矮视口仍是 inset 8px 浮动盒子）下模型与思考强度面板是底部抽屉：贴底全宽、顶部 16px 圆角、最高 70dvh、遮罩压暗正文与浮动标题条（打开时输入区层级抬到标题条之上），点遮罩关闭（遮罩按下时不转移焦点，否则输入区切回阅读态会把遮罩移开）；触屏打开时焦点落在当前选中行而不是搜索框，避免软键盘弹起盖住列表。 分组标题只写来源名与图标，不挂条目数徽标；组内各行不再逐行重复来源（provider 与组名相同时省略），只有收藏组（混着不同来源）和来源名与 provider 不同的行才写 provider。 思考强度选项只写中文档名（中/高），不再在下面重复英文值；单行选项桌面 36px、触屏 44px，勾号与档名垂直居中。 来源与收藏各是 listbox 里的 `role="group"`，`aria-labelledby` 指向可见组标题：行内省掉来源后，读屏逐项选择时由分组名承接来源。

### 3.10 侧栏宽度拖拽合同

宽屏（>820px）侧栏右缘提供 8px 透明拖拽热区，hover/drag/focus 显 1px `var(--ak-rule-strong)` 竖向强调线。拖拽只写 `--chat-rail-width` 一个值，写在被消费的 grid 容器（`.chat-shell-body`）inline style 上，范围钳制 15–26rem；双击复位（移除 inline 覆盖，回到 CSS clamp 默认）。拖拽柄同时是键盘 separator（`role="separator"`、`aria-orientation="vertical"`、左右方向键步进 0.5rem）。偏好持久化 localStorage（`akashic.chat.rail-width`），首次渲染前同步读取。窄屏（≤820px）与抽屉内不渲染拖拽柄。导航抽屉打开期间视口离开紧凑断点（平板旋转、分屏拖宽）时抽屉自动关闭：常驻侧栏已经回来，不能留一层模态遮罩压住整页。

### 3.11 会话排序投影合同

会话排序（最近活动 / 最近创建 / 标题 / 手动排序）是纯客户端展示投影：只重排"最近会话"区与项目内会话子列表，不改变服务端权威顺序，置顶区始终跟随服务端顺序。时间倒序中缺失时间戳的行稳定排到末尾。选中项持久化 localStorage（`akashic.chat.session-sort`），入口是"最近会话"分组标题行右侧的幽灵图标钮，复用行菜单浮层与键盘模式。

手动排序的顺序数组是客户端事实（`akashic.chat.session-order`），覆盖目录全集：行原生拖放（HTML5 drag）给出上/下半插入指示（发丝线），落点提交顺序数组并把排序切到手动模式——拖拽本身就是选择手动的意图。未排序过的新会话按展示序排到最前；分页外的会话保留在顺序尾巴；搜索过滤时拖拽关闭，已存顺序不因过滤丢失。

按最近活动 / 最近创建排序时，"最近会话"区按本地自然日分成"今天 / 昨天 / 7 天内 / 更早"，组名只在变化处出现一次：比分组标题更轻的一行小字，落在侧栏左竖线上，不加线不加底，不参与拖拽与行菜单。按标题与手动排序不分组——时间分组只服务时间顺序。

侧栏会话列表滚动时上下边缘 24px 渐隐（CSS 滚动驱动动画，不挂 JS）：在顶端时上沿清晰，到底时下沿清晰，内容不再被分隔线硬切。

切换到已有会话、历史还在读取时直接使用会话版式：输入区停在底部、占位是"继续…"，阅读列顶部 300ms 后淡入一行"正在读取消息"；不得先摆成首页（居中输入卡）再在消息到达时跳回底部。首页版式只属于真正没有消息的会话：恢复的会话本来就是空的或已不存在（404），读取结束后回到首页版式（这一次切换是有意的，空会话应当邀请开场）。读取失败（其它错误）不是空会话：保持会话版式，在"正在读取消息"同一位置写"没能读取这段对话的记录：原因"加一个文字按钮"重试"，输入框下不再重复错误行——退回首页会让人以为对话是空的，接着发也看不到上文。聊天挂在外壳页面里（ADR 0126），没有单独的启动壳：首帧由应用按 URL 非空 `session` 参数或标签页记住的会话选择版式，带会话打开时首帧就是会话版式。 失败原因归这块读取失败视图所有，不进全局错误行：任何重试（手动、重连后自动）开始时撤下旧原因、换成"正在读取消息"，不会先掉到输入框下再回来；切到别的会话也不带过去。 已有消息（旧记录在、或实时回复先到）时读取失败不换掉正文，改在输入框下的错误行写明"没能读取这段对话的完整记录"并给重试，失败不能静默。

全局快捷键只挂一份（抽屉里的侧栏副本不挂，避免重复触发；`Mod+K` 只在侧栏可见时聚焦它的搜索，紧凑断点下由导航抽屉接手，见上文；对话框、菜单、选择器打开时不接管）：`Mod+K` 聚焦会话搜索，`Mod+Shift+O` 新会话，`Mod+/` 快捷键面板。宽屏指针设备上搜索框空闲时在右侧以技术字体淡墨显示 `Ctrl K` / `⌘K`，聚焦或有输入即隐藏；新会话按钮的 title 带出快捷键。搜索框里 Esc 先清空，再按一次失焦；输入法组合中的 Esc 只取消候选。搜索时列表标题换成"匹配的会话"并收起排序钮；没有匹配时只留一行"没有匹配的会话或项目"，占在列表原本的位置、与标题同一左缘。命中片段用 CSS Custom Highlight 标出（换主墨色 + 1.5px 下划线，不铺底色块，不改行 DOM）。置顶、项目内和最近会话按可见顺序参与同一键盘流程：回车打开第一条会话结果（打开后清空筛选；宽屏焦点交给输入框，抽屉里不抢焦点免得弹键盘；鼠标点结果保留筛选，方便连看几条），↓ 进入结果，行间 ↑↓ 移动，从第一行按 ↑ 回到搜索框。会话标题和项目名称的命中片段都高亮。 `Mod+Shift+;` 复制对话里最后一个代码块（ChatGPT 同一组合；从最新回复往前找第一条带代码块的回复取最后一块，用 Markdown 解析器解析原文，引用、列表里的围栏和缩进代码块与页面上显示的同一组，不依赖代码块是否已渲染）：结果在输入卡上方左侧一行浮动状态（"已复制最后一个代码块（语言，N 行）"/"对话里还没有代码块"，1.8s 后消失，读屏播报），不改变输入区高度、不与正中的回到底部按钮重叠。不占 `Mod+Shift+C`（Windows 上是浏览器检查元素）。

### 3.12 破坏性行内操作合同

会话删除是行菜单内的就地两步确认，不用模态框打断列表浏览，行上也不放独立的删除方块：行的唯一操作入口是 ⋯ 菜单；选择"删除"（error 墨色、danger 修饰类）不直接执行，菜单保持开启并把该项就地变为"确认删除"，第二次选择才提交；菜单关闭或 3 秒未确认自动还原。提交成功的删除是软删：行从目录投影消失，导航区出现一行可撤销的状态条（含撤销与关闭），撤销窗口内 POST undelete 可恢复；窗口结束 UI 不再提供恢复入口，由服务端与决策 0086 兜底。已删会话被直接打开时消息只读展示并给出恢复入口，不允许向其发送新消息。

### 3.13 过程区折叠与日界合同

过程里的每一行（思考、工具、上下文提示）都能展开，但鼠标下收起着的行不常驻箭头：悬停或键盘聚焦该行时才出现，展开着的保留（提示怎么收回）；本轮与工具组的摘要行、图文回复前段收纳过程的摘要行、触屏照旧常驻。箭头位置仍预留，出现时不推动行内其它文字。同一回复里连续 ≥3 个已完成工具行折叠为一行"已执行 N 个工具 · Xs"摘要行（复用工具行栅格与 chevron），展开后逐行恢复原行与可点详情；运行中的工具永不参与折叠，保持逐行可见。思考、正文、部件项打断连续性，不跨行合并。日历日变化处在消息行之间插入居中日界（发丝线 + 日期：今天、昨天直接写字，其余同年写"10月14日周二"、跨年带年；不用"10/14"这种斜杠写法，中文里读起来像分数）；当天第一条消息上方也立界，分隔不进入消息行的锚点与 hover 区域。

媒体查看器：点开回复或附件里的图片、视频后整屏压暗，同一条消息里的媒体按文档顺序成组，顶栏"‹ 2 / 5 ›"、←/→（带修饰键不接管，视频聚焦时留给视频）与触屏横滑切换，到头停住。媒体只占顶栏之下、四侧安全区以内的区域，长图不压顶栏、横屏不进刘海。图片画框固定占满这块区域：放不下时（加载后与画框尺寸变化时都重算，转屏、分屏照样）可点图或顶栏按钮切原始像素，在同一画框里滚动，点击处留在指针下、键盘切换停在中心；放得下了缩放入口撤掉。缩放状态只属于这一次翻页：翻走再翻回、同一地址出现两次，都从适应窗口开始。小图不放大，没有固有尺寸的 SVG 按画框适应。画框里图片外的空白点了关闭。

一轮落定后（末条输出已完成、没有仍在运行的工具），本轮思考、工具、中途旁白与上下文提示收进一行摘要："思考 N 次，调用 M 个工具"，行尾是整轮用时（自本轮用户输入起算，<1s 不写），有失败时追加 error 墨色的"K 个失败"。只有单个思考项时不收（它本身已是一行）。脚注在两条渲染路径上同一外观：首条前一条 subtle 发丝线、次级墨色小一号、"1." 序号、返回箭头跟在句末（只有紧挨箭头的最后一段行内，多段脚注的前几段、列表、代码保持块结构）；富渲染路径（markstream）在每个引用处把段落拆成几个 p，同槽改回行内排，引用号与静态上标同色同大小。`turn.before_reasoning` 插件槽位留在摘要外保持可见；展开后逐行恢复过程视图，不再套一层"已执行 N 个工具"（外层摘要已经收过一次，二次折叠只是多点一下）。工具行成功是默认结果，状态列只写耗时，"运行中""失败"才写字。工具行摘要优先用模型写的 description，没有时取调用目标（`path` 的末三段、`url` 去协议、`query`、`command` 首行），不展开也知道读了哪个文件、搜了什么。工具结果是字面文本，不解释 Markdown；参数值与结果用 `--ak-ink-muted`（12px 技术字体下浅色 4.9:1、深色 5.6:1，不用透明混色）；失败输出改用次级墨色（不是普通结果的 52% 透明墨色，浅色对比度 7.5:1），只把"错误"小标题染成 error 色、左侧加 2px 错误色细线——整段日志染红喧嚣且难读；但统一 diff（有 `@@` 与 `---`/`+++` 行，常被包在 ```diff 围栏里）按行首给增删行着状态色与极淡底色，路径头与围栏退成次级，复制仍是原文；diff 不折行（折行会把一行增删拆散），在结果区内横滚，增删底色铺到最长一行。思考进行中也只占一行："正在思考" + 最新一句（右缘淡出），不自动展开——展开会与标题行重复同一句，结束时又整块收起造成版面跳动；想看全文由用户点开。"正在思考"只在这段思考确实还在进行时显示：同一次调用的正文开始输出、或本轮已停止，思考行即改为"已思考 Ns"，不与正在输出的正文同时转动。用户自己点开的思考内容不随思考结束自动收起。轮次未结束（末条输出 `finish=continue`、之后还没有输入或控制收尾）时不收摘要：刷新或重开会话恰在生成途中、实时活动尚未接上，这些输出按原位逐行显示，文字按旁白处理，不挂时间与操作行，与实时视图一致；落定后再收进摘要。"未结束"只在本会话的回复状态（`reply.status`）同步到之前成立：同步后仍在运行的轮次由实时活动接管，没有活动说明它不会再继续（异常中断、没有收尾记录的旧轮次），照常收起并挂上时间与操作，不能让它永远停在旁白态；不按记录年龄猜。被附件切开的图文回复（工具结果插图把过程分成前后几段）同样遵守：前段过程不提前折成"思考并调用 N 个工具"。 富渲染（markstream）的脚注解析只收段落，脚注正文改由同一原文的完整 GFM 解析（micromark，与静态路径同一份 HTML）提供（整篇解析，不自己截"定义区"：围栏、链接引用声明、嵌套引用都按标准走；只在回复落定后惰性解析一次、按原文缓存，生成中用 markstream 自己的脚注渲染，流式追加不触发整篇重解析；子树里的引用、回链换成富渲染的 fnref 体系，标签的 key 与 DOM id 统一用原文写法，大小写、百分号不变，中文标签按解码后匹配；标签原始写法只从正文的真实引用取，代码与转义的 `\[^A]` 不算；脚注里的 `$…$`/`$$…$$` 在解析前换成占位、解析后交给 KaTeX，`\$` 保持字面、代码里保持原文；占位字符逐条挑原文没用过的私用区字符，原文自带的私用区字符不受影响；链接地址、图片地址、title、alt id 都从 1 编起，按 id 全局找会跳到别的回复），不写地址栏 hash；焦点落到对面的链接上，回车即可来回。富渲染的引用号写成真正的 `<sup><a>1</a></sup>`（markstream 原生是键盘按不到的 span、显示"[1]"），读屏名"脚注 1"/"返回引用 1"，与静态路径一致。只含脚注语法的回复也按 Markdown 停止是一个持续状态而不是一次点击：发出 `/stop` 只代表请求送达，发送键保持"正在停止"（停止方块外一道细环转动；用 `aria-disabled` 而不是 `disabled`，键盘焦点留在原处）直到本轮真正结束，自点击起 10 秒仍未结束则复位允许再停。暂停、恢复、放弃这类轮次事件只渲染一行次级小字（"已放弃 · 原因"），不用标题加正文的块；执行失败仍保留醒目块。

### 3.14 空态 hero 合同

无消息空态用克制的纸感 hero：一行时段问候小字（凌晨/早/中/下午/晚）+ 任务口吻主标题，两行即止，不堆提示、推荐药丸或装饰动画。空态下 composer 输入框自动聚焦；连接、配置、加载等状态态仍走各自的说明块，不混入 hero。没有项目上下文的空白新会话，宽屏顶栏不写"新会话"、不画分隔线（与 hero 重复）；紧凑外壳保留标题给汉堡按钮做落点，项目里的新会话保留"项目 / 新会话"。

空态把 hero 与输入条合成一个居中簇，视为一个矩形区域：矩形中心钉在可视区几何中心（横轴 = 内容区中轴，纵轴 = 窗口中轴）；顶部标题条与会话行菜单触发器是悬浮 chrome，不参与簇的居中分配；不沿用有消息态阅读列的左偏置。这是纯布局切换——同一 composer 实例不迁移 DOM、不重挂载，草稿、附件与焦点保留；首条消息落地后输入条回到原底部 dock。导航侧栏底部动作区无动作时不渲染容器与其发丝线。

### 3.15 会话标题行内重命名

会话显示标题属于显式数据管理状态（服务端 `title` 覆盖，空值回到首条消息推导），不是消息事实。交互合同：会话行双击或行菜单「重命名」、会话标题双击进入行内编辑；编辑框沿用原排版、只以发丝底线标示；Enter 或失焦提交，Esc 放弃；提交失败时编辑态保留并沿用全局错误提示。从行菜单进入时，菜单关闭的焦点归还要落在编辑框上（不是"…"按钮），否则编辑框一出现就因失焦按原标题提交；回车提交后输入框转为 disabled 引起的失焦不再重复提交，同一次编辑只发一个请求。所有行内编辑框（会话行、顶栏标题）与输入框一样认输入法组合：`isComposing` 或 `keyCode === 229` 时回车、Esc 都交给输入法，不提交也不放弃。删除确认药丸与编辑输入框都不以弹窗打断流。

图表系列使用主题目录的 `--ak-chart-1` 至 `--ak-chart-6`；系列标签、图例和曲线保持同色，不能借用业务状态色。交互图在主题切换时更新颜色，不重建用户已操作的文档。

### 3.16 触摸落点稳定合同

点击引起的布局变化（展开工具行、显示菜单、插入提示）必须在该次 `click` 之后提交；`pointerdown`、`focus` 阶段不得让新控件出现在手指下——触摸的 click 按当时布局命中目标，提前展开会把点击送给新出现的控件（曾导致窄屏点输入卡右侧直接弹出思考强度菜单）。回车语义按输入方式区分：纯触屏（`(hover: none) and (pointer: coarse)`）上回车换行、发送交给按钮，软键盘回车键标为换行（`enterKeyHint="enter"`）；有悬停或精细指针（含外接键盘的平板）时回车发送、Shift+回车换行，软键盘标为发送。生成中（发送钮是停止钮）桌面键盘按回车把文字排进本轮之后（参考 Memoh 的 follow-up queue）：输入卡顶部出现与回复引用同几何、底色退到纸面的排队条"本轮结束后发送"，可撤回到输入框，再按回车会追加到同一条；本轮正常落定才发出；收尾期间继续回车仍追加到同一条，发送钮不可抢先发送。输入框与重试横幅的停止入口表达同一停止意图。用户按了停止、本轮暂停或出错、暂不可发、切走会话或收到另一条新输入时不替用户决定，排队内容退回原会话草稿。排队文字和后写内容保存在同一标签页草稿中，刷新后只恢复文字，不恢复自动发送意图。带附件或回复引用时不排队，回车显示轻提示；纯触屏回车本就是换行，不排队。输入法组合中的回车一律不发送：除 `isComposing` 外还认 `keyCode === 229`（Safari 在 `compositionend` 之后才派发确认候选词的回车）。附件与草稿、引用一样按会话归属：切换会话时随旧会话存起、切回取出，不会跟到别的会话里被发出去；发送成功才移除并释放 Blob URL（上传中切走会中止发送，附件留在原会话）。新会话首次被接纳只是同一编辑位置拿到会话 ID，不算切会话：发送期间追加的附件与文字一起归到这个会话，再开新会话时不会出现。文本类附件（源码、日志、Markdown、JSON 等）的内容会交给模型（单个前 48KB、一轮合计 160KB，超出时附件标签里写明；同一附件在历史里被引用几次就投影几次，额度按引用次数分摊，重复引用不会把一轮撑过 160KB；截断处只丢掉没写完的合法多字节字符，含非法字节的仍按非文本拒收），所以拖进 `.py`、`.log` 让模型看是有效操作；其它非图片文件模型只看到文件名、类型与大小。超过服务端上限（单个 50MB）的文件在入列时就拒掉，输入卡内轻提示"某某 超过 50MB，未添加"，其余文件照常入列（过长文件名中间省略、保留扩展名，完整名在 title 里）——不要等到发送被 413 再引导用户"重试"一个必然失败的上传。视频缩略图解不出首帧（编码不支持）时垫视频图标与文件名，不留空白方块。附件（输入卡与消息）见 3.20。图片与视频点开进同一个查看器：整屏压暗（`--ak-color-shadow-rgb` 86%），视频按视口等比放大（宽 `min(94vw, 56rem)`，小录屏不再按原始尺寸播放）；图片按原始尺寸显示、超出视口才等比缩小（位图放大只会糊，小图标、截图局部看原像素更有用），上方一行是文件名、新标签打开、下载、关闭（固定浅色前景，压暗层在两种主题下都是暗的），点媒体外的空白处或 Esc 关闭，打开后焦点落在关闭钮。查看器只有一个（参考 Memoh 的媒体灯箱）：附件按钮带 `data-media-*`、回复正文图片是普通 img，都由同一个 document 委托打开，不再每个附件各挂一个对话框。查看器铺满视口，顶栏固定在顶端、媒体在其下居中：翻到尺寸不同的下一张时翻页钮不挪位置。同一条消息里的全部媒体按文档顺序成组（不跨消息：远处消息是占位渲染，跨消息的组会时有时无），顶栏中间"‹ 2 / 5 ›"，←/→ 键与触屏在媒体上横滑切换，到头停住不循环；关闭后焦点回到当前这一张的入口。图片被缩小显示时出现"原始尺寸"按钮，点图也可切换：原始像素在同一块区域里滚动看细节，点击处留在指针下；再点回到适应视口；切到下一张自动回到适应视口。回复正文里的 Markdown 图片（两条渲染路径都是普通 img，不在链接或按钮里）显示放大镜指针，点开进同一个查看器（document 级委托，不改渲染节点）；键盘入口由同一处补上：可预览的图片设为可聚焦的按钮语义（`tabindex=0`、`role=button`、"查看图片：…"），Enter/空格打开，关闭后焦点回到这张图（它已被卸载时交还 Radix 默认处理）。对话框关闭钮的焦点环只在键盘聚焦时出现（`focus-visible`），鼠标点开不再先套一圈。文件拖进窗口任意位置都由输入卡接住（遮罩见 3.20），松开即入列。对话框、菜单、选择器打开或聊天未就绪时不入列、不显示强调态；已被其它放置区处理的拖放不干预；无论是否入列都阻止浏览器把文件当页面打开（那会离开聊天页、丢掉草稿）。正文框随内容长高，上限取视口高度的 30%（120–320px，约 5–13 行），超出才在框内滚动：写代码时整段粘贴不该只露 4 行；键盘弹起后 dvh 变小，上限回落到 120px。卡片长高多出的部分由 `--composer-grown` 让给消息区，贴底时最新回复跟着露出。输入卡空白处的点击等同点进输入框；阅读态下不可用的发送钮不拦截点击。没有精细指针时（触屏），点发送后让出焦点：软键盘收起、输入卡回到静止态，下一步是读回复，不该留着半屏键盘和展开的工具行；桌面发送后焦点仍在输入框。

窄屏阅读态的一行输入卡里，占位文字与发送钮同一中线（文本框上下各 10px）；空草稿的发送钮是一块淡墨底，不描边。宽屏指针设备上，焦点不在任何可编辑处且没有对话框/菜单/浮层时，直接打出的可见字符进入输入框（空格、组合键、输入法组合中不接管）。

### 3.17 滚动跟随与历史补载合同

- 发送后贴底跟随回答；当停靠点顶到阅读区顶缘时停止跟随，读者从开头读起，"还在生成"按钮负责回到底部。停靠点：宽屏是本轮用户提问（问题与回答开头同屏），窄屏是回答开头。用户自己滚离后，这一轮不再接管。
- 提问目录（参考 Memoh 的 scroll rail）：只在宽屏指针设备（≥1200px，右侧留白放得下）且已载入 ≥3 轮提问时出现。收起是对话区右缘每轮一道 2px 刻度、当前一轮更长更深；悬停或键盘聚焦展开为提问预览列表（当前一轮加粗并滚进视野），点选后离开贴底跟随、瞬时停到那一轮提问的阅读区顶缘，并逐帧复测校正（视口外消息是估算高度的占位，平滑滚动的预算目标会漂移）。Esc 收起并把焦点交还输入框（收起后列表不可见，焦点不能留在里面）。窄屏与触屏不挂滚动监听。
- 上滑补载更早消息时，补偿量按 DOM 提交那一刻计算：请求进行期间每次滚动记录第一条已渲染消息离滚动区顶部的距离（发请求前先记一次；没有请求时不读），插入后在 layout effect（绘制前）把它放回原处。不得在请求发出时一次性记录——请求期间用户继续滚动的距离会被抵消，并在提交到补偿之间闪出一帧顶部。原生 `overflow-anchor` 保持开启，它已生效时补偿差值为 0。
- 分页可能恰好切在工具调用与结果之间。还有更早历史时，窗口开头找不到调用的工具结果先不渲染（载入上一页后它会并回所属调用），不显示"调用不在当前记录中"的孤立块；已到对话开头才按原样显示。
- 表格没有外框只有行线，首列文字贴正文左缘（首列左内边距 0），不比段落缩进一格。单元格里英文词不拆开（不继承正文的 break-word，含 markstream 文本节点自带的 break-words）：中文照常按字折行，真放不下时整表横滚、按边缘渐隐提示。
- 放不下而横滚的表格和代码块（生成中与高亮后都算）进 Tab 序（`role="group"`，读屏名"表格/代码，可左右滚动"），键盘聚焦后方向键横滚；放得下时撤出 Tab 序，只撤自己加的 tabindex。焦点框画在框内（回复正文左右贴边会裁掉外扩框），表格聚焦时去掉边缘渐隐；代码的滚动元素在高亮 shadow 里，焦点框样式随 adoptedStyleSheets 补进去，鼠标点代码不出框。markstream 自带的 pre 一律 `tabIndex=0` 加英文名"Code block: json"，挂载时摘掉交给这套规则；它给链接写死的英文 `aria-label`（"Link: 地址"）会顶替链接文字，同样摘掉，读屏名就是链接文字。
- 流式放字跟着积压走（参考 Claude Desktop 的 paceReveal）：显示比到达晚约 0.3 秒，积压越多放得越快，不设固定字速上限；积压超过 400 字按 120ms 追平。不得再把字速钳成常数——快模型（≈300 字/秒）下旧参数（140 字/秒、每帧 6 字）让延迟一路涨到 1s 以上，后半段在落定那一刻整段跳出。验收：showcase 3× 速度下各标记短语的显示延迟 ≤400ms，生成中无长任务。
- 公式（reading-math.tsx）生成中就排版：闭合的公式交 KaTeX 并按"源码 + 模式"缓存 HTML（整条消息只排一次）；末尾还在写的公式每次提交渐进排版——补齐花括号、`\left`、环境后试排，失败就截掉写到一半的命令再试，仍不行沿用上一次排成的样子；一点都排不出时行内不显示、独立公式留一行空位，不闪源码、不出 Loading。还在写的公式墨色用 secondary，闭合后回到正文墨色（同一节点，不跳）。独立公式生成中只长高不缩回。只输出 HTML（不带 MathML）：DOM 更少、复制不混入逐字文本，读屏名用 TeX 源码。KaTeX、样式与常用字体在正文第一次出现 `$`、`\(`、`\[` 时预载；加载失败不缓存失败结果，公式先按源码显示，退避重试（2s 起翻倍，至多 60s），新公式挂载也会再试，载入后全部排版。
- 行内 `$$…$$` 按 display 字号排在行里（`\displaystyle`，inline-block），独立成段的 `$$` 才是居中的独立公式。独立公式不画底色，放不下时横滚、按边缘渐隐、进 Tab 序（读屏名"公式，可左右滚动"）。选中复制含公式的内容得到 `$tex$` / `$$tex$$` 源码；起止落在公式内部时扩到整个公式。复制处理挂在 document 上，选区跨多条消息也转换；克隆在页外取纯文本前把渲染外壳的 `content-visibility` 改回可见，整条回复全选复制不会得到空文本。
- 颜文字按字面显示，两条渲染路径同一套判断（kaomoji-markdown.ts）：富渲染路径是 markdown-it 行内规则，静态路径是 micromark 行内扩展，命中的颜文字按普通文字输出。不在整篇源码上预处理：扩展只在解析器已认出的行内文字里触发，围栏、缩进代码、跨行的行内代码原样不动；表格先按 GFM 分列再判断单元格（两条路径一致），脸里要有字面竖线须写 `\|`。每次判断只看候选前后有界的一段（脸 80 字、装饰脸 160 字），长文本的开销与解析本身同阶。曾经只装在流式解析器上，`(*´▽`*)` 生成中正常、落定后变成斜体。手臂包着括号脸（`_(:з」∠)_`、`~\(≧▽≦)/~`、`\(≧▽≦)/`、`¯\_(ツ)_/¯`）整体算颜文字，`\(` 不当公式开头；脸里没有符号的 `_(注意)_` 仍是强调，`\(x^2\)` 仍是公式。生成中括号还没闭合的脸（`(*´▽`）先按字面显示，闭合后不跳。
- 代码块生成中：只有末尾还在写的那一块是纯文本占位（无复制钮，复制到的会是半截）；围栏一闭合内容就不再变，直接高亮，落定时不再整批换手。占位与高亮块同一几何（实测换手 ±1px）。块头名按归一后的语言取（bash/sh/zsh → "Shell"），生成中与落定同一张表，不得用给高亮器的语法 id（shell → zsh）取名。
- 高亮交接：落定后的消息是新挂载的组件，高亮器要等几帧才重新上色（实测约 80ms 无色，同一块代码"有色 → 无色 → 有色"）。每块代码第一次画稳（shadow 内连续 150ms 无变化）时记下高亮结果与宿主的局部 CSS 变量，同一段代码再挂载时先盖这份快照，新高亮画稳后撤掉。快照只是视觉副本：`inert`、去掉复制来的 `tabindex`，不进 Tab 序、焦点不会落在随后被撤掉的节点上。只有生成中的回复记快照；打开历史会话时代码块不等稳定、不读样式。
- 代码高亮在 Worker 池里分词（参考 Claude Desktop，2–4 个线程，第一个代码块渲染时才建池），主线程只拼 DOM：主线程分词时第一块代码就是 50–100ms 长任务，12 块的历史会话多出 100–170ms；放进 Worker 后生成中长任务为 0，12 块只多 20–30ms。Worker 起不来（CSP、不支持）时高亮器自动退回主线程，结果不变只是慢。池子主题必须与 markstream 默认的 vitesse 深浅一对相同，深浅切换只换 themeType 不重建池子；Web Shell 的 CSP 为此放行 `worker-src 'self'`。
- 回复里的 ```diff 与高亮代码块同一几何：44px 块头（左 "Diff"、右复制钮）、12px/18px 等宽行；复制钮在块头里，不压首行的增删底色。无语言的文本块仍按阅读字体排（常含中文），不算代码。
- 代码横滚提示的测量（读 scrollWidth）合并到下一帧：流式时每次字符变化都会触发观察者，同步测量曾在一段带代码的回复生成期间累计约 130ms 强制布局。
- 行内 `$…$` 两条渲染路径同一规则（pandoc）：开 `$` 后、闭 `$` 前不是空白，闭 `$` 后不紧跟数字；不满足的那个 `$` 按文字显示，后面的原文照常解析。"$5 到 $10 一个月"是价格不是公式；"成本 $5 和公式 $x$"里的 $x$ 仍排版；公式里的 `\{` `\}` 等转义原样交给 KaTeX（集合记号的花括号不能丢）。
- 只清整段回复首块的上边距（标题、表格、代码、引用都算；代码、Mermaid、数学兜底的真实边距在包裹层里面的框上，一并清，列表/引用/表格里嵌着的不算首块）。富渲染路径每个块都包在 `node-slot > node-content` 里，不能按 `h2:first-child` 写，否则每个标题都丢掉上边距，标题离上文比离下文还近。
- 消息行的 `content-visibility: auto` 只用于末尾 120 条之前的历史（见 3.18）：新插入或刚切换到 auto 的元素首帧按占位高度布局，若作用于最新回复，一轮落定时正式消息会先塌成 160px、滚动被夹紧、下一帧再弹回（实测宽屏整屏闪跳约 500px）。流式活动区与落定后的消息使用同一纵向节奏（列表 gap 20px 加相邻规则），换手时不跳行。问答成组：提问到它的回答（落定 `.timeline-output`、流式 `.reply-activity`、思考占位同一规则）收 12px，轮与轮之间放 12px——每条消息下都预留了悬停操作行，均匀 gap 会让提问离上一轮回答和离自己的回答一样远。同一方接着说（补充一句、连发的主动消息、落定后又流式的下一条、本轮的"已暂停"收尾提示）与问答同距，收 12px，不当成新一轮。停止或暂停收尾、只有过程没有正文的输出不挂自己的时间与操作行（操作会指向一条空消息），时间只挂在紧随其后的"已暂停"上；有部分正文时照常保留，便于复制与引用。流式期间的代码块 `<pre>` 与落定后的高亮代码块共用同一几何（44px 块头位、12px/18px 行、subtle 发丝线、1rem 外边距），换手只多出复制钮，高度不变：流式期间预留的块头位里已写上与落定块头同名的语言（markstream `languageMap`，`ts` → TypeScript；映射外按落定块头的规则只把首字母大写），两态标题同为技术字体、500、`--ak-ink-secondary`（压过 markstream 自带的写死灰色，深色主题随墨色）。代码块复制钮的颜色经 markstream 的 `--code-action-*` 接到 `--ak-ink-secondary`/`--ak-ink-primary`，复制成功与消息、工具结果的复制同一成功色反馈。用户气泡里贴的代码块与回复同一套外观（不显示 markstream 的彩色语言图标、块头透明、同一标题与复制钮），代码块规则的作用域写全 `.agent-content, .process-markdown, .user-bubble`。代码行左右内边距 16px（高亮组件经 `unsafeCSS` 覆盖它写死的 1ch），与块头语言标签同一左缘。高亮组件加载期间块内的占位 `<pre>` 已在块头之下，只对齐代码区（12px/18px、8px 16px 内边距、无边框），高亮完成时块高不变；块外流式规则不得命中块内占位。
- 切走再切回会话时回到上次读到的位置（本标签页内记忆，刷新不保留）：随滚动在 rAF 里记录阅读区顶缘下第一条消息与偏移，贴近底部（≤80px）时不记、回来照常贴底。切回且消息就绪后，在之后的帧里离开贴底跟随，逐帧把那条消息压回原偏移（最多 20 帧，用户一有滚轮、触摸、按键、按下就停）；逐帧恢复期间不记录位置。会话之间切换时滚动区是同一个节点；从首页（还没有对话区）切回时它才挂载，滚动区与目标消息都可能晚一帧出现，所以每帧重新取、找不到就等下一帧；20 帧内都没找到（那条消息不在已载入范围内）就放弃，照常贴底。记忆按最近使用保留 50 个会话。

### 3.18 滚动路径性能合同

长会话滚动不得比 main 多做与内容无关的布局。性能回归的验收：1365×860 长会话，滚轮上下各 30 次（含历史补载），用 CDP `Performance.getMetrics` 对比 `LayoutCount`、`ScriptDuration`，并用 CPU profile 找热点。

- scroll 监听里不同步读几何：要读就合并到 `requestAnimationFrame`，或只在确实需要的状态下读（如补载请求进行中）。
- 每帧要在 N 条消息里定位时，利用文档顺序二分查找，不逐条读 rect。
- 历史消息带 `content-visibility: auto`，不要给每条消息挂 ResizeObserver，也不要在挂载时逐条读 `scrollHeight`：滚进滚出时尺寸在 0 与实际值之间切换，跳过渲染的子树每读一次就单独触发一次布局。先用字数、结构粗筛，只测量可能受影响的那几条。
- `matchMedia` 结果用订阅缓存（`useSyncExternalStore`），不要在每帧回调里重新创建。
- 用 ResizeObserver 观测的东西，注册时不再同步测一次：`observe` 之后同一帧布局完成、绘制之前它必定回调，首帧照样正确；在 effect 里同步读 `scrollLeft`/`scrollWidth` 会在提交阶段强制布局（宽表横滚渐隐 `watchOverflowEdges` 去掉后，落定换手最长忙碌 22.9→12.3ms）。
- `content-visibility: auto` 不是免费的：每条被锁的消息滚进视口都要一帧布局。只锁末尾 120 条（`LIVE_TAIL_MESSAGES`，约两页历史）之前的消息，近段滚动不触发解锁；更早的历史仍锁住，用来限制改宽度、开合侧栏时的重排范围。调整这个值要同时量滚动、流式输出、改宽度三项（160 条历史实测：120 比 16 滚动布局 140→83 次、流式布局 70→51ms，改宽度与完全不锁持平）。

### 3.19 连接与错误状态合同

- 标签页标题是"会话标题 · Akashic"（项目会话带项目名，空白新会话只写 Akashic），开着几个标签也分得清；页面在后台时本轮答完，标题前加"●"，回到页面即清除。不弹系统通知、不闪标题。
- 会自己恢复的状态（自动重连中）用输入框下方的安静状态行：次要墨色 + 警示色呼吸点 + 文字按钮"立即重试"。不用错误色、不用实心按钮，用户此时多半什么都不用做。
- 需要用户动手的状态（重连失败、请求出错）才用错误行（错误色 + 重试按钮）。发送失败（上传附件或投递出错）例外：草稿与附件已放回输入框，发送钮本身就是重试入口，错误行只说"没有发出：原因。内容还在输入框里，可以直接再发。"，不给"重试"（它是重连并重新加载，不会重发，放在这里会误导）；再次发出后错误行自动撤下。HTTP 错误没有服务端说明时统一写"请求失败（状态码）"，与功能设置页同一格式。
- 同一根因只说一次：聊天连接断开时，宿主执行状态无从确认，宿主提示静默，交给连接状态行。
- 断线期间草稿保留在输入框，恢复后不清空、不重发。因断线没送达的发送错误在连接恢复后自动撤下（草稿还在，用户看得出没发出去）；其它错误仍需用户处理。
- 网络恢复（`online`）或切回前台时：连接还开着就立即探测；已断开、正在退避等待就立即重连并重置退避，不让用户干等最长 30 秒。

参考 Claude Desktop 的附件系统，尺寸取紧凑横条（`attachment-card.tsx`，输入框与消息共用一张卡）：

## 4. 排版

- 阅读正文：Noto Serif SC 中文与 Source Serif 4 英文组成一套阅读字体，正文 ≥16px，三行以上正文行高 ≥1.4。中文字体按字频分层切片（首屏层、一级字整片、二级字与生僻区细切，见 `frontend/theme/src/fonts/reading-serif.md`），普通页面只下载约 1.7MB、预加载约 1.5MB；每片的 `unicode-range` 只写实际码位、互不重叠（宽区间靠重叠优先级在 Chromium 可行，Firefox 冷启动仍会多取 7–8MB）；不要退回按码段粗切——那会让任何中文页面下载全部约 11MB，并在首屏与 JS 抢带宽（10Mbps 下首条消息 10.9s→3.0s）。
- 代码、时间、运行身份、短技术标签：JetBrains Mono（`--ak-type-technical`）。中文句子里带数字的状态（"正在生成… 耗时 1m 52s"、"思考 3 次，调用 5 个工具"）不用等宽字体——汉字会被拉开——用阅读字体加 `font-variant-numeric: tabular-nums`，逐秒刷新也不抖。
- 会话标题不在数据层按字数截断（不拼"..."），完整标题交给前端按实际宽度处理；重命名与侧栏搜索都要用完整标题。
- 一行标题（侧栏会话、会话预览、项目名、项目内会话、顶栏标题、右侧轮次导航列表）放不下时不用省略号，右缘 28px 渐隐（`MarqueeText`）；所在行悬停或键盘聚焦 0.35s 后以 30px/s 往返滚出尾部，两端各停 0.4s，滚动时左缘随之出现 12px 渐隐。只在精细指针且未要求减少动态时滚动，触屏只渐隐；预览一类副文字只渐隐不滚动，免得一行里两处同时动。宽度变化（侧栏拖宽、字体加载、悬停露出行菜单）由共用的 ResizeObserver 重算，尾部始终正好停在可见区右缘。滚动靠注册过的 `--marquee-pos`（`@property`）插值：不支持注册属性的浏览器（检测 `CSS.registerProperty`）不加 `is-animatable`、不播动画，只保留静态渐隐，自定义属性的使用处都带 0px 回退。
- 工具行摘要是文件路径时（模型没写 description、取的是调用目标），放不下从左侧省略，离文件最近的目录与文件名留到最后："…time_diagnostics/profiling.py"，文件名本身也放不下时同样从左省略、保住扩展名；路径是一个文本节点（RTL 行内 LTR 隔离），选中复制得到原样的一行；悬停 title 给工具参数里的原始路径（含根目录、盘符与原分隔符）。其它摘要仍尾部省略。
- 会话列表在 Tab 序里只占一个停靠点（roving tabindex）：停在键盘上次停过的行；该行被搜索过滤或项目折叠卸掉后回退到当前会话，再回退到首个可用行；切换当前会话后停靠点跟到新会话。停靠点由侧栏按 DOM 统一维护，行组件不写 tabIndex。行上 ↑↓ 逐行、Home/End 到首末行，项目标题行也在其中；行的"…"菜单和项目的"＋新建对话"都不进 Tab 序（菜单里有同一项），在行上按菜单键或 Shift+F10 打开，关闭后焦点回到行的主按钮（`data-row-primary`；重命名时给输入框）。项目的展开箭头与项目名按钮重复，键盘只停项目名；搜索时项目名按钮只以 `aria-disabled` 停用折叠、不 `disabled`，它是这一行唯一的键盘入口，行菜单（含"新建对话"）要靠它打开。快捷键面板列出这两项。
- 紧凑/触屏侧栏里排序钮放到 44px 后，分组标题行去掉上内边距，热区不变，不在搜索框下留一大块空白。
- 模型触发钮只放模型名：OpenRouter 式 `厂商/模型` 去掉厂商前缀，完整 ID 留在 `title` 与选择面板里。
- 同一界面只使用共享的阅读组合与技术字体；不为单个组件引入额外字体。
- 字号优先使用 `--chat-type-*` 别名；新增字号别名需要至少两个真实消费者。
- 回复里的 Markdown 结构只靠字号、字重、留白和实线发丝线（`--ak-rule-subtle` / `--ak-rule-default`）表达：标题不加下划线，有序列表用阅读字体的次级墨色 `1.` 编号（嵌套层走 `::marker` 也同一字体，不换等宽小字）、条目之间只有行距，脚注区以 subtle 发丝线隔开、次级墨色 0.875em，代码块与概念块是一圈 subtle 实线，表格只有行线（表头下用 default），不用虚线、补零编号或斑马纹。长行内代码折行时每段都带内边距与圆角（`box-decoration-break: clone`；Chromium 断行不计复制出的右内边距，末端可能多出 6px 落进页边距，可接受）。裸网址（链接文字本身就是网址，静态路径标 `.reading-url`）按字符填满整行（`word-break: break-all`），不在 "-" 前后紧急断开留下单独一行的连字符。无标题文本块（引用里的代码等）的复制钮贴住块的右上角，横滚的长行在按钮左侧 16px 内淡出，不留露出文字的缝。 带语言的代码块：44px 块头（标题左 16px、垂直居中），代码区上 4px、下 12px，使标题上沿、标题到首行、末行到块底三段留白约 12–15px 同一节奏（不是上松下紧）；生成中的 pre、高亮占位与高亮后同一几何，换手块高不变。 代码高亮沿用 vitesse 两套主题的色相，但在纸面底色上每种 token 至少 4.5:1（原主题变量 3.3、函数 3.9、标点 2.6 —— 读代码吃力）：低于的颜色在 OKLab 里只调明度，半透明的弱化字符（引号等）调到 3.5:1，保持比正文浅一级；色值表在 `markdown-reading-nodes.tsx` 的 `READABLE_TOKENS`，升级主题或换主题时要重新量。高亮按深浅一对主题输出，每个 token 的 inline style 同时写着 `--diffs-token-light` 与 `--diffs-token-dark` 两个色值：修正必须改写对应主题的那个变量，不能直接改 `color`（否则浅色规则会命中深色值）。

## 5. 窄屏阅读

- 一次展示当前任务；目录、列表、详情逐层进入，返回动作明确。
- 回复里的 ```diff 块按原文逐行着色（与工具结果的 diff 同一外观：文件头、hunk 退次级，增删行状态色＋极淡底色整行铺满），复制完整 diff。markstream 会把 diff 解析成"改后代码"（只剩新增与上下文行、语言置空），删除行与文件头全丢，不能直接用它的 code。
- 代码块不限高、块内不纵向滚动（放开 markstream 默认写在行内的 500px `height`/`max-height`）：回复流里不出现嵌套滚动区，生成中的 `<pre>` 与落定高亮块同高（60 行实测都是 1142px），落定时不塌。长块读到中间时块头（语言、复制）在回复滚动区里吸顶：停在 `--heading-cover` 下（紧凑外壳顶栏在场时 57px，向下阅读顶栏移出后贴回顶缘），在展开的过程组、思考里再让出一行吸顶摘要；容器的 overflow 用 clip 不用 hidden（hidden 会让 sticky 失效）；只在真正吸住时（`scroll-state(stuck: top)`）下沿出一道 7% 发丝线。用户气泡里的代码块不吸顶（气泡本身有 12 行截断）。生成中的语言标签同样吸顶（在流里用与 pre 相同的外边距叠到块头位，不占高度；首块清边距时一起清），落定换手位置不变。
- 320px 宽度不发生横向溢出；代码块和宽表在自己的区域内横向滚动，普通正文按可用宽度换行。代码不折行（流式与落定同为 `white-space: pre`）；被藏住内容的一侧渐隐 28px（生成中的普通 pre 与落定后的高亮块同一套），滚到头即消失，触屏没有可见滚动条也看得出还能滑。宽表同一套渐隐（静态与富渲染两条路径都要接上）；紧凑外壳下四列及以上的表单元格至少 8.5em 宽，列多时横滚而不是把每列挤成三四个字一行；三列以内下限 5em，按内容分列宽在屏内折行（390 宽本来放得下，不为几十像素整表横滚）；宽屏仍以折行为主。等宽字体一律关闭连字（`font-variant-ligatures: none`）：代码按字面显示，`>=` 不画成 `≥`。文字选区用主色的淡底（`--ak-rule-focus` 22%）并保留原文字色，不用浏览器默认的亮蓝白字。
- 短屏（高 ≤30rem）让当前内容滚动，标题和操作不抢占全部高度。输入区此时回到文档流，消息区底部只留 1rem，不再按"浮在上面的输入卡"预留一整张卡的高度；回到底部按钮同样贴消息区底部 12px，不叠加输入卡增高量。
- 紧凑外壳（抽屉导航、44px 触控尺寸、矮屏文档流）的条件是"宽 ≤820px，或触屏且高 ≤30rem"：手机横屏宽度常在 844～932px，按宽度会得到常驻侧栏，把对话挤到一半宽。条件出现在多条媒体查询和 `compact-navigation.tsx` 的 `COMPACT_SHELL` 里，改动时一并修改；平板高度 ≥48rem，不会命中。
- 紧凑外壳有消息时标题栏浮在滚动区上方、向下阅读时移出；它在场时展开的工具/思考吸顶行停在它下面（`--heading-cover`），移出后随之贴回顶缘，不被标题栏盖住。
- 宽屏标题栏里工作目录名不与标题按比例分摊收缩（上限 14rem）：目录名短而信息量大，长标题先让；两者放不下时都用右缘渐隐（MarqueeText），不用省略号。
- 紧凑外壳的标题栏宽度先给标题：工作目录只留 44px 文件夹图标（点开看完整路径），新会话等操作都是图标。回到底部按钮只留 36px 圆钮（编辑面纸色、轻阴影，生成中的呼吸点挂右上角），文字标签只在宽屏出现，少压正文。
- 验收入口：`npm run check:narrow-ui -- --url <服务> --output <私有目录>`，覆盖 320～1365px。

## 6. 命名的反模式

评审中见到以下模式直接打回，并优先用本文件的规则或 token 修复：

- **纹理纸**：用噪点、纹理图或动画假装纸感。纸感只能来自排版、留白、墨色和规则线。
- **双 owner 宽度**：同一个几何值（列宽、inset、缩进）写在两个文件或两条规则里，改一处就漂移。
- **断点绕行**：media query 里硬编码一个已有 token 的值，使变量在窄屏变成谎言。
- **层叠地雷**：组件上的 Tailwind 工具类靠"非 layered CSS 优先级更高"被静默压掉。覆盖关系必须显式，死类直接删。
- **居中幻觉**：`left: 50%` 对整个容器居中，而内容列是偏置的——浮动物必须对阅读列居中。
- **vw 假设**：用 `calc(100vw - Npx)` 猜测页面留白；容器链上任何一级 padding 都会让它失效。
- **装饰性 elevation**：用阴影堆叠层级。层级用 `--ak-paper-*` 纸面表达，阴影只留给临时浮层。
- **颜色借道**：因为"当前颜色恰好相同"而借用 border 或 status token 当背景/文字色。
