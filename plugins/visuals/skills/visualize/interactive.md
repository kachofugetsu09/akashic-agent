# 交互与卡片写法

先写样式（简短），再写内容，最后写 script。控件都已预置样式，直接写原生标签即可。

## 交互讲解（"调大会怎样""帮我算算"）

- 用 `label.param`（文字 + `output` + `input[type=range]`）做参数行，`p.readout` 写当前读数，图用 `ak` 或 SVG。
- 图形和读数都由公式实时算出，参数一变立即更新；每图最多 12 个滑块，每个都有可访问名称和当前值。
- 不加外框，留白就是容器；讲解文字写在正文，不写进图里。
- 文本用 `textContent` 写入，显示的每个数都取整，避免 NaN、Infinity 和 `0.30000000000000004`。
- 分步讲解（循环、算法步骤）：一步一个面板，用 ● ○ ○ 表示位置，`button` 切换上一步、下一步；
  每步自己的输入和产物都放在这一步的面板里。切换时只改已有元素的类和文字，不用 innerHTML 重建控件。
- 要"放大"时做一个展开开关：同步切换一个类，把图变高、控件变宽，同时改按钮文字；不调用全屏接口。
- 收集输入的控件在提交时先校验，缺失或无效就在旁边用小字提示并停下，用户一改就清掉提示。

## 方案对比（"这几个选哪个"）

- `div.cards` 放每个选项一张 `div.card`；关键差异用简短标签，推荐项加 `featured`，并在卡头写一个小标签。
- 只做卡片网格；逐项参数对比表写成正文里的 Markdown 表格。

## 数据记录（一张名片、一张收据）

- 一张 `div.card` 包住全部内容；人物用首字圆形头像，下面用细线分隔的两列表格写字段。

## 界面示意

- 手机界面、对话、弹窗这类小部件放在一块浅底面上（`--ak-color-bg-surface`，圆角 12px，留内边距），不让它悬空。
- 仪表盘、设置页这类本来就铺满的界面不需要再包一层。
- 弹窗不用 `position: fixed`：用一个有最小高度、半透明深色底的普通块当"假视口"，把弹窗放在里面。
