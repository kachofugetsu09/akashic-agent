# 示意图写法

示意图坐标最容易出错：viewBox 太小被裁、箭头穿过无关方框、标签压在线上、文字超出边界。
每放一个方框、每画一条线之前都先算。

## SVG 基础

- 写 `<svg width="100%" viewBox="0 0 680 H" role="img"><title>…</title><desc>…</desc>…`。宽度固定 680，
  内容窄就在 680 里居中，不要缩小 viewBox——那会把字一起放大。可用区域 x=40…640。
- H = 最低元素的下沿（文字基线再加 4px）+ 20。不用负坐标。`text-anchor="end"` 的文字向左长，靠左时改用 start。
- 文字用预置类：`t`（14px 正文）、`th`（14px 加粗，方框标题）、`ts`（12px 次要，副标题与说明）。只用这两种字号，
  不旋转文字。SVG 文字不会自动换行，需要换行就用 `<tspan x="…" dy="1.2em">`；需要换两行以上就说明太长了。
- 宽度估算：14px 时中文每字约 14px、英文和数字每字约 8px，12px 时按 0.86 倍。
  方框宽 = 最长那行文字宽 + 48。一行四个方框时先算总宽：4 × 宽 + 3 × 间距 ≤ 600。
- 预置图形类：`box` 中性方框，`arr` 连线（配 `marker-end="url(#arrow)"`，箭头已预置、颜色随线），
  `leader` 虚线引线，`node` 可点的组。`d1`…`d6`、`d-gray` 给方框按系列色上色，加在直接包住图形的 `<g>` 上
  或图形本身；组内的 `t`/`th`/`ts` 自动换成同色深色字，深色模式也成立。
- 线宽 0.5px，方框 `rx="4"`（强调最多 8）；连线的 `<path>` 一定写 `fill="none"`。
- 线停在方框边缘，不穿过去再靠填充遮住；箭头和方框留 10px。
- 除了方框里的名称和图例，不放漂浮的文字；箭头标签多半不需要，含义写进方框副标题或正文。

## 流程图（查阅：步骤、分支、数据流转）

- 一个方向到底（全部自上而下或全部从左到右），一张图四五个节点。
- 方框之间至少 60px，框内留 24px；单行方框高 44，标题加副标题高 56；同类方框同高。
- 方框内文字用 `dominant-baseline="central"`，y 取所在格子的中线。
- 直连会穿过别的方框时，用 L 形折线绕开：`<path d="M x1 y1 L x1 ym L x2 ym L x2 y2" fill="none"/>`。
- 回到起点的循环不要画成一圈：在流程末尾写 `↻ 回到第一步`；循环本身就是重点时，改用 `interactive.md`
  里的分步讲解，最后一步的"下一步"回到第一步。

## 结构图（查阅：东西里面套着东西）

- 外层容器用大圆角矩形（`rx` 20），浅色填充；内部区域用中圆角（`rx` 8–12），换一个系列色表示不同的东西。
- 容器内至少留 20px，最多三层嵌套；区域并排时间距 16px 以上。
- 区域里只写名称和一句做什么，不在区域里再画流程方框或图标。外部输入输出放在容器外，用箭头指进指出。
- 示意性的容器用带标签的虚线矩形，不画云朵、机柜这类具象外形。

## 机制示意（理解：它是怎么运作的）

- 画机制本身，而不是关于机制的方框图：物理对象画简化剖面（热水器是罐子加底下的火），
  抽象概念找一个空间比喻（注意力是一排词元和从一个词元散开的连线，粗细就是权重）。去掉标签也应该看得懂。
- 能操作就给控件：真实系统有旋钮，图里就给滑块或开关。没有可调的东西才画静态图。
- 形状保持示意级：一条路径超过六段就简化。图形可以叠放出层次，但任何线条都不能压到文字上，文字周围留 8px。
- 颜色表示强度不表示类别：暖色是热、能量、活跃，冷色是冷、平静，灰色是惰性结构。
  只为连续的物理量（罐内温度分层）允许用一个渐变。
- 标签统一放一侧（默认右侧，`text-anchor="start"`），那一侧留 140px，用 `leader` 引线指过去。
- 构图：先画主体轮廓并居中，再画内部结构，再画外部连接，最后加状态（填色、小动画）。
- 动画只动 `transform` 和 `opacity`，循环不超过 2 秒，放在 `@media (prefers-reduced-motion: no-preference)` 里。

## 插画与图案

用户要的是画而不是解释时：铺满画面，可以写自己的颜色，用重叠的不透明形状做层次，
用重复的线、点、网格做质感，用 `<g transform="rotate()">` 做放射对称。
