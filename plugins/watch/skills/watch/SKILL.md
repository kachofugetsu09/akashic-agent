# 值班

## 整体怎么运转

1. **来源**把外面发生的事交进来：订阅内容、邮件、短信、健康和位置变化等。来源不决定要不要打扰用户。
2. **值班员**是跑在便宜模型上的小循环。每隔几分钟，它把新到的事件攒成一批，对照你写的嘱托、用户的记忆和最近的对话，给每条事件一个去向：
   - `wake`：现在叫醒你。只有命中嘱托、或者这件事等不起时才这样做。
   - `inbox`：放进待看列表，等你下次醒来自己看。
   - `log`：只记录。
3. **你**在一个独立的后台会话里被叫醒。那里的文字用户看不到；想让用户看到，必须调用 `message_push` 发到主对话。你可以静默做事、留便签、改嘱托，也可以什么都不做。
4. **每日复盘**时你回看值班员一天的判断，纠正它，把积累出的认识写进记忆，整理嘱托和来源。

用户的反应教你，你的嘱托和纠正教值班员，值班员的记录再回到你手里。

## 你能做什么，做不到什么

能做的：
- 给自己定时间回来（带时间的嘱托），到点被叫醒后用全部工具做事。
- 让值班员替你盯着：任何来源交进来的事件，只要嘱托里写了，就会叫醒你。
- 给自己加来源：凡是能用一个脚本查出来的东西（日志、接口、网页、磁盘、进程），都能变成事件。
- 调整口径：哪类内容叫醒、哪类只进待看、哪类不用记；暂停或移除来源。
- 主动对用户说话，或者静默把事做完。

做不到的：
- 你不是一直醒着。两轮值班之间约十分钟，做不到秒级响应。
- 值班员只会分拣，不会执行动作；要做事必须把你叫醒。
- 没有来源交进来的事，谁也看不到。答应盯一件事之前先确认有来源。
- 每天被叫醒的次数有上限，嘱托写得太宽会把额度耗在不重要的事上。

## 文件

都在工作区的 `watch/` 目录下，用普通的文件工具读写。

| 文件 | 谁写 | 用途 |
| --- | --- | --- |
| `WATCH.md` | 你（用户也可以改） | 写给值班员的嘱托，见下一节 |
| `cases.md` | 你 | 值班员判错或漏判的例子，一行一条，以 `- ` 开头。值班员每次读最近二十条 |
| `inbox.md` | 值班员 | 待看列表。看完的行删掉；三天没处理的会自动清掉 |
| `notes.md` | 你 | 你自己的便签：做到一半的事、以后用得上的观察。用户看不到它；想让用户知道的事要么当场说，要么写一条带时间的嘱托让自己回来说 |
| `log/日期.md` | 值班员 | 每条事件的去向和理由，保留十四天 |
| `events/日期.jsonl` | 系统 | 事件全文，每行一个 JSON，字段 `id`、`source`、`at`、`title`、`text`、`url`、`state`、`key` |
| `places.md` | 你 | 你认出来的地点，一行一个：`- 公司: 40.0023,116.4745`。之后位置事件里落在三百米内的坐标会自动标上这个名字 |
| `archive.md` | 系统 | 到期或已触发的嘱托 |

想看某条事件的全文，在 `events/` 里按编号查找，例如搜索 `"id": "e123"`。

## 嘱托怎么写

`WATCH.md` 里有两节。每条一行，以 `- ` 开头。

- `## 叫醒我`：什么情况叫醒你。值班员命中其中一条就会叫醒你。
- `## 留意`：给值班员的其他提示，比如哪类内容只进待看、哪类不用记。

行首可以带方括号标记：

- `[到 2026-12-01]`：到期日。不写会自动补上（叫醒条件十四天，留意六十天）。到期没续就移进 `archive.md`，所以想保留的要在到期前把日期改晚。
- `[长期]`：触发后保留。不写就是一次性的，值班员按它叫醒过你一次就归档。还想继续跟，就再写一条。
- `[每天 22:00]`、`[工作日 22:00]`、`[周末 10:00]`、`[周三 09:00]`、`[2026-11-12 10:30]`：到这个时间让值班员对照当时的状态看一眼，条件成立才叫醒你。等一件"没有发生"的事（比如到某个时间用户还没回家）要用这种写法，因为没有事件会触发它。想让自己到点一定被叫醒，就写"到点叫我"加上要做的事。带时间的行写在哪一节都会到点查看。

例子：

```
## 叫醒我
- [到 2026-11-25] 某某模型正式发布
- [工作日 22:30][长期] 用户还在公司
- [2026-11-12 09:30] 到点叫我，看看昨晚说的那件事有没有结果

## 留意
- 论文类内容只进待看，不用叫我
```

已经不需要的嘱托直接删掉，不必等它过期。

## 用户让你盯一件事

答应之前先把机制搭起来。没有机制的"好，我盯着"是空话：你不会一直醒着，只有来源交进来的事件和到点的嘱托才会把你叫回来。

1. **先看有没有来源已经覆盖。** `watch/log/` 最近几天的记录里，方括号里就是现有的来源名（邮件、订阅、GitHub、健康、位置……）。这件事发生时会不会从其中一个来源进来？
2. **先写嘱托。** 不管有没有来源，都先在 `WATCH.md` 的"叫醒我"里加一行：什么情况叫醒你、叫醒后你要做什么。这一步最便宜，也最容易在忙别的时候漏掉。
3. **有来源覆盖：到此为止。** 不要再造一个重复的来源。
4. **没有来源覆盖：再加一个来源。** 最省事的是脚本来源（见"增删来源"）：写一个检查脚本，先在命令行里跑通，再放进 `watch/sources/`。只有嘱托没有来源不会触发，因为值班员看不到没人交进来的事。
5. **只是到某个时间要做一件事或提醒一句：** 写一条带时间的嘱托（"到点叫我：……"）。固定周期给用户发一份内容（每天的早报、周报）用定时任务工具，不属于值班。
6. **做完告诉用户你搭了什么：** 靠什么发现、多久看一次、什么情况会找他、哪些情况发现不了。

被叫醒之后你有全部工具：可以查原因、改代码、跑命令、再决定要不要告诉用户。值班员只判断去向，不替你做事。

## 用户嫌某类内容太多、太吵

改口径，不动来源：在 `WATCH.md` 的"留意"里写清这类内容以后怎么处理（只记录、只留哪一部分），值班员下一轮就照办。来源留着，他哪天想看还能找回来。只有他明说"退订""删掉这个源"时才去动订阅或来源文件，动完告诉他移除了哪一个。

## 每件事都要有着落

你被叫醒不等于要说话，但你手里的每一件事在这一轮结束前都要有着落，只有三种：

- **现在说**：和用户最近说过的话、正在做的事或他等着的结果直接相关，而他此刻醒着、没在忙别的。几件事合成一条，一轮最多发一条。缺一个只有他知道的信息，就直接问。
- **留到合适的时候**：值得说但此刻不合适（他睡着、在玩、说过别打扰），或者事情过些时候才有结果。在 `WATCH.md` 里给自己留一行，定一个时间（"到点叫我：……"）或者一个时刻（见下）。
- **放下**：不值得说，从待看列表和便签里删掉。

"合适的时候"不一定是一个钟点。他下班、到家、起床、打完游戏，都会作为状态事件进来；在 `WATCH.md` 里写"他离开公司时叫我：……"，值班员看到那条事件就会叫醒你。没有话要说，就不要为这些时刻留嘱托：每次下班都收到一句问候，和每次进门都被问一句"回来了"一样没有意义。

"等他下次来找我时再提"不是着落：他不知道你手里有这件事。等不起的事（安全、期限、他点名要第一时间知道的结果）不看时机，现在就说。说过一次没被接话的事不说第二遍。

## 增删来源

一个来源就是往事件流里写东西的任何程序。

- **脚本来源**：把脚本放在 `watch/sources/名字.sh` 或 `名字.py`，文件名就是来源名。值班每一轮（约十分钟）替你运行一次，运行环境和你用命令行执行时相同，当前目录是 `watch/sources/`。
  - 标准输出的每一行是一条事件：一个 JSON 对象（字段都可选：`title`、`text`、`url`、`at`、`state`、`key`），或者一行纯文本。没有新情况就什么都不输出。
  - 带 `key` 的事件同一来源只记一次。脚本每次都把"当前看到的问题"全部输出、各带稳定的 `key`，就不需要自己记上次看到哪里。
  - 三十秒内必须结束；每轮最多收两百行。退出码不是 0 时，你会收到一条"来源脚本运行失败"的事件，里面有错误输出。
  - 例子（盯一个服务的报错）：

    ```sh
    #!/bin/sh
    # watch/sources/myservice-errors.sh
    docker logs --since 15m myservice 2>&1 | grep -i error | while read -r line; do
      key=$(printf %s "$line" | cut -c1-120 | md5sum | cut -c1-12)
      printf '{"title": "myservice 报错", "text": %s, "key": "%s"}\n' "$(printf %s "$line" | python3 -c 'import json,sys; print(json.dumps(sys.stdin.read()))')" "$key"
    done
    ```
- **文件来源**：别的程序自己在跑时，让它往 `watch/sources/名字.jsonl` 追加一行，格式同上。文件只追加，不要截短或重写。
- **暂停与移除**：把文件改名（比如加上 `.paused` 后缀）就是暂停，改回来就恢复；删掉文件就是移除。
- **状态也是事件**：位置、睡眠、在不在线这类"现在怎么样"的信息没有另一条通道。来源在状态变化时交一条带 `"state": true` 的事件，它照常进事件流和值班记录，同时顶替这个来源的上一条状态；你和值班员看到的"用户当前状态"就是各来源最近的那一条。和上一条一模一样的状态不会重复记。想知道一段时间里状态怎么变过，在 `events/` 里按来源名搜索。
- **插件来源**：其他插件可以经 `watch.events.v1` 直接交事件。订阅类内容（RSS、推特等）由订阅插件管理，用它自己的工具增删订阅。
- 调整来源之前，先确认依据：这个来源长期没有产出用户在意的东西，或者用户对它的内容一直没有回应。能暂停就不要删除。调整之后要让用户知道：当场说，或者定一个时间说。
