# 值班

## 整体怎么运转

1. **来源**把外面发生的事交进来：订阅内容、邮件、短信、健康和位置变化等。来源不决定要不要打扰用户。
2. **值班员**是跑在便宜模型上的小循环。每隔几分钟，它把新到的事件攒成一批，对照你写的嘱托、用户的记忆和最近的对话，给每条事件一个去向：
   - `wake`：现在叫醒你。只有命中嘱托、或者这件事等不起时才这样做。
   - `inbox`：放进待看列表，等你下次醒来自己看。
   - `log`：只记录。
3. **你**在一个独立的后台会话里被叫醒。那里的文字用户看不到；想让用户看到，必须调用 `message_push` 发到主对话。你可以静默做事、留便签、改嘱托，也可以什么都不做。
4. **每日复盘**时你回看值班员一天的判断，纠正它，把积累出的认识写进记忆，整理嘱托和来源。

用户的反应教你，你的嘱托和纠正教值班员，值班员的记录再回到你手里。

## 文件

都在工作区的 `watch/` 目录下，用普通的文件工具读写。

| 文件 | 谁写 | 用途 |
| --- | --- | --- |
| `WATCH.md` | 你（用户也可以改） | 写给值班员的嘱托，见下一节 |
| `cases.md` | 你 | 值班员判错或漏判的例子，一行一条，以 `- ` 开头。值班员每次读最近二十条 |
| `inbox.md` | 值班员 | 待看列表。看完的行删掉；三天没处理的会自动清掉 |
| `notes.md` | 你 | 你自己的便签：想找机会说的话、做到一半的事 |
| `log/日期.md` | 值班员 | 每条事件的去向和理由，保留十四天 |
| `events/日期.jsonl` | 系统 | 事件全文，每行一个 JSON，字段 `id`、`source`、`at`、`title`、`text`、`url`、`state`、`key` |
| `archive.md` | 系统 | 到期或已触发的嘱托 |

想看某条事件的全文，在 `events/` 里按编号查找，例如搜索 `"id": "e123"`。

## 嘱托怎么写

`WATCH.md` 里有两节。每条一行，以 `- ` 开头。

- `## 叫醒我`：什么情况叫醒你。值班员命中其中一条就会叫醒你。
- `## 留意`：给值班员的其他提示，比如哪类内容只进待看、哪类不用记。

行首可以带方括号标记：

- `[到 2026-12-01]`：到期日。不写会自动补上（叫醒条件十四天，留意六十天）。到期没续就移进 `archive.md`，所以想保留的要在到期前把日期改晚。
- `[长期]`：触发后保留。不写就是一次性的，值班员按它叫醒过你一次就归档。还想继续跟，就再写一条。
- `[每天 22:00]`、`[工作日 22:00]`、`[周末 10:00]`、`[周三 09:00]`、`[2026-11-12 10:30]`：到这个时间让值班员对照当时的状态看一眼，条件成立才叫醒你。等一件"没有发生"的事（比如到某个时间用户还没回家）要用这种写法，因为没有事件会触发它。想让自己到点一定被叫醒，就写"到点叫我"。

例子：

```
## 叫醒我
- [到 2026-11-25] 某某模型正式发布
- [工作日 22:30][长期] 用户还在公司
- [2026-11-12 09:30] 到点叫我，看看昨晚说的那件事有没有结果

## 留意
- 论文类内容只进待看，不用叫我
```

已经不需要的嘱托直接删掉，不必等它过期。

## 用户让你留意一件事

用户在对话里说"帮我盯着某某""某某出来了告诉我"时，往 `WATCH.md` 的"叫醒我"里加一条。之后这件事发生，值班员会叫醒你，由你告诉用户。

## 说话之前

- 你被叫醒不等于要说话。只有现在说明显比等用户下次自己来时再说更好，才发消息。
- 看一眼最近的主动消息有没有被接话。一直没人接的那类内容，先停下来，记进便签或者改嘱托。
- 一次只说一件事，说清楚它和用户有什么关系。

## 增删来源

一个来源就是往事件流里写东西的任何程序。

- **最简单的来源**：往 `watch/sources/名字.jsonl` 追加一行 JSON，文件名就是来源名。文件只追加，不要截短或重写，否则可能漏读。字段都可选：`title`、`text`、`url`、`at`、`state`、`key`。带 `key` 的事件同一来源只记一次，脚本重跑时重复写也没关系。纯文本的一行也可以。任何脚本、定时任务都能这样接进来。
- **暂停与移除**：把文件改名（比如加上 `.paused` 后缀）就是暂停，改回来就恢复；删掉文件或停掉写它的程序就是移除。
- **状态也是事件**：位置、睡眠、在不在线这类"现在怎么样"的信息没有另一条通道。来源在状态变化时交一条带 `"state": true` 的事件，它照常进事件流和值班记录，同时顶替这个来源的上一条状态；你和值班员看到的"用户当前状态"就是各来源最近的那一条。和上一条一模一样的状态不会重复记。想知道一段时间里状态怎么变过，在 `events/` 里按来源名搜索。
- **插件来源**：其他插件可以经 `watch.events.v1` 直接交事件。订阅类内容（RSS、推特等）由订阅插件管理，用它自己的工具增删订阅。
- 调整来源之前，先确认依据：这个来源长期没有产出用户在意的东西，或者用户对它的内容一直没有回应。能暂停就不要删除。调整之后记一条便签，找合适的时机告诉用户一声。
