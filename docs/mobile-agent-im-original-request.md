# Akashic Mobile Agent IM 原始需求基线

本文冻结花月哥哥对移动端的长期要求。每轮实施开始前必须回看，不能因局部修复丢失产品方向。

## 产品定位

Akashic Mobile 不是 WebChat 的缩小版，也不是 Telegram 的换皮客户端。它是 Akashic-native 的日用 Agent IM：

- 用全程 WebSocket 承载低延迟流式回答、思考、工具调用、断线恢复和主动推送。
- 把 Akashic 的记忆、插件、Hook、左右脑协作和可观测过程变成移动端可操作能力。
- 保留成熟 IM 的基本功：时间、引用、复制、搜索、跳转、未读、附件、失败恢复和可访问性。
- 允许插件提供远端 Dashboard，但按移动任务重组，不能原样塞入桌面页面。

```text
┌─────────────────────────────────────────┐
│ 日用 IM 基本功                          │
│ 时间 · 引用 · 复制 · 搜索 · 附件 · 恢复 │
├─────────────────────────────────────────┤
│ Agent-native 实时过程                   │
│ 思考 ○──工具 ◇──思考 ○──最终回答       │
├─────────────────────────────────────────┤
│ Akashic 扩展面                          │
│ 插件空间 · Hook · 主动推送 · 记忆状态   │
└─────────────────────────────────────────┘
```

## 不可偏离的设计原则

1. **Task first**：先确定用户要完成的任务和状态，再决定是否需要容器、颜色、形状和动效。
2. **Material Design 3 语义优先**：颜色承担连接、Agent 活动、错误和选中状态；形状区分组件类别；层级主要由色面、位置和留白建立。
3. **克制使用卡片**：相关内容形成一个主题区，不把每条消息、每个工具、每个动作机械包成独立圆角卡片。
4. **形状有类别**：图标动作使用圆形 state layer，主操作使用胶囊，消息气泡使用方向性圆角，临时流程面板才使用大圆角容器。
5. **成熟交互优先复用**：引用滑动、触觉反馈、消息动作、滚动锚点等先研究 ExtraGram；前端能力先检查现有 SDK 和依赖，能复用不手搓。
6. **动效可中断且尊重减弱动画**：手势必须跟手、可撤销、无弹跳失控；最终状态稳定；`prefers-reduced-motion` 下仍可完成任务。
7. **排版服务阅读**：正文保持稳定行高与可读行宽，时间和数字使用 tabular figures，代码和工具参数才使用等宽字体。
8. **去除真正的 AI slop**：清理无语义渐变、胶囊泛滥、嵌套卡片、过度圆角和装饰性状态色；不得误删有明确 M3 状态含义的色面或 Agent 时间线语义。
9. **交互必须附着在语义对象上**：消息动作紧邻对应消息，引用预览附着在输入框上方，时间与送达状态跟随所属消息对齐；不能只保证功能存在，却把组件放在错误区域。

## ExtraGram 交互基准

引用消息采用 ExtraGram 的手势语义：

- 仅向左滑，最大位移 `80dp`。
- 横向意图明确后才接管手势，不能抢占正常纵向滚动和文字选择。
- 越过 `50dp` 阈值时触发一次轻触振动；退回阈值内后可再次触发。
- 松手仍越过阈值才进入引用；随后消息平滑归位。
- 输入区上方展示引用来源与单行预览，可关闭；发送后清空引用。
- 用户自己的提问和已完成的 Agent 回答都能被引用；正在流式生成的回答在完成前不可引用。
- 引用必须进入服务端历史和 Agent 模型上下文，并能在历史同步后恢复。

## 能力发现基准

每轮从以下七个领域找最弱项，不以“页面已经能聊天”为完成：

| 领域 | 必须持续补齐的能力 |
|---|---|
| 消息基本功 | 时间、日期分组、复制、引用、搜索、跳转、未读、重试 |
| 实时 Agent | 字符流、思考/工具时间线、停止、工具详情、错误和耗时 |
| 媒体 | 上传进度、预览、下载、分享、meme/GIF、失败恢复 |
| 网络 | 抖动、重连、ACK、恢复窗口、跨网络、明确连接状态 |
| 会话 | mobile 全量同步、稳定身份、切换、新建、失效处理 |
| 扩展 | 插件空间、移动 Dashboard、Hook 插槽、KVCache 试点 |
| 质量 | Pixel 7 真机、隔离 workspace、真实模型、截图/日志、回归 |

## 每轮固定闭环

```text
发现缺口
   ↓
Better UI + Better Colors + Better Typography 设计
   ↓
定义可复用的 Pixel 7 验收标准
   ↓
隔离环境实施与自动化验证
   ↓
Pixel 7 真实聊天、手势、振动、截图和日志验收
   ↓
Kill AI Slop 扫描与人工语义复核
   ↓
记录文档 → 独立 Review → 修正 → 小步 Commit
   └──────────────────────────────↺
```

## 安全与验证边界

- 所有会写数据的验证使用独立 workspace 和独立 `AKASHIC_PLUGIN_HOME`；正式 workspace 只允许只读复制需要的样本。
- 修改持久化文件或执行可能覆盖数据的动作前，先建立清晰、可恢复的备份。
- 允许使用 `config.toml` 中的真实模型做验收，但不能把测试对话写入正式会话库。
- Android 以 Pixel 7 为主验收设备；自动测试、真机操作、截图和 logcat 共同构成证据。
- 每个语义完整的功能组独立 Review、独立提交；发布 APK 是版本闭环，不替代功能验收。

## 插件集成方向

插件不是首轮最高优先级。先完成日用 IM 基本功，再以 KVCache/状态类 Dashboard 做第一个试点：

```text
会话抽屉
├─ 会话列表
├─ 插件空间入口
│  └─ 核心区域切换为移动任务面板
│     ├─ 摘要状态
│     ├─ 高频动作
│     └─ 需要时展开详情
└─ 新聊天与低频维护动作
```

插件已有 Dashboard 时先审阅信息结构和 RPC，再迁移一个移动任务切片；不一次性移植全部桌面界面。
