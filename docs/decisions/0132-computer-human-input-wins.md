# 0132 · Computer 不再接管：谁在动谁用

- 状态：proposed / implemented for review
- 日期：2026-10-24
- 关联：替代 [0092](0092-computer-viewing-and-control.md) 的接管与只读规则；PLG-017、WEBUI-008

## 背景

0092 让人先点「接管」才能操作，Agent 整个回合期间锁住面板，交还要再点一次。实际用法是：Agent 卡在登录页，人在面板里登录，然后在聊天里说“继续”。接管状态不会自己结束，Agent 的下一次调用一直等到 Core 的 170 秒硬超时，报出看不懂的 TimeoutError。Memoh 完全不锁，人和 Agent 的键鼠直接写同一个桌面，登录这类事走聊天提问。

## 决定

- 画面连上后随时可以直接操作，没有接管、交还和只读模式。
- 只在 Agent 正在执行单个浏览器操作时（通常一两秒，最后一步之后再留 300ms）挡住人的键鼠，面板胶囊显示“Agent 正在操作…”。Agent 的调用在进行、但这一刻没在操作时不挡。
- 人点击、滚动或按键时持有 5 秒短租约，每次输入从头计时：Agent 做完当前这一步后停下，等人的那次调用暂停计时，人停手后自己继续。移动鼠标不算。地址栏、标签条等面板操作同样持有租约。
- 一次调用累计最多等人 40 秒；超过就明确失败，提示模型去聊天里问用户是否操作完成。110 秒调用上限加 40 秒等待留在 Core 的 170 秒之内。
- 登录、验证码、二次验证：工具说明和 computer skill 要求 Agent 在聊天里请用户在面板完成并结束回合，不猜凭据、不反复试选择器。
- Agent 光标停在最后的落点，直到 Agent 下一次操作或人点击画面；不再 5 秒后消失。

## 代价

人的输入先送到浏览器、租约随后才建立，Agent 一步刚开始的约 100ms 内（状态还没推到面板）人按下的键可能和这一步交错；不为此让每次点击先等租约确认，那会给每个首次点击加延迟。人两次输入之间停顿超过 5 秒时，Agent 可能插进来一步；登录这类长操作靠 Agent 主动停下来等聊天回复兜住。租约不区分窗口：画面同一时刻只给一个窗口（0123），没有第二个可以抢的人。

## 验收

隔离 E2E：移动鼠标不暂停 Agent；点击后 Agent 的计时和 OpenCLI 暂停，租约到期后自己继续；Agent 执行一步时代理丢弃原始键盘、剪贴板和二进制输入；不接管直接点击、输入、粘贴生效。真实发消息复现：Agent 打开需要登录的页面并在聊天里请求登录，人在面板直接登录后说“继续”，Agent 接着操作。
