# 0142 · 主题按「配色 × 明暗」选择，内置配色遵守同一组感知规则

- 状态：accepted / implemented for review
- 日期：2026-11-06
- 关联条款：WEBUI-001～WEBUI-007
- 细化：0043 的纸面品牌 token；颜色仍然只在 `theme-catalog.json` 里声明。

## 背景

用户反馈「纸感 / 墨纸」看久了不舒服。把两套主题换算到 OKLCH（感知均匀的色彩空间）后，有四个可测量的原因：

- 正文对比过强：亮色 16.7:1，暗色 14.9:1。长时间阅读的舒适区大约在 10–13:1。
- 冷暖相冲：纸面色相 h≈100（偏黄），强调色海军蓝 h≈258，两者接近互补。浅蓝强调底 `#eef2f7` 的明度 0.960 和纸面 0.966 几乎相同，色相不同而明度相同的边界看起来发脏。
- 纸面层级不等距：纸面 0.966、侧栏 0.972、卡片 0.948、0.924、0.899。侧栏比纸面还亮，只差 0.006，分区几乎看不出来。
- 错误色彩度 0.147，其他状态色在 0.03–0.08，错误色一出现就抢走注意力。

切换方式也有问题：唯一的入口是侧栏底部的循环按钮。主题一多就要逐个点；手机上这个按钮在导航抽屉里，每点一次抽屉就关上。

## 决定

1. **主题目录升到 version 3，按配色组织。** `families` 列出配色，每个主题用 `family` 指向它。每套配色恰好一个亮色、一个暗色主题，运行时和首帧脚本都会校验。
2. **偏好是「配色 × 明暗」。** 明暗分为亮、暗、跟随系统三种。固定明暗时 cookie 仍然写主题 id，旧 cookie 照常可用；跟随系统写 `system-<配色>`，运行时和首帧脚本按 `prefers-color-scheme` 取这套配色的亮色或暗色，系统外观变化时实时切换。同步频道比较的是偏好而不是生效的主题：「暗」改成「跟随系统」时生效主题可能没变，但另一个文档里的菜单也要更新。
3. **侧栏的主题入口改成菜单。** 上方是三段明暗选择，下方是带色票的配色列表。选中某项后菜单不关，手机抽屉里也能连续比较几套配色；点菜单外面或按 Esc 收起。另外加一个快捷键 Ctrl/⌘+Shift+L，在当前配色里切换亮色和暗色。`cycleTheme` 的含义随之改为「当前配色里亮暗互换」。
4. **Host SDK `@akashic/web-ui-v1` 新增四个导出：** `themeFamilies`、`themeSelection`、`setThemePreference`、`useThemeSelection`。聊天和外壳在同一个文档里共用外壳的主题运行时（见 0126），所以菜单只能通过 SDK 读写。这四个都是新增导出，已有导出不变。
5. **内置六套新配色，原有「纸感」保留，默认主题不变。** 新配色都由同一组规则生成：
   - 正文对比度控制在 10–14:1。墨色带一点纸面的色相，不用纯黑或纯白。
   - 强调底不单独取色，而是用强调色在 OKLab 空间里以 10% 叠到纸面上（暗色为 22%），所以它自然带着纸面的冷暖。
   - 纸面层级在 OKLCH 里按等间隔排列。亮色时侧栏比纸面略暗；暗色时层级逐级变亮。
   - 状态色共用同一个明度和彩度，只换色相；错误色的彩度只略高一些。
   - 所有文字配对都满足 WCAG：正文和次要文字 ≥ 7，弱文字放在卡片上也 ≥ 4.5，按钮文字 ≥ 4.5，容器里的文字 ≥ 7。

| 配色 | 依据 | 正文对比（亮 / 暗） |
|---|---|---|
| 纸感·校正 | 保留羊皮纸和海军蓝，只修正上面四个问题 | 13.5 / 12.7 |
| 赭墨 | 邻近色：纸、墨、强调色都在暖色一侧 | 12.9 / 12.3 |
| 苔绿 | 灰绿纸面配松绿强调色，对灰和墨的色偏最小 | 12.9 / 12.5 |
| 石灰 | 近乎无彩度的纸面，强调色和状态色显出本来的颜色 | 13.8 / 13.0 |
| 雾蓝·铜 | 冷底配暖强调色，两者明度拉开，避免互补色振动 | 13.6 / 13.0 |
| 暮色·低对比 | 纸面压暗、间隔最小、眩光最低 | 10.4 / 10.2 |

## 代价与已知限制

- 主题 id 是公开偏好的一部分。以后要改名，需要像 `warm-paper` 那样在运行时和首帧脚本里写迁移。
- 在跟随系统模式下按 Ctrl/⌘+Shift+L 会退出跟随，改成固定明暗。这是有意的：按快捷键就表示此刻要的是另一面。
- 原来的「纸感」仍有上面列出的四个问题，保留它是为了不改变现有用户的观感。默认主题要不要换成「纸感·校正」，另行决定。
