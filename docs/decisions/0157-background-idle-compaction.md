# 0157 · 空闲摘要由后台提前生成，发布仍由 compaction 独占

- 状态：accepted
- 日期：2026-11-14
- 关联：PR #2048；CTX-001、CTX-007、STA-002、PLG-017
- 部分 supersedes：[0095](0095-context-compaction-uses-settled-batches.md) 中不启动后台摘要的实现选择；批次切点、原文保留和失败合同继续有效。

## 背景与决定

只在下一条输入到达后做空闲摘要，会让用户再次等待旧历史压缩。本次将已启用的空闲策略提前到后台执行；新输入仍可触发原有兜底，不另设摘要存储或发布 owner。

后台每分钟检查一次。selected 只检查显式会话；all 检查最近七天更新的 listed 会话。没有开放的 conversation 输入、已有回复结束且空闲时长和 token 门槛满足，才进入既有批次摘要算法。其他来源未结算的尾部沿回复视图的规则隐藏，不改写原 Message。

同一会话的后台与回合内压缩串行。新输入到达时，正在生成的后台摘要可以完成；回合侧等待并采用新 head，再判断是否仍需强制缩减。摘要模型与业务模型由本次独立 execution 固定；不动态切换到另一个执行接口。失败预算按会话和模型复用，可恢复模型故障保留原材料，内部或存储错误进入真实任务故障。

```text
┌──────────────────┐     ┌──────────────────────────┐
│ 后台空闲检查      │ ──▶ │ 同一会话的压缩锁          │ ◀── 回合内压缩
└──────────────────┘     └─────────────┬────────────┘
                                      ▼
                         ┌──────────────────────────┐
                         │ compaction 摘要发布事务   │
                         │ summary + head + 边界消息 │
                         └─────────────┬────────────┘
                                       ▼
                          模型采用摘要；UI 展示分隔条
```

后台摘要、head 和 source=compaction 的静默 Output 在同一 Ledger 事务提交。边界只记录摘要引用、触发原因、代数和 token 估算；预览由 UI 在同代作用域内异步读取并投影，不复制为新的持久正文。边界不进入模型输入和后续摘要正文，也不取得对话渠道发送权。既有消息、摘要、工具回执不改写或删除；没有自动减少协议，无 schema 迁移。

## 取舍与恢复

不取消已经开始的摘要模型调用来抢占新输入，避免重复付费和两条发布路径争用 head；代价是新回合可能等待本次可选摘要。后台仍复用空闲摘要的调用期限。扫描范围限制在近期会话，避免每分钟遍历全部历史。

不分两次提交摘要与边界，否则第二次失败会留下无法恢复的可见记录缺口；也不另建重试 outbox。事务失败两者都不发布，模型调用账如实保留。进程重启按现有 head 和持久边界重新判断，无已完成消息重放或数据回滚。源码恢复使用 Git 和发行版身份，不覆盖正式消息。

验收使用隔离实例，覆盖无输入时生成、同一静默期不重复、新输入与摘要并发、边界写入失败的整笔回滚、既有消息全文和顺序，以及等待摘要读取时事件循环仍可运行。浏览器核对窄屏、键盘展开和摘要预览；隔离结果不冒充正式渠道送达。
