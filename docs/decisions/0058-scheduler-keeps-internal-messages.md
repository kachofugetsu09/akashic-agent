# 0055 · Scheduler 保留可恢复的内部消息

- 状态：accepted
- 日期：2026-09-06
- 关联条款：SCH-001～SCH-003、SES-003～SES-005、MEM-001～MEM-002
- supersedes：0041 对 Scheduler 采用 in_memory 的选择

## 背景

原 Scheduler 在内存中完成完整 ReAct。新工具合同要求先持久保存调用和原 binding，崩溃后才能核对已开始的效果。内部推理完全不落盘无法满足该合同；仅在聊天界面隐藏消息也不能自行取得持久化授权。

## 决定

维护者允许 Scheduler 每次触发建立独立内部 Session，保留恢复所需消息。具体可观察合同由 SCH-003 拥有。这项批准只改变 Scheduler，不推断其他来源也已取得同样授权。

```text
┌ job + 触发时间 ┐
└───────┬───────┘
        ▼
┌ 独立内部 Session ┐
│ Input → ReAct    │
│ 调用与结果可恢复  │
└────────┬────────┘
         ▼
┌ 目标聊天的最终通知 ┐ → Delivery 回执 → job 结算
└─────────────────┘
```

## 理由与影响

无状态推理表示每次只读取当前触发的输入，不表示丢弃已经发生的工具事实。复用 Message 和工具回执可避免另一套 Scheduler 执行日志；来源仍以既有 job 区分，不在 Core 新建 Run 或业务分支。

内部消息与最终通知属于不同 Session，展示、自动投递和学习分别遵守明确准入规则。内部消息没有自动减少协议，备份覆盖原消息、binding、工具和 Delivery 恢复材料。正式 workspace 的迁移仍按整栈发布流程执行。

## 验收

- 连续两次触发不读取彼此的推理历史。
- 工具已执行或最终输出已保存后重启，不重复工具或推理。
- 内部消息不进入聊天列表、默认投递和记忆学习；最终通知按原发送回执结算。
- 停止、取消、未知效果及周期重排保留各自真实状态。

实施与迁移见 [Message/plugins 分层合同](../design/0902-reviewed-v4.md) 第 09 层。
