# 0121 · 对话工具区升级为按会话组织的工作台

- 状态：proposed
- 日期：2026-10-16
- 关联：WEBUI-008、PLG-014、PLG-016、SES-009、SH-004、0051、0053、0070、0092、0111、0115、#1419
- 设计：[conversation-workbench](../design/conversation-workbench.md)

## 背景

`conversation.tools.v1` 只有“电脑”一个标签，现有能力有三个缺口：
- 标签拿不到当前会话；
- 对话里的点击打不开标签；
- 标签里的内容回不到输入框。

所以终端命令、每轮文件改动、附件预览这类与当前会话强相关的能力都放不进来。

## 决定

1. **宿主只增加三项通用能力，仍不拥有会话、轮次或领域状态。**
   - **会话上下文**：聊天 iframe 报告当前会话 ID，conversation-ui 原样转交给标签，只读，不保存、不推导。
   - **意图路由**：对话内容可以在点击处理函数里发出带版本的意图，例如 `workspace.changes.open.v1`。
     - 宿主只校验外层（名字、大小、当前会话），按标签顺序交给第一个 `accepts` 该意图的标签，并异步回执处理结果。
     - payload 由意图的领域 owner 定义。宿主不认识意图含义，也不按插件名分支。
   - **引用回输入框**：标签在点击处理函数里请求插入一段带来源说明的文本，请求必须带发起时的会话。
     宿主和聊天端各核对一次当前会话，不一致就拒绝。复用现有 `insertDraft`，不新增消息内容种类，不自动发送。
2. **只有用户的点击可以打开工具区。** Agent 侧活动仍只亮徽标（延续 0092）。
3. **合同升级为 `conversation.tools.v2`**，补上可核对摘要的合同 JSON。v1 唯一的消费者是电脑，迁移时一并删除 v1。
4. **事实由 owner 持有，标签由 owner 或独立插件提供。**
   - 命令记录和终端标签都归 `standard_tools`。只有一个消费者，按 0111 暂不发布跨插件合同。
   - 新插件 `workspace_changes` 拥有每轮改动，经公开合同取会话目录、轮次投影与进程执行，不读取兄弟插件的私有状态。
   - 预览标签是独立插件，经 `ARTIFACT_READ` 读附件。
5. **每轮改动首版只支持 git 仓库**，口径是“观测窗口内的工作目录差异”：
   - 起始与结束各拍一次工作区快照。快照用临时 index，不改用户的 index、HEAD 和 refs。
   - 结束时立即算出 diff 并保存。
   - 窗口可能偏差时标“可能不完整”，不当作精确归因。
   - 仓库声明了 filter（含 LFS）时不拍快照。
   - 非 git 目录不统计。
6. **新增持久记录用固定槽位循环覆盖**：每会话命令 200 条、轮次改动 50 条，每条有字节上限。
   OwnerStore 没有删除接口，槽位数就是每会话的物理上限。

## 不做

- 完整文件管理器；
- 改动的暂存、回滚、提交；
- 多面板平铺、独立窗口；
- Agent 自动打开工具区；
- 全局工具事件总线；
- 本会话净 diff。

终端实时输出与交互终端需要 host_execution 的非消费输出观察合同，另立决策。
非 git 目录的改动统计需要 host_execution 在文件锁内返回改前改后的回执，另立决策。

## 后果

- WEBUI-008 增补：工具区可以向子标签转交当前会话 ID、路由用户意图、转发核对过会话的引用请求；仍不得拥有会话、轮次和领域状态。
- 新增两类持久事实，各自归 owner：
  - `standard_tools` 的命令记录：内容与对话里的工具结果相同；
  - `workspace_changes` 的轮次改动：可能包含工作区里尚未进入对话的文件内容。

  两类都存在 sessions.db 里，备份范围与对话相同。插件停用时不采集，卸载保留历史。
- 跨会话的总量随会话数增长，物理清理要等 ledger 提供窄清理合同，是已知限制。
- 切片与延后项见设计文档第 6、7 节。
