# 0121 · 对话工具区升级为按会话组织的工作台

- 状态：proposed
- 日期：2026-10-16
- 关联：WEBUI-008、PLG-014、PLG-016、SES-009、SH-004、0051、0053、0092、#1419
- 设计：[conversation-workbench](../design/conversation-workbench.md)

## 背景

`conversation.tools.v1` 只有"电脑"一个标签。标签拿不到当前会话，对话里的点击打不开标签，
标签里的内容也回不到输入框，所以终端命令、每轮文件改动、附件预览这类与当前会话强相关的能力都放不进来。

## 决定

1. **宿主只增加三项通用能力，仍不拥有会话、轮次或领域状态。**
   - 会话上下文：聊天 iframe 报告当前会话 ID，conversation-ui 原样转交给标签（只读事实，不保存、不推导）。
   - 意图路由：对话内容可以发出 `{intent, payload}`，例如 `workspace.changes.open`；标签用 `accepts`
     声明能处理的意图，宿主按标签顺序交给第一个接受者。宿主不认识意图含义，也不按插件名分支。
   - 引用回输入框：标签可以请求把一段带来源说明的文本插入输入框草稿，复用现有 `insertDraft`，不新增消息内容种类。
2. **只有用户的点击可以打开工具区。** 意图必须来自用户手势；Agent 侧的活动仍只亮徽标（延续 0092）。
3. **合同升级为 `conversation.tools.v2`**，补上可核对摘要的合同 JSON；v1 标签在过渡期仍可注册。
4. **事实由 owner 发布窄合同，标签插件只消费。**
   - `standard_tools` 发布 `standard_tools.command_log.v1`（会话内 shell 命令记录）与
     `standard_tools.file_edits.v1`（`edit_file`/`write_file` 的改前改后记录）。
   - 新插件 `workspace_changes` 拥有每轮改动：git 工作区快照、轮次 diff 与存储；不读取兄弟插件私有状态。
   - 终端标签、改动标签、预览标签各是独立插件，可单独卸载。
5. **每轮改动的口径**：工作目录是 git 仓库时，以输入提交时与轮次结束时的工作区快照之差为准
   （临时 index，不改用户 index、分支与提交）；否则只统计文件工具的改动并在界面注明。
   起始快照晚于该轮第一次工具调用时，结果标为"可能不完整"，不静默当作完整。

## 不做

完整文件管理器、改动的暂存/回滚/提交、多面板平铺、独立窗口、Agent 自动打开工具区、全局工具事件总线。
交互终端需要 host_execution 的输出流合同，另立决策。

## 后果

- WEBUI-008 增补：工具区可以向子标签转交当前会话 ID、路由用户意图、转发引用请求；仍不得拥有会话、轮次和领域状态。
- 新增两类持久事实：`standard_tools` 的命令与文件编辑记录、`workspace_changes` 的轮次改动摘要与有界 diff。
  两者都按会话保存在各自 owner 的状态中，随插件数据清理，设上限并在超限时明确标注。
- 每一步单独提 PR，按设计文档的切片顺序推进。
