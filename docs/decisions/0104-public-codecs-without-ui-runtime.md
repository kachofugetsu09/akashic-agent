# 0104 · 公共表示不要求启用 UI runtime

- 状态：proposed / implemented for review
- 日期：2026-10-11
- 依据：#1179 的 headless 和停用验收；本次用户授权自主决定并独立提交评审。

## 决定与理由

提供方的公共 API 可以包含无隐含状态的值校验、编码和显式只读流适配，
与其公共类型一起固定到进程寿命。补充 0102 的 Protocol、值和 ServiceKey
约定：这些函数不能发现 provider、打开数据库、登记资源或写入业务状态。
流适配只能使用调用者传入的窄 reader，取消时关闭它自己打开的订阅。
需要 provider 或资源的投影仍由运行中的 UI Effect 拥有。

将通用消息编码留在 Core 会让 Core 继续拥有展示词汇；让 Gateway 的基本历史
读取硬依赖 UI runtime 则无法满足无 UI 的 headless 模式。复制同一编码到各客户端
会产生两套 wire 表示。因此消息页、会话摘要与续读编码由 UI 公共 API 唯一拥有，
浏览器服务、工具展示 callback 和查询线程仍只在 UI runtime 活动时可用。

┌──────────────────────┐      ┌────────────────────────┐
│ Gateway / Web 调用者 │ ───► │ UI 公共编码 + 窄 reader │
└──────────────────────┘      └────────────┬───────────┘
                                          │ 可选借用
                             ┌────────────▼───────────┐
                             │ UI runtime 的业务展示  │
                             └────────────────────────┘

可观察变化：停用 UI 后，Gateway 仍返回基本消息事实；需要工具名称或插件展示的
字段明确标记 unavailable。此前这条请求报 UI 不可用。权威消息和 wire 字段不变，
不安装、启用或代选 UI。公共 API 制品仍须显式安装，改变 API 后必须重启。

如果未来 wire 版本不再共享此表示，重新评估编码 owner；不因此建立中央 contracts。
源码可回退到本 PR 前置分支，没有数据迁移或正式数据写入。
