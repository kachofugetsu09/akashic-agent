# 0152 值班：话留到合适的时刻说，聊天里先回应

状态：proposed / implemented for review
关联条款：PRO-004～PRO-006

## 背景

0151 之后主 Agent 不再把事情搁着不说，但真实记录和长程回放里还有四类问题：

- 用户来主对话的八十多次开口里，约三成是它本可以先开口的事（问睡得怎么样、报状态、设备数据断了、一件事的结果）。它手里有这些信息，却等用户来问。
- 它主动说的几乎全是提醒，像秘书而不像认识他的人：用户提过要发生的事（考试、答辩、在等的东西）过去之后，它不会回头问一句结果。
- 聊天回复过长（平均四百字），常以提问结尾，把用户分享的一件高兴的事接成叮嘱和建议。
- 位置事件只有一对坐标，它既认不出那是哪里，也没法据此开口。

用户主动消息的真实回复率很低（两小时内说话的约两成，真正在回的约百分之五），所以"他没回"不能当作"他反感"的证据。

## 决定

1. **着落的第二种改为"留到合适的时候"**：除了定一个时间，也可以定一个时刻。下班、到家、起床、打完游戏本来就作为状态事件进来，嘱托写成"他离开公司时叫我：……"即可。没有话要说就不为这些时刻留嘱托。
2. **主动消息的口径**：不回是常态，每句话自己立得住，不因没回而越说越少；没有内容的话不发；想问的只问他自己提过、在意的事，一次一句，没回就放下；一条消息说一件事，不把不相干的小事凑成一条，不请他回一句来销账，不为改口再补一条。
3. **复盘时回看两件事**：他提过要发生的事有没有过去了还不知道结果；他这些天是为了什么来找它的，其中哪些下次可以先开口。只挑真有内容的那几回。
4. **认识带来源**：复盘时自己去看、去读，把对他多明白的一点记进记忆并写明依据，猜的标明是猜的；记忆是改写不是追加。常去的地点记进 `watch/places.md`（一行 `- 名字: 纬度,经度`），之后事件里落在三百米内的坐标自动带上名字。
5. **聊天里的提醒始终注入**（原先只在便签非空时给）：后台攒下的东西不是这次对话的议程，先回应他这句话；他的话短就回得短；没人问不给建议；知道的事相关时用上并说得出来源。

## 依据

- 人际研究：跟进式提问比换话题式提问更招人喜欢（Huang 等 2017）；动机式访谈要求回应与提问至少二比一，连问会让对方变成被审的人；不被察觉的支持比显眼的支持有效（Bolger 等 2000）；别人分享好消息时，一起高兴比给建议更能增进关系（Gable 等 2004）。
- 人机研究：既私密又出乎意料的主动开口最容易让人不适，所以要求它说得出是从哪知道的；主动助手评测里主要的失败是误报；混合主动的经典做法是按期望效用在"说、问、等"之间取舍（Horvitz 1999）。
- 长程回放：用同一段十九天的真实事件和真实用户开场句，按真实回复率模拟回复，对比 0151 版本与本次改动。数字见 PR 描述。

评测脚本和素材含用户的真实记忆与对话，留在本机，不进仓库。

## 已知限制

- 回放里用户的回复是按比例模拟的，评测间隔是六小时或一小时而不是生产的十分钟；时机类的结论只能看方向。
- "先开口"提升有限：多数这类事要求它在用户开口前几小时内就得到信息并判断值得说，目前只在睡眠和期限两类上稳定出现。
- 地点靠主 Agent 自己认并写进文件，认错了要它自己改；三百米的半径是固定的。
- 主动消息量比 0151 版本略多。每天叫醒次数的上限不变。
