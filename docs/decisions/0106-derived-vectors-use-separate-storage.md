# 0106 · 消息向量使用独立派生库

- 状态：proposed / implemented for review
- 日期：2026-10-11
- 依据：#1179 D1'、P2f；用户授权自主决定并单独提交重大选择。

Ledger 将消息向量写入 `sessions-derived.db`，权威消息、owner 事务、bindings、身份和
交接仍在 `sessions.db`。向量检查真实已接纳消息，但不参与源库事务，也不获得源消息
更新或删除能力。首次保存后同身份的不同向量仍报冲突，损坏不伪装成缓存缺失。

┌─────────────────────────┐       ┌────────────────────────┐
│ sessions.db             │ 读取  │ sessions-derived.db    │
│ 原消息和业务事务        │◄──────│ 文本摘要、模型及向量   │
└─────────────────────────┘       └────────────────────────┘

Yoyo `20261011_01_derived_storage` 用只读源连接复制 `message_embeddings` 和
`message_embedding_migrations`，核对全部源行；已有目标冲突则回滚目标事务并报错。
不删除、改名或清空原表。步骤重试允许相同复制结果，不允许覆盖不同结果。
旧 Core 可以继续读取保留的旧表；本层之后的新向量只进入派生库，回退不会自动同步它们。
恢复点为前置提交 `f4c78443afa559df64fd861fc595c07d1eb23579`。

派生库缺席时创建空库，正常读取返回缺失，重算写入不接触源库。卸载只关闭连接，
不删除文件。运行时不重复从旧表复制，避免复活迁移后被显式清除的缓存。
取消和换代先排空消费者，再由 Ledger Effect 关闭派生连接和权威连接。

这是 P2f 的存储层；[0107](0107-restore-missing-vectors-before-reading-memory.md) 补齐按原模型
空间恢复缺失向量的行为及真实召回验收。存储缺失检查本身不证明应用召回可用。
正式 workspace 未迁移。旧版本实际生成的数据通过新 Yoyo 迁移后，两张表完整行相同，
重复迁移无操作，源库字节保持；删除派生副本后的缺失和重新写入也不改动源库字节。
