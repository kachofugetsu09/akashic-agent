# 0070 · 插件负责自己的持久化数据

- 状态：accepted
- 日期：2026-09-14
- 关联条款：PLG-018、RUN-008、RUN-009、ERR-001
- 部分取代：[0069](0069-bindings-follow-selected-runtime-scope.md) 第 4 项的恢复兼容性准入

## 背景与决定

组件身份相同不等于旧操作可恢复，代码变化也不等于旧数据不可读。Core 的
`matches_current()` 将插件依赖闭包的 archive_ref 比较传播到业务恢复，阻止了当前插件处理自己的旧数据。

插件系统负责加载、依赖与切换，并提供本次选定 scope 中的插件。插件负责自己的持久化数据，
处理不了就明确报错。删除 Core 版本匹配和消费者准入分支，不增加通用恢复入口、版本声明或迁移框架。
插件需要迁移数据时，由插件按已有数据管理协议执行；系统传播错误，不替插件兜底重跑。

```text
┌─────────────────────────┐
│ 插件系统：加载、依赖、切换 │
└────────────┬────────────┘
             ▼
┌─────────────────────────┐
│ 当前插件：处理自己的数据   │
│ 处理不了：明确报错         │
└─────────────────────────┘
```

## 影响与验收

Binding 继续保存不可变选择，执行记录仍由原业务 owner 保存。消息、回执、binding、归档和
plugin-data 不迁移、不改写、不删除；已有增加、更新与保留协议不变。源码 backup 分支保存修改前状态。

- 当前插件可以读取并处理换版前留下的事实，不因代码或依赖版本变化提前拒绝。
- 插件无法处理数据时错误明确传播，不伪造成功、不自动重复外部副作用。
- 原操作身份、目标和回执不因切换而重建；终态重复读取不再执行。
- 本次调用的 scope、候选隔离、权限和资源生命周期继续由已有 owner 负责。
