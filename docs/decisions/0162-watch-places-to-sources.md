# 0162 值班：反复去的地方接成来源，搁久的猜测当天了结

状态：proposed / implemented for review

## 背景

0161 上线后读了两天、十三个后台回合。去的地方明显变多，足迹自动记、自动带进下一轮。但有四件事没到位：

- 用户自己的账号里不断有新记录的地方，它每一轮都重新进去翻一遍。提示词只在"用户问过还在变的事"和"用户反复提到却没有来源覆盖的话题"两种情况下让它加来源，而 0161 又让它对着足迹挑地方去，于是这些地方只被当成去处，没有被当成来源。回合的调用数从二三十次涨到五十到九十多次。
- 看到的东西大多只进了记忆，记的是用户在哪里做了什么，没有写它因此对用户多明白了什么，也很少变成对用户说的一句话。
- 便签里一条只能猜的观察挂了五天，仍写着继续观察。评测里它会问，线上事情一多就一直拖。
- 足迹不认命令行去的地方，这类回合被记成没有出门（0161 的已知限制）。

## 决定

1. 去过的地方分两种：看一眼就够的，和不断有新东西的。后一种去过两三回、每回都有新的，就接成来源，让新东西自己进事件流；只交变化，零碎的合成一条，进不去时也交一条。接好之后在记忆里写明，不再专门去。每日复盘时对着足迹做同样的检查。
2. 技能说明里写明用户自己的账号、设备、应用里的记录和外面的消息一样可以接成来源。
3. 每日复盘时，便签里搁了三天以上还只是猜测的必须当天了结：去印证、定时间问用户，或者删掉。
4. 复盘时看到的东西除了记下事实，还要用一两句自己的话写下它们放在一起说明了什么，分清印证过的和猜的。
5. 在用户的地方看到的东西和他眼下的事接得上时，是开口的由头。
6. 足迹多认一种：命令行每一段开头的"程序 子命令"。

## 已知限制

- 命令行的认法是按形状猜的，会混进一些只是查看本机状态的命令；它只影响"去过哪"的清单，不影响别的判断。
- 接成来源靠它自己判断哪处值得接。接多了事件变多，由每日复盘里已有的"猜着加的来源到期不续"收。
- 登录失效时来源会断，靠脚本自己交一条事件；它没这样写的话仍会悄悄断掉。
- 开口的由头变多，主动消息可能变多。
