# 0095 · 请求摘要按已结算工具批次切分

- 状态：accepted
- 日期：2026-10-06
- 关联条款：CTX-001、CTX-003、CTX-007、MEM-011、MEM-012
- 部分 supersedes：0030、0052、0068 的整 Turn 请求切点与 20K 最低保留量；原数据、插件 owner 和单窗口摘要合同不变。

## 背景

一次长调查可以包含几十个工具批次，最后才提交完成 Output。随后只有一条很短的新输入。
整 Turn 不可拆分与至少保留 20K 原文同时成立时，保留旧 Turn 无法压缩，摘要整个旧 Turn
又不足 20K 尾部。模型窗口配置正确也会遇到“没有合法摘要切点”。
维护者已授权按 Pi / DSH 的安全批次边界调整，并要求压缩失败原因对用户可见。

## 决定

1. 模型请求视图允许在已结算或明确放弃的工具批次后切分，包括已完成 Turn 内部。
   切点不能跨未结算调用；当前工作 Input 仍由模型投影的保留输入集合逐字提供。
   Turn 归属、原 Message、工具回执和学习资格保持不变。
2. 20K 是近期原文目标。优先保留达到目标的尾部；没有满足容量的切点时，允许保留更短
   尾部，并显示实际估算。system、工具 schema、当前输入和输出预留一并参与容量判断。
3. 每代仍只生成一个成功摘要。首次覆盖从日志起点开始；摘要模型只取得可容纳的最大
   连续近期窗口，更早退出请求的消息记为 omitted，不冒充已经摘要或可学习的资料。
4. 74% 只触发压缩。压缩后的真实完整输入必须减少且满足硬容量，允许仍高于软水位。
   摘要的可恢复错误只在原请求满足硬容量且不是强制缩减时允许继续。provider 明确容量
   拒绝和本地硬容量失败仍阻断；取消、损坏、CAS 和内部契约错误不降级。
5. 压缩状态复用 Reply 预览。降级、fallback 与减少保留量的说明随请求材料冻结，并作为
   `context.notice` 追加到真正提交的 Output；历史、实时显示和复制均可读。诊断不进入
   provider 输入、模型 replay 或摘要材料，不成为模型指令。
   `SummaryReducer` 增加可选 `on_status` 回调；自定义摘要 owner 须接收该参数。
6. Markdown 继续按完整 Turn 学习。累计覆盖只到 Turn 中间时先不学习该 Turn。即使同一
   generation 已应用更早的完整 Turn，延后的尾部仍保持资格；后续覆盖到结束边界时，
   追溯父链补齐该 Turn 的真实摘要输入，不重复学习先前已经完整应用的 Turn。

```text
完整 Message 日志 ──只读──┬── 已结算批次 → 一份摘要 + 近期原文 → 模型请求
                         └── 完整 Turn → Markdown 学习
```

## 理由与代价

工具配对是 provider 协议的必要边界；完整 Turn 是工作归属和学习边界。二者使用同一
切点会让长任务无法继续。增大窗口或重试无法解决这个约束冲突。
不采用无条件继续：硬容量失败仍会产生明确错误。不在本次引入后台摘要任务，避免新增
并发发布 owner。摘要仍有损，关键工作进展由既有摘要 Prompt 保留，原文始终可读取。

## 状态与恢复

Message 正常只追加；本次无既有消息原位更新、逻辑失效或物理减少。摘要 owner 只新增
不可变 v2 记录，以现有事务和 parent CAS 推进 head；旧摘要与调用账保留。没有 schema
迁移或自动删除。诊断随原生成准备恢复，不要求重跑摘要。源码基线由 Git 保留。

## 验收

隔离安装真实回复插件，以本地 HTTP 对端检查已完成长 Turn、开放长 Turn、短尾部、
软水位摘要失败继续与硬容量阻断。核对当前输入、工具配对、精确摘要来源，以及所有
既有 Message 行的完整字节、身份和顺序；跨代学习须补齐延后的尾部。显示端须提供
可见诊断且不回送模型。
