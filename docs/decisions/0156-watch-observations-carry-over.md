# 0156 值班：看到的和走过的路留进记忆专题，收尾并进已有回合

状态：proposed / implemented for review
关联条款：PRO-004～PRO-006

## 背景

0154 之后主 Agent 会自己去看、自己接着看，但看过的东西留不下来：

- 用户让它去一个地方查数。它撞到一道过不去的验证，上网查了绕法，最后只把查到的数写进记忆。那道墙、绕法、用户问了却没答上的问题都没有留下，下一次还是从头摸、再撞一次。
- 它替用户经手一件事（放进待买、约好之后接着做），对话结束后没有任何后续安排；用户自己把事办完了，它不知道。
- 便签只有后台回合读得到。它在后台看到的东西写进便签，用户在主对话里问起时用不上。
- 待看里和用户正在做的事直接相关的条目，因为嘱托写着"他提到才说"被整批放下；它把"没看到"记成了"他不在意"。

## 决定

1. **观察写进记忆专题，不写便签。** 记忆专题的目录每一轮（主对话和后台）都带着，是唯一两边都读得到的地方。后台提示写明：想让以后每一轮都用得上的东西写进专题；去一个地方之前先看专题里有没有走过，去过之后补上路怎么走通、卡在哪、缺什么、有没有别的路、看到了什么、是哪天。
2. **主对话只读不写。** 聊天提示只加一句：他问的事和某个专题沾边，先读再答。主对话里不要求记录，不改值班文件。
3. **收尾跟着下一个后台回合走。** 上次后台回合之后用户说过话、且已经停了半小时，这段对话就算没收尾。下一个后台回合不管因为什么醒来（事件叫醒、过一眼待看）都带上收尾这一段：经手过的事后面怎样、没答上的问题留嘱托、因会变的条件放下的东西接着看、走过的路补进专题。四小时内没有任何后台回合，就单独跑一次；每日复盘兜底。一次集中提问最多多出一个回合，和问了多少句无关。
4. **他做的事和他说的话一样算数。** 状态和记录里看得到他在做的事，就是他在意的证据；没看到只是没看到，不记成结论。
5. **没答上是欠他的。** 留一行嘱托，等缺的东西有了回来答。

提示词只讲道理，不举具体的应用或场景，不规定记录格式。

## 依据

三套评测，被测模型与线上不同，只比较同一模型下前后两版；分数见 PR 描述。

- 两段式场景（16 个，各 3 遍）：每段是全新会话，上一段只剩它写下的文件、来源和定时任务，看留下的东西有没有改变下一次的行为。
- 0154 的能动性场景做回归。
- 多日回放：真实事件流和对话上叠一层用户没说出口的生活（浏览记录、收藏、屏幕、账户、订单，逐日变化），几天后在全新对话里问平常的话，同时数主 Agent 的调用次数。

评测脚本和素材留在私有仓库和本机，不进本仓库。

## 已知限制

- 多日回放的目标分两版在噪声范围内（每版两次），差别在留下的专题数量和回答时不用重新去找；它不证明回答更准。
- "过一眼"回合的步数约为原来的 1.5 倍；多日回放里总调用次数多约一成。
- 专题会变多。靠每日复盘合并和清理，没有硬上限。
- 一处地方它从没想到去看，就不会有记录；提示词只给了方向，不保证覆盖。
- 主对话里不写记录，所以对话里走过的路要等到下一次"过一眼"或复盘才进专题；这之间再问一次仍会重走。

## 勘误（2026-11-14）

最初的第 3 条只把收尾挂在"过一眼待看"和每日复盘上，调度代码不变。上线后八个半小时里这两种回合一次都没跑：值班员把大部分事件判为只记录，待看没有新条目，"过一眼"就不触发；期间两次事件叫醒不带收尾。前一晚替用户放进待买、答应到货后迁移的那段对话因此没有任何后续安排。多日回放没暴露这一点，因为回放里待看一直有新条目。现改为上面的写法。
