# 0110 · Ledger 检查沿用现有消息语义

- 状态：proposed / implemented for review
- 日期：2026-10-11
- 依据：#1179 P2e；用户授权自主决定，重大决定独立 PR。

Issue 的“Turn 开闭配对、uncertain 回执”不对应当前数据模型。Turn 是
`turn_projection` 从消息前缀计算的引用；Scheduler 等来源可以只产生 Output。
Delivery 的未知外部效果以 `started` 表示，非幂等且无可查询回执时记录明确的
失败及“可能已送达”，不静默成功。工具结果的未知以 `interrupted` 表示；旧
`unknown` 只属于历史解码。这些合同不因账本迁出 Core 而改写。

┌──────────────────────┐    ┌─────────────────────────────┐
│ Ledger 事务中的新消息 │───►│ ledger_invariants 同步检查   │
└───────────┬──────────┘    │ 只读同事务前缀，不持有 SQL  │
            │               └─────────────┬───────────────┘
            │                   通过 / 抛错
            ▼                             │
┌──────────────────────┐                  │
│ 同事务提交或整体回滚 │◄─────────────────┘
└──────────────────────┘

配套插件默认启用，检查 seq 严格递增、abandon 不重复关闭
已结束前缀。它不新建 Turn 表，也不要求每个 Output 前必须有 Input。Ledger
提供窄 `ledger.append_checks.v1` 注册能力，调用在新消息写入前；异常回滚整个
owner transaction。重放已提交消息不再次检查。回调同步且无外部效果，撤回等待
正在执行的检查结束；禁用检查插件不卸载 Ledger 或改写历史。

每个不变量只有一个 owner：Control 不指向未来由 Message 构造函数校验；引用、结果唯一性与幂等身份由 Ledger 持续校验，
Delivery 独占发送恢复和成功回执判定；检查插件不复制这两套规则。未知结果不能
被成功覆盖已有 Ledger 身份，未知发送也不能由内存恢复冒充已送达。相关行为由
既有真实恢复场景验收，而非添加一个重复的可变状态机。

新增检查会使以前能写入但投影不能读取的重复 abandon 在提交点失败；事务内
消息及 owner_state 一起回滚。该行为变化特意独立提交供评审，未迁移正式数据。
