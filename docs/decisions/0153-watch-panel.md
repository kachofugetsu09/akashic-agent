# 0153 值班面板：从已有记录现读，只认识来源和事件

状态：proposed / implemented for review
关联条款：PRO-005

## 背景

值班员的每次判断和主 Agent 的每个后台回合都有记录（`watch/log/`、`watch/events/`、后台会话），但只能去服务器上翻文件。用户看不到它一天里看见了什么、为什么这样判、被叫醒后做了哪几步，也就没法发现它给自己定了不合适的规矩。

## 决定

1. 面板挂在侧栏已有的“插件面板”里（`sidebar.panels`），不进主对话、不加新的导航入口。小浮层给当天的一句话和最近几件事，展开后是完整的一天。
2. 展开后的“动线”页：上面是一天的时间轴，每个报过状态的来源一行，一段是相邻两条状态事件之间的时间，文字是事件原文；再加对话一行和值班一行。点值班的一轮，下面三栏依次是值班员当时手里各来源的最近状态、这一轮新进来的事件和去向与理由、主 Agent 的工具调用和它最后写下的话。
3. 界面不认识任何一种具体的状态：没有“睡眠”“位置”这样的固定栏目，多一个来源就多一行。
4. 后端不新增存储：`day` 查询解析当天的值班日志、读事件文件和主对话，`round` 查询读一个值班自己的后台会话。另外三页原样显示 `WATCH.md`、`notes.md`、`inbox.md`。

## 已知限制

- 只读。想改它的规矩，仍然是在对话里告诉它或直接改文件。
- 值班员当时拿到的嘱托、最近对话和记忆没有逐轮留存，第一栏只有各来源的状态。
- 一轮的归拢靠日志行的时分，同一分钟内的两轮会并在一起。
- 值班日志只保留十四天，更早的日期是空的。
