# 0153 值班面板：从已有记录现读，只认识来源和事件

状态：proposed / implemented for review
关联条款：PRO-005

## 背景

值班员的每次判断和主 Agent 的每个后台回合都有记录（`watch/log/`、`watch/events/`、后台会话），但只能去服务器上翻文件。用户看不到它一天里看见了什么、为什么这样判、被叫醒后做了哪几步，也就没法发现它给自己定了不合适的规矩。

## 决定

1. 面板挂在侧栏已有的“插件面板”里（`sidebar.panels`），不进主对话、不加新的导航入口。小浮层给当天的一句话和最近几件事，展开后是完整的一天。
2. 展开后的“这一天”页从上到下四块，每块的标题就是它回答的问题：**主 Agent 做了什么**——每日复盘和每次被叫醒各一行，行上直接是它收尾时写的交代，点开是全文、它改了记忆的哪几行、当时各来源报告的状态和一步一步的工具调用；**各来源什么时候来了事**——每个来源一行、同一条 24 小时横轴，竖线落在事件被判断的时刻，只记录的短而淡、进待看的中等、叫醒的最高最深，点一行就只看这个来源；**事件和值班员的判断**——新的在上，默认只留进了待看和叫醒了的，以及用户与它之间的对话，点一条看值班员的理由；**用量**放在最后。
3. 界面不认识任何一种具体的来源：没有“睡眠”“位置”这样的固定栏目，也不区分“报状态的来源”和“只来事件的来源”。订阅、邮件、脚本、到点查看和状态来源画法完全一样，多一个来源就多一行；行的先后只按当天要紧的事多少排。
4. 后端不新增存储：`day` 查询解析当天的值班日志（含值班员记录的 `值班模型` 用量）、读事件文件和主对话，并通过 `models.call-stats.v1` 现查每个唤醒会话里模型调用的真实模型与用量；`round` 查询读一个值班自己的后台会话与用量。另外三页原样显示 `WATCH.md`、`notes.md`、`inbox.md`。

## 已知限制

- 只读。想改它的规矩，仍然是在对话里告诉它或直接改文件。
- 值班员当时拿到的嘱托、最近对话和记忆没有逐轮留存，回合里只有各来源当时的状态。
- 复盘改了嘱托、便签和地点的哪几行没有逐行留痕（只有记忆有），要看它收尾的交代。
- 条带上竖线的位置是值班员判断的时刻，比事件真正到来最多晚一个值班间隔。
- 一轮的归拢靠日志行的时分，同一分钟内的两轮会并在一起。
- 值班日志只保留十四天，更早的日期是空的。
