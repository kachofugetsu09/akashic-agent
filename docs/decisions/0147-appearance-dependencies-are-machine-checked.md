# 0147 · 外观依赖由静态检查守护

- 状态：accepted / implemented for review
- 日期：2026-11-09
- 关联条款：WEBUI-007、PLG-001
- 细化：[0143](0143-radius-joins-the-brand-contract.md)。0143 把其它插件的圆角留到“改到时再迁”，本决定一次迁完并加检查。

## 背景

风格切换（配色之外再换形状、字体）的前提是插件不自己决定外观。对生产环境实际加载的样式表和源码统计后发现：

- 95 处裸圆角，其中 78 处正好在刻度上，只是没有引用 token。
- 27 处带模糊的投影各写各的，不少基于墨色；深色主题的墨色是浅色，投影变成浅色光晕，违反 design.md。
- 6 个公开 token 没有定义，靠回退值撑着。`--ak-color-action-on-primary` 把名字写反了，深色下主按钮的文字一直是白色；`--ak-accent-primary` 回退到写死的蓝色，不跟随配色。
- 插件和宿主的依赖没有约束：`models` 占用了 `--ak-pop-origin`，还引用了不存在的 `--shell-band-height`；`product-band.css` 放在 theme 里，却读 `shell_ui` 写入的变量。

## 决定

1. 公开 token 新增高度轴：`--ak-elevation-raised`、`--ak-elevation-float`，与已有的 `--ak-elevation-overlay` 一起都基于 `--ak-color-shadow`。
2. 外观依赖只有一个方向：变量只能解析到自己或宿主。插件之间不共享私有变量，宿主不依赖插件。`--ak-*`、`--md-*`、`--chat-*` 归宿主。
3. `scripts/check_css_tokens.mjs` 做静态检查并进 CI，规则写在 design.md 2.2。它只按目录判断 owner，不写任何插件名。例外要在声明前写明理由。
4. 不禁止公开 token 的回退值，只检查 token 是否存在。这样已有约 150 处回退值不用改，也能抓到真正的问题。

## 理由

有 N 种风格、M 个插件时，只要中间隔一层公开 token，工作量就是 N+M，否则是 N×M。这与插件正交的方向一致：插件只依赖宿主发布的合同，不依赖兄弟插件。

外部的做法也一致：Atlassian、Firefox、Obsidian 都是公开 token 加机器检查。

检查是脚本而不是单元测试，符合 TST-001。

## 影响与回滚

- 默认外观有少量可见变化：
  - 不在刻度上的圆角有 17 处，其中 15 处贴到刻度：6/7px → 8px，5px → 4px，差 1–2px。贴着父级角的另外 2 处（主题菜单的明暗分段、设计编辑器的视图分段）用 `calc(sm - 2px)`，仍是 6px。
  - 小于 4px 的圆角不动。
  - 投影统一到三档，透明度和偏移有变化。最明显的是选区“引用”胶囊：从 `0 2px 8px` 变为 `0 8px 24px`。
  - 深色主题：浮层不再有浅色光晕，投影接近看不见，层次靠描边和表面色；工作区改动的主按钮文字不再固定为白色；隐私打码的激活色跟随配色。
- 不涉及数据、协议和插件 API。回滚还原 CSS、脚本和文档即可。

## 已知限制

- `product-band.css` 归属不对，应迁入 `shell_ui`；迁移涉及 `@scope` 与层叠顺序，这里先写明豁免。
- `models` 的设置弹窗写死了 48px，隐含了 `shell_ui` 的顶栏高度；换成 `--band-height` 会改变窄屏位置，另行处理。
- `models`、`privacy_mask` 的选择器伸进了宿主结构（`.chat-main`、`.composer-wrap`、会话行等），检查不覆盖选择器。
- 外置插件的仓库不跑这个检查，比如 `status_commands` 仍引用已不存在的 `--m-shape-*`。
- 裸颜色、裸字号和 JS 内联样式不在本次范围内。

## 验收

- 迁移前检查报错，迁移后通过；故意制造每一类违规都会被拦下，理由为空的豁免也被拒绝。
- 固定 Chromium 下对比改前改后的截图，浅色、深色、桌面、窄屏。
- 隔离实例里真实发送一条消息，模型调用工具并回答完。
