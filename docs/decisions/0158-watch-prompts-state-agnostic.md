# 0158 值班：提示词不认识具体状态，叫醒之后有自己的时间

状态：proposed / implemented for review
关联条款：PRO-004～PRO-006

## 背景

线上两天的记录里，不请自来地去了解用户只发生在每日复盘（凌晨）。事件叫醒只办被叫醒的那件事，办完就结束；而它是唯一发生在用户醒着、且知道他此刻状态的后台回合。

同时，值班的四份提示词里到处写着具体的状态和来源："他睡着了、正在玩""他下班、到家、起床、打完游戏""带他登录态的浏览器、他的手机"。这有两个后果：

- 没写到的状态不适用。状态是来源报上来的，来源会增减，提示词不可能列全。
- "此刻不合适说"被写成了"此刻不合适做"。后台做的事用户察觉不到，本来不受他的状态约束。

## 决定

1. **做事和说话分开。** 后台做的事什么时候都可以做；会到用户面前的只有消息，发之前看他此刻的状态，自己判断这条消息现在出现是不是打断他。提示词只给这条原则，不出现任何具体状态、来源或工具的名字。状态的含义由来源报上来的那一行自己带着。
2. **事件叫醒之后有自己的时间。** 该办的办完之后，像一个醒着的人那样自己挑一件事去做：顺着这件事或他眼下的状态去看、替他先备好接下来用得上的、印证搁着的猜测，看到的写进记忆专题。约束：先办正事；只做一件，看两三处没有就停；会花钱或以他的名义对外说话的事只备到差他点头。不新增回合。
3. **开口的规矩由它自己定，写在嘱托的「留意」一节。** 它从用户的状态和他对消息的反应里摸出来的规矩（处在什么状态时哪类话可以说、哪类留着）写在 `WATCH.md` 的「留意」，带依据和到期日；依据的事实写进记忆。放在嘱托而不是记忆里，是因为值班员和后台的主 Agent 每次都读它、它有到期机制、用户看得到也改得了，而且不占每一轮聊天的上下文。
4. **技能说明里讲文件格式的例子保留**（地点文件、抓取脚本），带判断的句子按第 1 条改。

## 依据

两段式评测新增十个场景回合（事件叫醒五个、自定规矩两个，各含留出场景；其中"驾驶中""会议中"两种状态从未出现在提示词里），分数见 PR 描述。被测模型与线上不同，只比较同一模型下前后几版。

## 已知限制

- 事件叫醒的步数约为原来的两倍（评测里约 11 步到约 20 步）。线上事件叫醒一天一到三次。
- 它常常不止看一处；"只做一件"压住了一部分，没有完全压住。
- 多数时候是去看，很少真的替用户备好东西；评测里也没有可备的东西。
- 它自己定的规矩可能是错的。靠到期日和用户一句话纠正，没有别的校验。
- 去掉例子之后，判断全靠模型读状态那一行；状态行写得含糊，判断就会含糊。
