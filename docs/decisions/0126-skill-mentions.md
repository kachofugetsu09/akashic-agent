# 0126 · 输入里的 /技能名 是本轮的显式技能选择

- 状态：proposed / implemented for review
- 日期：2026-10-18
- 先例：Codex 的 `$`/`@` 技能提及、Claude Desktop 的 `/` 菜单。

## 决定与理由

用户想用某个技能时，原先只能等模型自己判断是否 `load_skill`。现在用户在输入里点名，本轮直接生效。

1. **语法即合同。** 行首或空白后的 `/` 接技能目录里的已知名称，名称后是结尾、空白或标点；
   同一位置取最长名称（`/foo bar` 优先于 `/foo`）。代码块与行内代码里的不算。前端菜单、
   消息气泡与服务端用同一规则，QQ、Telegram 手打同样生效，不需要给 Input 增加新字段。
2. **注入位置。** `standard_tools` 技能材料在本来源最新的 Input 中识别提及，把技能正文作为
   可回放 reminder 并入当轮；后续轮次在历史中仍能看到这次选择。不可用或正文为空时只注入
   原因，不声称已加载。
3. **前端。** `/` 或 `@` 打开菜单，选中后写入 `/名称 `；每次打开菜单重新读取
   `/api/chat/runtime/capabilities` 的技能目录。

## 已知限制

- 与命令同名的技能放在消息开头时按命令执行（命令先于回复）；放在句中即可作为技能提及。
  目前内置技能与命令没有重名，不为此在 Input 中另建技能选择身份。
- 输入框里的 `/名称` 不着色，只在发出的消息里显示为提及。
- 模型仍可能再调用 `load_skill`，届时正文会重复出现一次。
