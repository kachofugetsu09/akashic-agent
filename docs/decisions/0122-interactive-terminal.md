# 0122 · 工作台终端是用户自己的交互 shell

- 状态：proposed / implemented for review
- 日期：2026-10-16
- 修订：0121（PR #1420，工作台标签）中“终端 = Agent shell 命令回放”的切片
- 关联：WEBUI-008、PLG-016、GOV-004

维护者要求工作台的终端用起来像 kitty：用户在侧栏里自己敲命令，不是查看 Agent 跑过的命令。
因此终端改为执行主机上的长期 PTY 会话；Agent 的命令仍由对话里的工具卡展示，不再单独记录一份。

```text
┌───────────────┐  WebSocket   ┌──────────────┐  host.terminals.v1  ┌──────────────────┐
│ 终端标签       │─────────────▶│ terminal 插件 │────────────────────▶│ host_execution    │
│ xterm.js       │ 输入/尺寸/输出│ 会话 → 终端   │ open/write/resize/  │ PTY + 环形缓冲     │
└───────────────┘              └──────────────┘ read/close/list     │ 本机或 Host Bridge │
                                                                     └──────────────────┘
```

## 决定

- **执行主机拥有 PTY。** `host.terminals.v1` 与 `host.processes.v1` 共用同一个 manager、关闭排空和
  owner 隔离；终端运行在 Agent 命令所在的同一台机器上（本机模式或 Host Bridge 宿主）。
- **shell 由执行主机选。** 用用户自己的登录 shell（`$SHELL` → passwd → Agent shell 默认），
  `TERM=xterm-256color`、`COLORTERM=truecolor`；shell 经 `login_tty` 取得控制终端，作业控制和
  Ctrl+C 与普通终端一致。调用方只给工作目录和尺寸，不传环境变量。
- **输出按偏移读，读了不删。** 每个终端保留最近 256 KiB；读取在没有新输出时等待，长轮询即可实时回显，
  Host Bridge 不需要流式传输。断线重连从缓冲开头回放；偏移大于请求值表示更早的输出已滚出。
- **不设硬超时，终端与 shell 同生同死。** shell 由一个监管进程（`pty_supervisor.py`）启动，
  监管进程是服务端唯一直接发信号的对象。shell 退出后监管进程先不回收它：未回收的 shell 占着自己的
  PID，会话号就不会被复用，这时按会话号（Linux `/proc`，pidfd 固定身份后再核对）找到的进程一定属于
  这个终端，包括转入后台进程组、忽略 SIGHUP 的作业；挂断后宽限 2 秒强制结束，然后才回收 shell 并带着
  shell 的退出码退出。关闭等同关掉窗口：服务端向监管进程发 SIGTERM，监管进程按同样的步骤挂断整个会话；
  它不响应时服务端结束它，主端关闭后内核也会挂断会话。服务端从不按旧 PID 数字发信号。
- **关闭做完才算数。** 关闭是终端自己的任务：调用方被取消也会继续；完成前终端留在登记表里（不再列出、
  不接受读写），shutdown 与 owner 清理会等待它；失败时恢复为可列出、可再关的终端。同一终端的写入串行进行，
  多个浏览器同时输入不会互相覆盖。输入缓冲写满后会话挂断时主端写入只报 EAGAIN、不报 EIO，所以在途写入与
  “会话结束”竞争，结束或开始关闭时取消写入、撤下 fd 回调，持写锁后才释放主端，同号 fd 不会收到旧回调。
  shell 启动前还原 Python 忽略的 SIGPIPE、SIGXFSZ，`yes | head` 这类管道照常静默结束。owner 清理和 generation 关闭会关闭其全部终端。每个 owner 最多 8 个，
  全局 32 个，已退出未关闭的也计数。
- **Agent 不读用户终端。** 不提供读取终端的模型工具；终端是用户的，不进入上下文。
- **一个工作台标签一个终端。** 终端是可多开的工作台工具，每个实例对应一个 PTY，属于创建它的会话。实例与终端的对应按会话
  记在浏览器的 sessionStorage；认领时剪掉已关标签（不在 `view.instances` 里）和已不存在的终端，剩下没人认领、还在运行的
  终端交给新开的实例接管，而不是另开一个。用户关闭标签即关闭 PTY；换会话只卸下标签，PTY 留着，回来接着用。

## 信任边界

交互终端等同于让已登录的 Web 用户在执行主机上执行任意命令。这与 Agent 已有的 shell 能力处于同一信任级别，
但入口变成了浏览器。因此终端只经已登录的 Dashboard 路由暴露，沿用宿主的浏览器请求约束；停用 terminal
插件即整体关闭这一入口，host_execution 本身不暴露 HTTP。

## 已知限制

- 应用重启或 host_execution 换代后终端不保留（与 Agent 后台进程相同）。
- 截断回放可能从全屏程序（vim、htop）中途开始，首屏可能错位；按一次重绘键即可恢复。
- Windows 执行主机暂不支持（需要 ConPTY）。没有 `waitid` 或 `sigwaitinfo` 的 Unix（如 macOS）上监管进程退化为直接成为
  shell，只能挂断 shell 的进程组，转入后台进程组的作业可能残留。
- `nohup` 之类忽略挂断的进程会在宽限后被结束；需要跨终端存活的进程应 `setsid` 脱离会话或交给 Agent 后台任务。
- 浏览器端没有渲染背压：输出远快于渲染时（例如 `cat` 巨大文件）只能靠服务端每次 64 KiB 的读取节奏，
  xterm 的写入队列在极端情况下可能丢弃数据；需要时再按 xterm 的 flow control 指南加确认。
- 手机上没有 Esc / Tab / Ctrl 辅助键行。
- 两个浏览器标签页打开同一会话时，各自的认领记录互不可见：一边新开终端可能接管另一边正在用的终端，两边共享输入输出。
