# 0077 · 信任已安装的运行材料

- 状态：accepted
- 日期：2026-09-28
- 关联：PLG-001、PLG-002、PLG-009、ERR-001
- 修订：第 07 层固定 Python 环境的运行时摘要复验合同

## 背景

hua-home 在每日备份后重启 Core。Fitbit 的环境打开同步计算源码、requirements、
基础解释器和环境树摘要，耗时 11.020 秒；同一事件循环上的 Web 启动出现 11.231 秒
调度空档，超过监听期限。环境扫描读取约 250 MiB、5,310 个文件。

维护者明确要求采用乐观读取，删除 SHA 等复验，参照 DeepSeek Harness 简化流程。
参考源码固定为 `deepseek-ai/deepseek-harness@477b4f420553e8a52c2fbccc464d7561b239c443`：

- `packages/boot/plugin-manager/src/operations.ts`：安装交给 pnpm 子进程。
- `packages/boot/app-boot/src/profile.ts`：启动读取包元数据，构建固定解析表。
- `packages/mcp/mcp-client/src/index.ts`：资源等待自己的连接和工具发现完成。

这些路径没有在每次使用时递归核验所有依赖文件。实验 Python provider 仍有一次
带期限的同步版本探测，本项目不照搬该探测。

## 决定

运行时读取合同由 PLG-002 拥有。安装准备、归档命名与普通使用分开：

```text
┌─────────────────────────────┐
│ 安装：准备代码、依赖与固定引用 │
└──────────────┬──────────────┘
               ▼
┌─────────────────────────────┐
│ 运行：读取引用 → 使用目录     │
└──────────────┬──────────────┘
               ▼
┌─────────────────────────────┐
│ 资源 owner：spawn / 协议握手 │
└─────────────────────────────┘
```

删除 `PluginArchive` 读取时的 descriptor、索引与文件树摘要复验，以及
`PythonEnvironments` 的源码、requirements、环境树和基础解释器复验。
源码复制后的摘要只命名实际复制出的制品，不再与复制前的摘要比较。
新归档不再写只服务摘要复验的 `index.json`；已有索引保留。
不增加线程校验、verified cache、后台扫描或校验开关。

`PluginArchive` 同时服务代码与 Skill 文件归档；两者统一信任已发布目录。
Skill 只保存文件树引用，不再保存、比较或输出正文摘要；读取旧 binding 时仅在
反序列化边界忽略其 `body_sha256`，原记录不改写。
引用结构、路径范围与实际读取错误继续由现有 owner 处理。
下载的离线 wheel 输入校验属于发行安装边界，保留原协议，不进入普通读取路径。

## 影响与恢复

已发布目录仍由安装 owner 写入。读取不新增目录、不安装依赖、不改写引用。
目录或解释器缺失、非法引用、JSON 结构错误、import、spawn 和握手失败明确返回。
已安装文件的原位字节变化不再因为摘要不匹配被提前拒绝；实际执行使用目录中的材料。

环境 descriptor 版本仍为 1；读取只使用版本和相对 UUID。新记录停止增加无消费者的
环境树和基础解释器摘要；旧记录不迁移、不改写、不删除。安装输入仍固定代码引用、
解释器路径、runtime root 与可选离线 wheel 输入。新安装按新输入准备环境，旧选择
继续使用原目录。已发布环境、归档、消息、binding 与 plugin-data 没有新的减少路径。

代码回退可恢复原读取实现，但新制品不满足旧读取合同：新归档没有索引，新环境
descriptor 没有旧验收字段，新 Skill binding 没有正文摘要。回退须使用升级前的
workspace 备份；已有新消息或 binding 时不能覆盖新事实，须单独制定转换方案。
仅回退源码或重装插件不能恢复新 Skill binding 的旧合同。

## 验收

- 对旧、新环境 descriptor 使用同一读取路径，直接启动真实 Python 进程。
- 在禁止摘要计算、全树扫描和解释器探测的条件下，实际命令解析与环境读取成功。
- 冷启动固定 generation 与旧、新 Skill binding 沿同一乐观读取路径恢复。
- 所需目录、解释器或 descriptor 缺失以及非法路径仍明确失败。
- 现有概念基线与静态检查通过；正式 hua-home 发布与客户端验收单独进行。
