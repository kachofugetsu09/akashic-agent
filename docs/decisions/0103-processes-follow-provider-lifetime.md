# 0103 · 进程集合随提供方生命周期关闭

- 状态：accepted
- 日期：2026-10-11
- 依据：Issue 1179 P2d、ADR-0102；维护者授权自主推进并将重大决定单独交付评审。

## 决定

HostExecution 提供 `host.processes.v1`，由自身 Effect 拥有实际进程集合。
更新、停用或卸载该 provider 时，先排空消费者，再终止并确认其进程退出。
清理失败保留实际 manager、失败明细和 Effect，由原关闭 owner 重试。

这是明确的生命周期变化：旧实现把进程保留到整个 PluginManager 退出；新实现
不会让旧 HostExecution 的后台进程跨 provider 换代。旧执行 ID 在换代后失效，
未知外部效果不会被自动重跑。取消一次等待仍只取消等待，进程可在本代继续续接。
普通 standard_tools 换代没有撤下 HostExecution 时，仍沿原稳定 owner key 接续。

```text
┌──────────────────────┐     ┌───────────────────────────┐
│ standard_tools 调用  ├────►│ HostExecution / processes │
└──────────────────────┘     └─────────────┬─────────────┘
                                          ▼
                            ┌───────────────────────────┐
                            │ Effect 排空 → 确认进程退出 │
                            └───────────────────────────┘
```

## 理由与代价

保留宿主全局进程池会让插件移除后仍留下原实现和资源 owner，因此不采用。
跨代转交现有进程需要第二套交接协议，也不能证明旧代码已排空，因此不新增。
代价是更新 HostExecution 会终止其仍运行的后台命令；更新其他无关插件不受影响。
若未来确需跨代进程存活，应先制定独立进程 owner 的交接与失败协议再重议。

进程清理不拥有消息、回执、配置或业务库的写权限。现有进程日志回收规则不变。
源码恢复点是父提交；回退代码不能恢复已经终止的外部进程或撤销其副作用。

## 验收

`host_process_plugin_scenario.py` 使用真实安装、Root 和子进程验证取消、provider
换代、卸载与同 workspace 重启，核对旧 PID 不存在及旁支 Fiber 身份保持。
既有进程隔离测试继续核对单 owner 清理不会阻塞其他 owner。
