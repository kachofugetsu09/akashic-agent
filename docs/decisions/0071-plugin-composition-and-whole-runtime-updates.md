## 决定与理由

插件决定怎样做事，底座决定怎样组成系统。更新是低频事件，允许暂停接纳和完整重建，
不为局部无停顿换代维护增量 Root、Overlay 或跨代运行实例共享。

底座拥有入口加载、挂载树、服务依赖与选择、作用域、装配合法性、整体换代以及唯一 stable 提交点。
插件拥有配置解释、业务检查和持久数据；资源 provider 拥有资源的实际操作。
唯一入口为 `apply(ctx)`；`ctx.config` 提供当前组合固定的配置输入。插件自行解析和校验，
底座不寻找 `Config` 导出或实例化插件配置模型。凭据引用与授权仍由宿主边界控制。
删除插件专用 TOML、重复身份与运行描述。所有能力通过插件代码注册和调用，
底座不枚举 MCP、Workload、Channel、UI 等能力，不建立新的通用业务规格表。

硬依赖同时约束初始化顺序：提供者可用后才初始化消费者。缺依赖、冲突、依赖环或初始化失败
明确拒绝。发布后固定插件与服务绑定，组合变化统一经过下一次整体换代；连接重试等内部变化归插件。
不增加 before/after、priority 或第二套启动排序协议。

## 启停与归属

初始化建立资源但不接纳正式工作。统一接纳控制约束外部入口和主动工作来源；普通计算和存储插件
不承担接纳策略。更新先关闭来源接纳，再等待已有工作退出，再按依赖逆序关闭插件及资源。
消费者未关闭时保留它退出所需的 provider；无关分支继续清理。失败资源句柄留在原 owner，
确认关闭后才解除归属。并发关闭等待同一次操作，资源重试由 provider 保证，不重放业务效果。
跨进程残留由进程宿主或 Controller 管理；无法退出的同进程任务不能被假报为热更新成功。

更新调用必须有有限截止时间。提交前排空超时或更新被取消时，撤销本次提交权，stable 不变；
若尚未释放旧资源，则恢复旧来源接纳，已有工作继续持有旧绑定。若已进入资源释放或新实例启动，
不得直接重开旧接纳；真实恢复完成后才开放，否则保持停止接纳并报告需要宿主重启或维护者处理。
截止时间不允许遗弃正在关闭的资源，也不允许自动重放更新或业务效果。
取消不配合的异步任务仍归原操作所有，迟到成功不能重新取得提交权；新更新不能越过它。
同步 import、同步文件刷盘或阻塞事件循环的插件不能靠异步超时强制中断，硬截止归外部宿主。
耐久提交成功后的取消不撤销该提交；报告已提交及尚未完成的运行恢复。
指针写入结果不确定时保持停止接纳，保留写入和资源证据，不回写旧值冒充回滚成功。

## 提交与数据

候选和正式实例使用同一固定制品及装配输入，但不互换数据目录或运行身份。
候选在独立环境接受检查；被 revert、取消、异常结束或未获所属更新的提交授权时 stable 不变。
更新来源指发起更新的调用程序（包括 Agent 插件和 operator 入口），拥有检查流程与所属工作的正常终态判断；底座校验提交对应当前候选和基线，
不解释 attached child 的业务测试。候选验证实例关闭后，正式切换才开始排空旧组合。

Agent 更新采用 PLG-013 的普通 programmatic 调用及默认晋升规则，而非专用裁决 Agent。
升级发起者能够观察这次调用并撤销晋升；正常完成仅生成提交请求，实际提交仍由底座执行。
这将普通执行、升级授权和资源换代分开，不让读取 latest 或模型回答中的批准文字直接改变 stable。
失败、中断、结果未知和提交前撤销都不产生晋升授权；耐久提交后的 revert 不被描述为取消成功。

安装只增加不可变制品。stable 是一份完整组合记录的唯一耐久选择；提交前死亡仍启动旧组合，
提交后死亡启动新组合，不自动续跑候选。正式新组合初始化失败时先关闭新资源，再按旧 stable 重建。
旧资源未释放时不启动冲突的新资源；恢复失败保持错误与原资源 owner 可见，不宣称恢复成功。

a′ 负责处理 a 的数据，Core 不检查兼容性。a′ 的向前兼容不代表 a 能读取 a′ 改写的数据；
stable 只保证代码和装配选择的恢复，数据迁移或回退由插件承担。候选隔离不因这一前提削弱。

## 持久状态与恢复

### 2026-09-15：普通调用沿用模型设置

维护者确认插件按可信本地代码设计。普通 latest 调用默认沿用现有模型设置和凭据，
由模型插件提供给新组合；不要求独立账号，不新增凭据审批或通用数据复制机制。
原文中的候选隔离约束资源实例、消息与正式接纳，不承诺候选永远不能取得凭据。
模型连接的接续及 token refresh 由模型 owner 负责，真实模型请求不随 revert 回滚。
这项修订不允许跨 Root 借用旧模型执行实现，也不改变 stable 的提交权或资源关闭责任。

- 制品和组合记录只增加；stable 指针只在完整提交时原子更新，旧选择保留为历史。
- 消息、回执、binding、归档与 plugin-data 的增加及原位更新仍由原 owner 协议决定。
- Scope 关闭只减少所属临时任务、连接、进程等资源，不删除插件数据。
- 本次不授权正式数据迁移、制品自动 GC 或历史记录清理，没有新增物理减少协议。
- 初始代码恢复点是 `91b09ecd` 与实施前 Git archive。旧安装格式转换只能显式执行，
  先备份再检查前后完整性；普通启动不得覆盖未知状态。

## 验收

新增外部能力不改底座；仓库内插件经正式安装链运行；依赖缺失与初始化失败明确拒绝；
接纳开放前不产生正式工作；关闭失败保留资源；revert、提交前后强杀与旧组合恢复有实际证据。
