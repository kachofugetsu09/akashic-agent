# 0092：模型生成持续恢复，工具效果按原回执处理

- 状态：accepted
- 日期：2026-10-06
- 范围：Models、Provider driver、ReAct、Reply
- 依据：维护者要求一次输入遇到故障后仍尝试输出，减少用户重复说“继续”
- 勘误：[0063](0063-execution-failures-have-terminal-results.md) 中模型失败的恢复限制；Tools 与 Delivery 合同保持有效

## 问题与选择

旧设计将“远端可能生成过响应或计费”当成禁止再次模型生成的条件。
读取超时、5xx 和已经收到片段的断流因此在第一次就停止；90 秒恢复窗口
还可能在首次长推理结束前耗尽。用户只能提交新输入，已经完成的任务却没有收尾。

模型请求只生成响应。ReAct 在得到完整、可解码响应后提交 Output，Tools
才按已提交的 CallRef 执行本地效果。恢复当前生成不会从头重放工具链。
本决定接受可能重复的模型生成费用，保留未知 usage；不推断远端未执行或未计费。
Provider 如果执行额外远端业务效果，必须按其协议分类恢复资格，不能套用本地工具假设。

参考本地 Codex `b741e480` 的 `session/turn.rs` 与 `responses_retry.rs`：
失败的采样请求局部恢复，重新带入已经记录的工具结果，并公开重连进度。
参考 dsh `477b4f4` 的 `llm-retry`：先保存重试事件再可取消等待，支持有界
和持续恢复；其 agent-loop 保存失败尝试，完整响应后才分发工具。
这里采用持续恢复暂时故障，不照搬 dsh 对每一种错误都无限重试的 always 模式。

## 行为与 owner

```text
┌───────────────┐
│ Input → ReAct │  冻结当前模型请求，保留已提交工具结果
└───────┬───────┘
        ▼
┌───────────────┐
│ Models → Driver│ 每次一个物理请求，每次单独记账
└───────┬───────┘
        ├─ 暂时失败 → 保存错误/允许时间 → 撤下失败草稿 → 可取消退避 ─┐
        │                                                        │
        ◀────────────────────────────────────────────────────────┘
        ├─ 完整响应 → ReAct 解码/提交 → Tools 原 key 执行 → 下一模型步
        └─ 永久失败或显式额度耗尽 → 来源 failure Control → 用户可见原因
```

- 默认对 timeout、transport、429、5xx、空生成持续恢复，直到成功或取消。
  Driver 的 `retryable` 描述模型请求恢复资格；`send_evidence` 只记录发送事实。
  部分响应不能授予工具执行权，也不禁止重新生成完整响应。
- 显式 `max_attempts` 优先，旧 `max_retries` 按首次加 N 次重试解释；不配置
  则没有次数上限。匿名无 key 调用仍只有一次尝试。取消传播到当前 Task，
  不在已取消的 Task 中再发请求。持久恢复资格不替代来源的授权检查。
- 本地等待约为 2、4、8、16、20 秒，带 ±10% 抖动；服务端 Retry-After
  固定为绝对允许时间并优先遵守。移除独立的 90 秒总窗口，长等待可取消。
- 回调、回执保存、内部契约、binding 与 schema 错误立即传播；凭据、额度、
  无效请求和安全拒绝不以原参数无限重试。上下文缩减继续由 ReAct 拥有。
  输出长度与 ReAct 步数上限仍是明确失败，不能伪装成正常完成。
- 确认旧 owner 死亡后，Models 将 started 孤儿结算为响应与 usage 未知，按原
  次数限制安排下一次生成。无法确认 owner 死亡时不抢跑。原已终结、没有
  next_attempt_at 的旧失败不被改写或自动复活；显式 resume 可授权新准备。
- 模型恢复沿原冻结请求与 key，不切模型、不重建 Turn、不重置显式次数。
  成功响应只回放；已完成工具不由重试循环重复执行。Tools 与 Delivery 的
  取消、查询、幂等和权限仍由各自 owner 处理。

## 持久化、取消与恢复

| 对象 | 增加与更新 | 失效、减少与恢复证据 |
|---|---|---|
| model_calls | 每次物理请求新增 started；Models 原位结算 success/error、实际已知 usage 与 next_attempt_at；已有终态不改写 | 成功只读回放；新孤儿仅在真实 owner 死亡后结算；不自动减少；调用账与 Git 基线可核对 |
| Message/ToolResult/生成准备 | 原 owner 按既有合同追加；模型恢复读取原请求与已完成结果 | 不删除旧消息，不修改原工具结果；失败草稿从未成为已提交 Output；原消息库重开核对 |
| Reply preview | 展示当前尝试及退避进度；失败或新 attempt 清空旧片段 | 只撤下内存草稿，不影响持久事实；scope 结束后释放 |

不迁移 schema，不触碰正式 workspace。回滚代码会恢复旧策略；新增调用记录
仍可读取，已完成外部效果不能因源码回退被当成撤销。

## 验收

真实 loopback HTTP、Models/Message 账本、Reply、ReAct 和 standard_tools 文件
工具验证：一次 Input → 文件写入 → 含工具参数断流 → ReadTimeout → 完整正文；
工具仅执行一次，失败片段不提交，重试请求相同，重开后原消息内容与顺序一致。
另核对超过六次仍恢复、显式次数耗尽、永久错误、空生成、取消、长 Retry-After、
回调/回执拒写及旧 owner 死亡恢复。正式网关与浏览器验收单独报告。
