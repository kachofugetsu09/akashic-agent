# 0140 · 设计工作台：Agent 和用户在同一块 open-pencil 画布上做设计，取代“网站”

- 状态：accepted / implemented for review
- 日期：2026-11-04
- 关联：0121（工作台标签）、0124（show_site，本记录取代）、0117（可视化附件）
- 修订：0124 整体退役：`show_site`、对话里的网站卡片、`/sites/frame.html` 与“网站”标签删除，已有的 `akashic.site.v1` 附件只剩普通文件下载

## 背景

0124 让 Agent 把 workspace 里的网页发到工作台“网站”标签。网页只能看、不能改：Agent 改一次要重新写文件、再发一次；
用户想挪一个按钮，只能用文字描述给 Agent。设计稿更适合放进专业的设计软件：图层、属性、撤销，双方在同一份文档上动手。

open-pencil（MIT）是开源的 Figma 式编辑器，npm 上有拆好的包：`@open-pencil/core`（场景图、CanvasKit 渲染、约 130 个工具）、
`@open-pencil/vue`（无样式的画布与面板原件）、`@open-pencil/dom-css`（HTML 转图层）。它自带的 AI 聊天、云端协作、遥测和更新都不需要。

## 决定

1. **内置插件 `design` 提供“设计”标签。** 文档按会话存在插件数据目录（`.fig` 字节 + 修订号），浏览器自动保存；
   修订号不一致时拒绝覆盖（合并见第 8 条）。编辑器（约 5 MB 脚本、7 MB WASM、字体）是单独的构建产物，
   第一次打开标签时才加载。
2. **编辑器跑在同源 iframe 里。** 宿主不允许 Web 模块动态加载代码；iframe 没有 Web 模块身份，
   它的接口请求和实时连接都经标签模块代发（`ctx.http.request` / `webSocketUrl`）。
3. **Agent 的设计工具就是 open-pencil 的核心工具，在服务端执行。** 构建时从 `CORE_TOOLS` 生成名字、描述和 JSON Schema（去掉联网取图库的
   `stock_photo`、执行任意代码的 `eval`，以及只对用户画布有意义的 `get_selection`、`viewport_zoom_to_fit`），注册成 `design_*` 一组（按需加载）。
   用户常常交代一句“你设计一下”就离开，Agent 不能依赖用户开着网页：插件用部署里已有的 Playwright Chromium 打开同一份编辑器代码的无头入口
   （`worker.html`，托管与网络隔离在 `plugins/design/headless.py`，接口不含设计专属概念；别的插件也要在服务端跑自己的前端代码时提成公共能力，
   新增 Core 公开模块要过插件边界评审），每个会话一块，闲置 10 分钟回收。
   每次调用读入存储里的最新修订、执行、带修订号写回；Agent 手里的图层 ID 是 `.fig` 里不变的 GUID，文档重新读入或无头页面重开后仍然有效。
   用户开着画布时经实时通道收到新修订和“Agent 正在改哪份文档”（切过去，桌面端每轮展开一次标签）。
   选它而不选在 Core 镜像里加 Node：不新增运行时依赖，JSX 沙箱与网页导入照旧用浏览器自己的隔离和 CSS 引擎。
4. **Agent 写的 JSX 只在不透明源沙箱里求值。** open-pencil 的 `render` 用 `new Function` 编译 JSX；构建时把这一处换成
   交给 `sandbox allow-scripts` 的独立页面求值，交回的只是纯数据的图层树。编辑器页面自己的 CSP 不放行 eval 与内联脚本。
5. **网页预览并入设计文档。** `design_show_html(path, title?, import_layers?)` 取代 `show_site`：沿用 0124 的快照（同目录资源内联），
   快照成为会话里的一份设计文档，“预览”在 CSP sandbox 页面里原样运行；`import_layers` 用浏览器的 CSS 引擎把页面转成图层，放进新的一页。
6. **回退字体经后端代取。** 内置字体只有 Inter；中日韩文字从 Google Fonts 取按字子集，Google 的字体目录不带 CORS，
   由插件后端只对三个 Google 域名代取，并按 URL 缓存在数据目录。
7. **不悄悄丢修改。**
   - 每个修订各写一个内容文件，索引指向哪个修订就读哪个文件：索引写失败时旧修订仍然完整。
   - 冲突或保存失败后切走文档或会话，没存下的修改另存成“…（未保存的修改）”；只有点“重新加载”才明确放弃。
   - 会话切换、用户的文档操作（打开、新建、重新加载、导入图层）、别处保存后的自动跟进与重连对账排在同一条队列里；
     用户的导入带上点击时的文档，轮到时文档变了就拒绝。
   - 替换画布期间（换文档、新建、重新加载）和导入图层期间冻结用户输入：
     先让聚焦的输入框提交、进行中的拖动落下（派发一次 `mouseup`，输入法组字随失焦结束），再把画布与面板设为 `inert`、停用画布输入、文字编辑与快捷键。读取或另存副本期间画布仍有修改（版本变了）就留在原文档。
   - 新修订已提交后，旧修订文件删不掉只记日志，不把成功的保存报成失败。
8. **用户动手少，并发按乐观方式处理，不加锁。** 双方各自带着基于的修订号写回：
   - Agent 一侧写回冲突（用户刚保存过）就读入最新修订，把这次调用重做一遍。
   - 画布一侧有没存下的修改时，别处的新修订或保存被拒（409）都不再报冲突：取回最新修订，以画布所基于的修订为共同基线，
     按 GUID 把对方的改动原地合进画布（`editor/merge.ts`），再带新修订号保存。按字段合并，同一字段两边都改了以本地为准；
     对方删掉的图层只有本地连同子孙都没动过、也没挪过才删，本地删掉的不复活；子图层顺序本地改过就保留本地的；
     新图层全部建好以后再换算组件等引用。只有引用别的图层的字段（组件、覆盖）换算 ID，文字、名称原样比较。
     视口、选择和本地撤销栈不受影响，合进来的改动在本地记成一步撤销。合并本身出错才退回冲突提示，由用户选择重新加载。
   - 画布保存的基线修订在导出之前定下：导出期间合并进来的新修订不借给旧内容，服务端按旧基线拒绝，合并后重存。
   - Agent 的调用失败（可能改了一半）后，无头画布下次整份重读，残留不会混进之后的保存。

## 已知限制

- 无头画布常驻时每个会话约占一个 Chromium 页面（几十 MB 内存），第一次调用要冷启动浏览器和编辑器（本机约 1–4 秒）；
  闲置 10 分钟回收，之后的调用重新读入。部署环境里 Playwright 的 Chromium 不可用时，设计工具返回“无头浏览器不可用”。
- Agent 的修订是整份 `.fig` 写回：画布跟进时按图层合并，不是逐笔操作同步；Agent 的改动以保存为单位出现在画布上，不是逐帧动画。
- 合并是字段级的三方合并，不是 CRDT：同一字段两边同时改，以合并发生的一方（画布）为准；文字内容按整段比较，不做字符级合并。
  合并带来的页面增删不进撤销步骤（撤销只回退已有页面里的内容）。对方新图层的 GUID 恰好被本地别的图层的 ID 占用时，
  新图层换个 ID 建，GUID 只在这次会话里保留，画布保存后会换成新的 GUID，Agent 下次按名称重新找到它。
- 画布没开着时 Agent 的修改不在任何撤销栈里，存储只保留最新修订；要回到之前的样子只能让 Agent 改回来。
- 换文档和导入图层时画布短暂不能操作（通常不到一秒）；会话切换与文档操作要等正在执行的读写跑完。
- 离开时原文档和副本都存不下（网络断开）：切换文档会被拦住；切换会话照常进行，修改丢失并给出提示。
- 文档与实时接口只校验会话 ID 的格式，不核对会话是否存在：宿主是单一所有者、外层已有身份校验，按现有合同不另做会话归属检查。
- HTML 导入时 dom-css 在编辑器同源的 iframe 里计算样式，页面内容经 `innerHTML` 写入（不执行 `<script>`）；
  内联事件、`javascript:` 地址与外部图片由编辑器页面的 CSP 拦下。这一条依赖编辑器 CSP 保持不放行内联脚本。
  同源的图片与 iframe 地址仍会被请求（`img-src`/`frame-src 'self'` 放行）：这些请求和编辑器页面直接访问接口一样不带宿主身份，接口会拒绝；只会读到无身份也能取的静态产物，结果也不回到导入流程。
- JSX 里的变量引用跨沙箱时按标记还原，其他非 JSON 值（函数）会被拒绝。
  死循环的 JSX 靠 10 秒超时丢掉沙箱；这依赖浏览器把不透明源 iframe 放进单独的进程（桌面 Chromium 的站点隔离），
  不隔离的浏览器里同一份 JSX 会卡住编辑器页面。
- 回退字体依赖 Google Fonts 可达：某次代取失败时那段文字暂时缺字形，重新打开文档会再取。
- HTML 导入只带页面里的内联样式与已内联进快照的本地样式表，外链样式表不加载；
  画布用的字体与浏览器排版时不同，固定宽度的小元素里文字可能折行被裁，导入后需要手动调整。
