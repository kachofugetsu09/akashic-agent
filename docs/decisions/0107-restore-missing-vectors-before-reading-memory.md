# 0107 · 读学习图之前补齐缺失的派生向量

- 状态：proposed / implemented for review
- 日期：2026-10-11
- 依据：#1179 P2f；补全 [0106](0106-derived-vectors-use-separate-storage.md) 的丢库恢复。

派生库独立以后，Akasha 必须能够从原消息恢复缺失向量。恢复先按原 learning binding
核对消息摘要、学习资格及来源，再要求实际模型身份和维度等于该 binding 的空间，
只补缺失值，然后装载原学习图。正常启动和归档召回使用同一恢复过程。
已有向量内容或维度冲突仍报错，不把损坏当作缺失，不用当前默认模型替代旧空间。

┌──────────────────┐   ┌─────────────────────┐   ┌─────────────────┐
│ 核对原消息与规则 │──►│ 同空间模型补缺向量  │──►│ 装载原图并查询  │
└──────────────────┘   └─────────────────────┘   └─────────────────┘

这是一个显式行为变化：首次读取缺少向量的已学习图现在可以调用模型并写派生库。
学习事件、图、消费进度和源消息不重放、不更新；已发布查询回执仍直接读取原回执。
没有模型端口的离线读取明确报告缺失，不悄悄调用网络。补算失败或被取消时保留已经
成功写入的缓存，下一次只补余项；取得图 writer 之前的失败不会留下学习写入。

真实模型不可用时恢复失败，不能承诺离线也能重算。模型需在同一空间身份下保持其
文本映射；本地确定模型的实际学习/召回验收证明重算后结果一致，不把它当作远端模型
永不漂移的证明。若未来必须逐位保留远端历史向量，则这些向量不能再被定义为可重算缓存。

隔离场景实际学习三轮，关闭后删除派生副本，首次查询补六个向量并得到相同非空召回；
再次查询及在线恢复不再调用模型，权威消息库和已发布学习图库完整字节保持不变。
