# 0123 Computer 只剩一个浏览器，Agent 按标签操作

- 状态：proposed（维护者要求精简 Computer 并提交 stacked PR，待代码评审）
- 日期：2026-10-17
- 关联：PLG-017、0084、0088、0092、0093
- supersedes：0084 的“桌面与输入 driver”部分、0092 的“多位观看者”部分、0093 的“独立 headless 进程”部分

## 背景

Computer 容器里原来有完整桌面、桌面输入 driver（`sky`）、主 Chromium 和一份给匿名浏览器用的
headless Chromium。实际使用只有两类：保持个人 profile 的登录身份；让 Agent 做大量网页操作。
桌面层几乎没有独立用途，却带来常驻内存、唤醒时间和两套输入路径。匿名浏览器另起进程，
画面只能靠截图轮询，和主画面不是同一条流。

参考 Codex Desktop：Agent 的操作单位是浏览器标签，不是整块屏幕。

## 决定

容器只运行一个 Chromium，读取个人 profile；OpenCLI 刷新继续复用这一个实例。

```text
┌─────────────────────────────────────────┐
│ Xvnc + matchbox：窗口铺满屏幕、随 RandR │
├─────────────────────────────────────────┤
│ Chromium（个人 profile，kiosk）          │
│  ├─ 默认 Context：你的标签、Agent 标签   │
│  └─ 匿名 Context A/B…（同进程隔离）      │
├─────────────────────────────────────────┤
│ selkies H.264：只编码最前面的窗口        │
└─────────────────────────────────────────┘
```

1. **一个浏览器。** 删除桌面输入 driver 和 `sky`；Agent 只用 Browser API（`tab.cua`、
   `tab.playwright`、`tab.ax`）。人工输入经 selkies 送到屏幕最前的窗口；网关旧的 `/input`
   把键鼠转成 CDP 输入，发给最前的页面。
2. **标签是操作单位。** 每个 Agent 标签是一个后台窗口；画面显示哪一个由面板的标签条决定，
   切换只是 `Target.activateTarget`，不重连视频。被挡住的窗口照常渲染和计时。
3. **匿名浏览器是同进程 Context。** `Target.createBrowserContext` 建空 Context，不带个人
   cookie 与存储，扩展默认不进入。上限、所属 Turn、闲置 10 分钟回收沿用 0093。
4. **画面跟随面板尺寸。** 面板的画面连接以 selkies 主控端身份接入，屏幕按面板尺寸调整；
   只读由 Dashboard 代理保证：未接管时只转发分辨率、帧率和关键帧协商，键鼠、剪贴板和上传
   一律丢弃。同一时刻只有一个窗口拿到画面，后打开的接走，先打开的明确提示并可重新连接。
   屏幕尺寸会变，所以截图记下当时的 CSS 视口尺寸和像素比例；之后这些值变了，坐标动作（`tab.cua` 和
   `tab.ax` 的坐标点）直接报错，要求先重新截图。按元素操作不受影响（参考 Cursor 的
   `browser_mouse_click_xy`）。
5. **空闲回收三档不变。** 画面（没人看就不编码）、标签（匿名 Context 闲置回收）、
   浏览器（无操作满 10 分钟休眠）。0084 的身份与启停规则不变。
6. **OpenCLI 刷新清理页面。** 刷新等人工交还后开始，结束后清理新增的个人页面，保留 Agent
   页面和弹窗。期间有人接管、或收尾时 Agent 正在操作，则保留无法确认归属的页面。
7. 插件 ID 与工具名保持 `computer`；用户看到的名称改为“浏览器”。

## 理由与替代方案

- 保留桌面、只删 headless：仍有两套输入，唤醒和常驻内存降不下来。
- 匿名浏览器继续独立进程：隔离更强，但画面要另走截图，资源翻倍。维护者选择轻量和速度，
  接受同进程 Context 的隔离级别（0084 已接受 headless 崩溃影响同批匿名测试）。
- 保留 selkies viewer 角色：可以多人同看，但 viewer 不能调整屏幕尺寸，画面只能缩放，
  文字发糊。维护者要求“和本地用浏览器一样流畅”，因此选择画面跟随面板、单一观看窗口。
- 自写视频流：没有收益，selkies 已满足 60fps、恒定质量和静止补帧。

## 代价与已知限制

- 同一时刻只有一个窗口能看画面（取代 0092 的“多位观看者互不踢出”）。输入权限规则不变。
- 没有桌面层：浏览器之外的原生窗口（系统文件对话框、打印预览）不可见也不可操作；
  不能再用浏览器快捷键整页放大来看小目标。
- 匿名 Context 与个人 profile 同进程：渲染进程崩溃可能影响其他标签；扩展不进入匿名 Context。
- 全屏后重新激活观看中的标签，可能闪一帧。
- 刷新与人工或 Agent 操作重叠时，可能留下刷新页面；保留页面优先于回收内存。
- 两个 Session 同时向同一个未认领标签按同一个键，仍共享浏览器输入状态；并行任务应使用各自的标签。
- 被顶下来的窗口仍能点标签条切换画面；输入仍受接管规则约束。

前提改变时可重议：需要多人同时观看（例如演示），可在代理侧加一路只读转码；
需要操作浏览器外的程序时，再评估恢复桌面层。

## 验收

- 容器内测试：超时后浏览器和截图可用；不同 Session 并行、同一 Session 串行；匿名 Context
  不带个人 cookie、不出现在主目录、Turn 结束后清空。
- 真实应用 + 测试容器：面板显示标签条，切换不重连；屏幕跟随面板尺寸；只读时点击不生效；
  Agent 新开标签时画面跟过去，手动选过后本轮不再跟随。
- 资源（同一台机器、全新 profile）：休眠 132MB → 45MB；唤醒 1.5–2.1s → 0.8s；
  醒着 520MB–1.4GB → 约 330MB。
- MiniWoB 配对：同模型、同任务、同 seed，与 main 对照，见 [设计文档](../design/computer-one-browser.md)。

开 PR 不代表 hua-home 已更新；正式镜像由 CI 发布后再更新插件固定 digest。
