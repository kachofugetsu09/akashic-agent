# 0067 · Web 与 Mobile 属于普通插件

- 状态：accepted；实施与最终验收未完成
- 日期：2026-09-13
- 修订：[0044](0044-akashic-channel-uses-web-and-mobile-adapters.md) 的 Core 内建归属
- 关联：AKC-001、AKC-002、PLG-001、STA-001、WSP-003

## 决定

维护者要求 Akashic 只保留插件底座与原子能力，先完成全部本地插件，再处理第三方迁移。
Web 与 Mobile 的既有统一身份不变；一个普通 `akashic_clients` 插件拥有唯一的 `akashic`
Channel、两个 adapter、HTTP/WebSocket 监听、配对、客户端配置和客户端展示投影。
不能只把业务目录换名，再让 Core bootstrap 继续 import 和构造客户端。

```text
┌────────────────── 普通客户端插件 ──────────────────┐
│ Web adapter ──┐                                   │
│               ├── 一个 akashic Channel             │
│ Mobile adapter┘                                   │
└──────────────────────┬────────────────────────────┘
                       │ 显式声明的能力与宿主端口
┌──────────────────────▼────────────────────────────┐
│ 中立渠道宿主 · 请求租约 · 任务作用域 · 耐久输入       │
│ Message 日志及其既有读写边界                        │
└───────────────────────────────────────────────────┘
```

请求只获得原声明 Fiber 的能力和精确 generation lease。长期监听归该 Fiber，不能持有一个
请求租约覆盖整个 WebSocket 生命周期。停止先关闭接纳，再排空请求和任务；启动必须证明真实
监听就绪，意外退出必须报告失败。插件之间用各自声明的版本化能力名和结构合同组合，不 import
对方实现；Core 不维护客户端概念目录。

耐久输入由既有 handoff store 拥有接管事实。普通渠道声明相应能力后取得窄的接管端口，不能
取得整个 MessageBus、任意 SQL 或伪造其他渠道的恢复入口。恢复不得使用 Mobile 专用标记
决定 Core 控制流。端口中立化不改变接管、附件发布、消息提交和完成之间的顺序。

## 受保护状态与迁移边界

本次没有正式 workspace 写入权限。Session、Message 正文、顺序、附件、设备密钥及既有
数据库路径保持原有权威 owner。历史 Yoyo 脚本退役不影响本次之后的新迁移声明。
配置转入插件时由插件自己的新迁移拥有：先备份，校验已有目标冲突，保留原数据路径引用，
失败不记成功且可重试。不得借配置迁移搬移数据库、删除账本或重写既有 Message。

客户端重连必须读取真实的持久消息或已提交传输事实。未知 turn 不能凭空标记成功或失败；
不能用空实现、旧 SessionManager facade 或新的重复执行模型隐藏缺失的恢复链路。

## 验收

- Core bootstrap、分发源码和配置不再直接拥有或构造 Web/Mobile 业务。
- 插件可通过正式安装链运行，未安装时 Core 可独立启动；无源码 checkout 的产物可启动。
- Web/Mobile 继续同一批 Session，真实消息、附件、流式、取消和断连恢复通过现有协议验证。
- 失败、取消、热更新、旧租约排空与监听释放均由同一条宿主生命周期处理。
- 最终栈顶执行行为测试、完整 Gate、独立累计概念审查；静态 import 清零不足以通过。
