## 背景与决定

维护者要求用普通非特权插件完成长工具结果折叠：保留全部证据、先完整展示一次、随后释放上下文，
需要时可回读全文或范围；长回读同样可以折叠。Maka 的限长回读不等于永久豁免，本方案允许完整回读。

原始 ToolResult 已完整写入追加日志，因此直接用 `(message_id, part_index)` 定位原文。
不增加第二份归档文件、seen 数据表、可变历史副本或归档专用 Core hook。

```text
┌──────────────────────────┐
│ Tools 提交完整 ToolResult │ 原文唯一 owner：MessageLog
└────────────┬─────────────┘
             ▼
┌──────────────────────────┐
│ Models 内容投影           │ 原文 / 普通内容贡献者
│ 实际请求 + 首次展示位置   │ 冻结 owner：ReAct
└────────────┬─────────────┘
             ▼ 有效响应通过原提交检查
┌──────────────────────────┐
│ Output 的 model.facts     │ 新增首次完整展示回执
└────────────┬─────────────┘
             ▼ 下一次请求
┌──────────────────────────┐
│ content_view 普通插件     │ 已展示的大文本 → 稳定引用
└────────────┬─────────────┘
             ▼ read_content
┌──────────────────────────┐
│ 原消息位置 + 字符范围     │ 新 ToolResult 仅保存引用
│ 投影展开完整范围          │ 大回读也先看一次再收起
└──────────────────────────┘
```

## 两项通用能力与归属

1. `models.content-views.v1` 由普通 Models 插件提供。注册者按只读消息快照、来源、获授工具名和
   已完整展示的位置生成纯内容投影。结果是模型内容块与 `complete`；同一位置有两个处理者时失败，
   不靠隐含优先级覆盖。bind 固定实际贡献者并保护其 scope，关闭后拒绝调用。
   附件正文展开、结构结果展示、脱敏视图也可使用该入口；脱敏或节选不得声称完整展示。
2. `ModelRequest.content_refs` 是尚无成功展示回执、且本次实际完整渲染的消息位置。
   它不进入 provider wire。ReAct 与原请求一同冻结；成功响应的 `model.facts` 保存它，随 Output
   原子提交。Models 从同一 source 的已提交事实推导后续 `seen`，不由策略插件猜测“seq 小所以看过”。
   该证据也可用于确认引用材料实际入模、恢复请求和解释展示差异。

Core 只扩展通用请求值的来源字段及边界校验；注册、阈值、提示词和回读均由普通插件拥有。
`reply_program` 借用可选视图 provider；缺席时保留基础投影，不要求其他模型 provider 实现新注册表。
插件不申请 Message writer、OwnerState、全会话目录、Artifact store、workspace 文件或模型调用权限。

## 插件行为

- `fold_after_chars` 默认 8192，只作用于工具文本和本插件回读内容；小于或等于阈值的内容保留。
- 新结果第一次完整展示；只有有效响应提交后才能折叠。估算、候选渲染、失败、取消与提交被替代不产生回执。
- 只在当前获授工具菜单含 `read_content` 时折叠。工具组声明 always_on，使已获授的回读 schema 从首次请求起稳定存在。
- 折叠引用包含原消息位置、字符范围、长度和短预览。按确定规则从原文生成，不引入可漂移摘要。
- 回读参数限定当前 CallSource 的不可变会话前缀；不能指定 Session、文件路径或 URL。
  省略范围读取全文；范围按 Python Unicode 字符计数，使用 `[start, end)`。
  不存在、非文本、越界显式拒绝，不把截断结果冒充完整。
- 回读结果保存 `content_view.read` 内容引用。回读旧回读时折算成原文坐标，不产生引用链。
  渲染时展开请求的全部范围，长范围在这次展示成功提交后可收起。
- 当前或前一次成功请求用过内容变换时，不用旧 opaque continuation，按当前完整消息投影开始请求。
  `content_transformed` 随实际请求冻结和成功 facts 保存，覆盖插件卸载后恢复全文的情况；原 opaque 事实仍保存在日志。
- 首次全文超过模型容量时沿既有容量拒绝与摘要协议报错。本插件不凭空宣称已读，也不自动执行原工具。
- 卸载不改原文；其他消费者仍能读原始 Message。回读引用仍可审计，但其展开需要本插件的 renderer；
  不把插件缺席时的原始 JSON 引用展示宣称为全文回读能力。

## 持久化、失败与恢复

| 对象 | 正常增加 | 允许更新 / 逻辑变化 | 物理减少与恢复 |
|---|---|---|---|
| 原始 ToolResult | Tools 原有事务追加完整结果 | 无本插件改写 | 无自动减少；原 sessions.db 备份 |
| 回读 ToolResult | Tools 同一事务追加原文位置与范围 | 无 | 无自动减少；同库原文与引用一起恢复 |
| Output 的 model.facts | 成功提交时增加首次完整展示位置 | 不回填或改写旧 facts；旧消息没有证据时再次完整展示 | 无自动减少；读取原库可恢复 |
| ReAct 生成准备 | 原协议冻结请求时附带来源位置 | 原 owner 的 attempt 协议不变 | 无新清理；恢复精确重放原请求与来源 |
| 插件注册与投影视图 | 运行时注册 / bind | 释放 scope 后失效 | 仅释放内存；不持有业务删除口 |

消息 schema 不变，不做数据迁移。原请求冻结仍保存完整 wire payload，以保留既有精确恢复合同；
本次不改其存储格式。阈值改变可能重建历史投影并影响缓存；阈值稳定时旧引用保持相同。

## 验收

`PYTHONPATH=. .venv/bin/python docker/debug/content_view_scenario.py` 在一次性目录运行真实
PluginManager、Tools、Models 调用账和 MessageLog，只在 provider 边界使用可控响应。
包含改名插件安装、首次全文、折叠、全文回读后再折叠、Unicode 范围、跨会话与越界拒绝、
无引用链、请求冻结、关闭后读取、无回读工具时展开、摘要边界、纯渲染无副作用、provider 失败不算已读、贡献者排空、
关闭视图失效、同位置冲突拒绝、卸载视图清空旧 opaque 和既有原文不变。
场景不是模型推理质量或真实 provider 缓存性能验证；这两层不能由本地模拟响应证明。

本地实现不改变正式安装选择，也不部署。该插件与 Models/Reply Program/ReAct 的新源码组合交付；
旧 model.facts 和旧冻结请求可读，降级旧代码之前应停止新执行，不能让旧严格校验器读取新 facts。

场景使用当前 `channel.input.v2`；完成和失败状态分别在全新进程重开，同 ID 输入返回原 Message，
模型调用数为零，原消息逐字段、实际工具效果及 SQLite 完整性保持。场景 provider 的模型账本
随其 scope 关闭，避免父进程残留文件锁阻止恢复进程加载。
`PYTHONPATH=. .venv/bin/python docker/debug/content_view_scenario.py --directory-page` 将真实
`list_dir` 页及其续读提示送入同一闭环；回读只恢复该页原文，后续目录条目仍按生产者游标读取。
