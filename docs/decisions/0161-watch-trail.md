# 0161 值班：后台回合的足迹自动带进下一轮，看不明白可以问

状态：proposed / implemented for review

## 背景

0159 上线后读了四天的后台回合。它自己发起的探索几乎只去同一处，其余的去处都是跟着订阅事件走；用户很久以前聊过的地方一次没去。另外它在便签里记下了一条连续几天重复出现、靠数据看不明白的观察，写的是"留待下周再印证"，没有问用户。

原因有两层。每个后台回合是一个新会话，上一轮做过什么只能靠它自己写便签，而它只用便签记观察，从不记去过哪；值班日志里每轮只有状态和会话名。于是每一轮拿着同样的线索，选中同一个最显眼的去处。提示词要求"挑没看过的去看"，但它没有任何东西能判断哪里没看过。提问那一头，提示词写着能靠看弄明白的就不要问、想问的只问他自己提过的事，把靠看弄不明白的猜测也挡住了。

## 决定

1. 每个后台回合结束后，系统从这一轮实际发生的调用里算出一行足迹，追加到 `watch/trail.md`：去过的地方（调用参数里出现的站点和应用标识）、对用户说的话、改过的文件。不依赖它自己记得写。
2. 每轮醒来的现场带上最近十二行足迹，以及三十天里各处去过几轮、最近是哪天。主对话的常驻提示指向同一个文件。
3. 不用固定的后台会话。回合之间隔几个小时，缓存已经过期，固定会话每轮要冷读全部历史，很快就要压缩，压缩后留下的也只是一份摘要。
4. 提示词让它对着足迹挑没去过或很久没去的地方；每日复盘把用户用的、提过的地方整理成一个记忆专题，以后从里面挑。
5. 靠看弄不明白、而用户一句话就能答的猜测，可以问：问是印证的一种。一次一句、没回就放下的规矩不变。
6. 提示词开头说明它是一个认识用户很久、醒着的人，后面的规矩只管别在错的时候打扰。"过一眼"回合去掉"十步上下是常态"。

## 已知限制

- 足迹只认调用参数里的网址和反向域名写法的应用标识。用命令行去的地方、按名字打开的应用不会出现在"去过"里，它可能把去过的地方当成没去过再去一次。命令行这一种已在 0162 补上。
- 足迹只记去过哪和留下了什么，不记看到了什么；看到的东西仍靠它写进记忆专题。
- 回合会更长，提问会让主动消息变多。提问多了用户嫌烦时，靠他的反馈和"留意"里的规矩收。
- 评测里的"换地方看"场景只有两处可去，说明方向；真实多样性以部署后的足迹为准。
