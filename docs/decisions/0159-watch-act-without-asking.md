# 0159 值班：后台回合动手不设限，办成或卡住先交代

状态：proposed / implemented for review

## 背景

0158 上线后读了部署后的三个后台回合（每日复盘、过一眼待看、一次事件叫醒）。它查得很广，但产出只有记忆里的几行：一件能替用户办掉的事被说成"记得去做"，一件已经了结的事留着为它排下的定时任务，要用户自己开口来停。提示词里约束动手的句子（只做一件、看两三处就停、只备到差他点头）比鼓励动手的多，举的例子也多是"去看"。

另外，后台会话没有工作目录，改文件和执行命令时相对路径落到源码目录，几乎每个回合都要白走几步再改用完整路径。

## 决定

1. 提示词不再给动手设授权边界：用户的机器、账号、设备都可以直接动，能办掉的事办到底，提醒用户自己去做只是办不了时的退路。拦住它的是事情本身（非本人到场不可的一步），不是提示词。
2. 透明代替许可：替用户动过的东西要让他知道办了什么、怎么撤回；什么时候说仍按 0158 的"不打断"原则。
3. 办成或卡住先交代，再做别的；同一步试两三次过不去算卡住。回合随时可能被打断，没交代的等于没办。
4. 事件叫醒后的那段时间和每日复盘，目标从"去看一件事"改成"办成一件事或交出一样现成的东西"；复盘多一步，回头把只记了一笔的事办掉。
5. 场景段给出工作区的完整目录。

## 已知限制

- 这是用户明确要求的"先看到极限"的版本，没有按可否撤回分级。误动的代价由事后告知和用户的反馈来收，必要时再收紧。
- 评测环境的终端是无状态的桩，模拟不了真实机器，动手类场景只能说明方向；真实效果以部署后的记录为准。
- 回合更长，开销更高。
