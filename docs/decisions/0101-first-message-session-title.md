# 0101 · 首条输入自动命名，空标题乐观写入

- 状态：accepted
- 日期：2026-10-10
- 补充：[0087](0087-session-title-override.md) 的 title 写入范围；保留手动重命名与清除行为。
- 需求：SES-012。

## 决定与理由

维护者确认只需要首条用户消息产生一个短标题，并允许复用现有显式覆盖字段。
自动标题是普通插件，不新增并行标题字段、版本、迁移或后台补齐任务。
首条输入触发后台小任务，使用 fast 模型角色和有限输入、输出、等待预算；
预期模型失败或空输出退回首句截断，内部与存储错误继续传播。

生成期间不锁定会话；落库在 Session owner 的事务内执行空标题条件更新。
非空标题或软删使写入返回 False，不重试。这样正常路径只有一次条件 UPDATE，
不靠写入前多次读取保证并发，不增加所有手动改名路径的版本维护成本。
代价是仅比较当前值：若用户在生成期间先改名又清空，当前空值仍允许此次写入。
若未来需要保护这段操作历史，再单独引入版本合同；不把它藏在本次优化中。

```text
首条 Input → 同步通知入队 → Fiber 后台生成 → Session 条件 UPDATE
                                             ├─ 空且未删：写入
                                             └─ 已有标题/软删：放弃
```

## 生命周期与持久状态

Fiber 取消并等待后台任务及其子任务排空后才能卸载。普通后续输入只查询消息头，
不重读历史正文；首条文本固定读取，不随后续消息变化。已有标题避免模型调用。
正常只原位设置 title，不改变消息、排序时间或学习；不增加逻辑失效或物理减少协议。
用户仍可用原重命名入口覆盖或清空；后续输入不会重新自动命名。
源码由 Git 恢复；既有 title 无迁移，卸载插件不回写、不清除已生成标题。

## 验收

真实 CompositionRoot、来源事件、SessionAdmin 与临时 SQLite 验证首条触发、后续跳过、
手动改名竞争、清空后不重跑、软删竞争、模型降级、任务取消排空和消息/排序保全。
默认分发 profile 必须通过正式加载器的依赖顺序检查及镜像启动 CI。
