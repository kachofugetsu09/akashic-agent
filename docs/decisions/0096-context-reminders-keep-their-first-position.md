# 0096 · 不变提醒保留首次使用位置

- 状态：proposed
- 日期：2026-10-07
- 关联条款：CTX-004、CTX-009、SES-005
- 部分 supersedes：[0052](0052-compaction-and-markdown-memory-are-ordinary-plugins.md) 的末尾位置约定；材料归属、权限与持久资格不变。

## 问题与决定

每次工具续接都将相同提醒移到末尾，会改变上一请求的消息前缀，也会让环境数据持续成为最后一条 user 消息。
维护者要求优化任务完成能力，同时减少不必要的缓存失效。优化必须适用于普通任务，不能识别某个 benchmark 的任务或路径。

Model 投影复用成功 Output 中已有的 Input 身份和材料摘要。同一身份的材料保留在首次使用它的 Output 前。
新材料首次出现在当前请求末尾；成功后按同一规则重建。不同 Input、变化后的材料与无身份旧事实仍保留。
Context 只组装本次贡献，不另建消息 writer、持久缓存或材料状态表。

```text
┌────────────────────────────────┐
│ Message 中的 model.facts       │  已保存的材料与真实 Input 身份
└──────────────┬─────────────────┘
               ▼
┌────────────────────────────────┐
│ Model 只读投影                 │  重建首次位置；新材料追加
└──────────────┬─────────────────┘
               ▼
┌────────────────────────────────┐
│ 本次请求                       │  再加入当前实时材料
└────────────────────────────────┘
```

实时材料不进入 `model.facts`。它随当前 reminder 出现；没有 reminder 时放在本来源最新 Input 后。
每次读取当前贡献。切换目录、删除 AGENTS 或卸载贡献插件后，旧实时正文不得重新出现。
本次不改变供应商续接策略。原有思考正文、调用账、continuation 和 assistant 协议元数据完整保留。
当前 Codex continuation 只接收 reasoning 项；不能把它当成保存完整输入的隐藏会话而清空。

## 理由与替代方案

- 不将环境数据提升为 system 权限。用户输入保持独立。
- 不增加重复阅读计数器来强制写文件。只读任务仍能正常结束。
- 不靠扩大缓存 TTL 或忽略材料变化降低成本。新事实比缓存命中重要。
- 不单独保存“上次提醒”。成功 Output 已拥有可重建事实，第二份状态会增加重启和卸载分支。
- 不按所有文本相同就去重。不同 Input 和旧的无身份事实不能互相替代。

## 状态、恢复与代价

`messages` 仍只随真实 Input、Output、ToolResult 或 Control 正常追加。此次不 UPDATE 或 DELETE 旧行。
可回放材料仍随成功 Output 保存；失败和取消不新增成功事实。实时材料仍不保存为 replay。
插件撤下只撤销当前贡献，不删除历史。物理减少仍只由已授权消息管理操作执行。
没有数据库迁移。恢复旧源码只恢复旧请求位置；已提交消息与冻结请求保留。

第一次切换实现会改变部分旧会话的请求前缀。真实材料变化、摘要与模型切换仍可能使缓存失效。
稳定前缀是可测的请求属性，不能单独证明供应商命中缓存或模型更快完成任务。
若供应商要求其他位置，应使用可观测的协议适配与对照证据，不能静默改变来源或权限。

## 验收

用真实 Message 与组件装配重放多次工具续接，核对实际请求和既有记录：

1. 不变材料只出现一次，后续请求保留已有消息前缀。
2. 材料变化后新版本位于变化后的请求边界；不同 Input 不共用身份。
3. 重建 Model 投影后位置一致；摘要只改变临时窗口，当前 Input 与工具配对仍在。
4. 实时材料变化或撤下立即可见，旧 Output 不恢复它；原有供应商协议内容不因位置调整而丢失。
5. 未修改的消息正文、身份与顺序完整；生成失败不产生成功 replay。
6. 在不同任务上独立验收质量、逐轮耗时、缓存命中与重试成本，不以一次跑分快照替代泛化验证。
