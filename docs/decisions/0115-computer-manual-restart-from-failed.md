# 0115 Computer 出错后由用户重启电脑

- 状态：proposed / implemented for review（维护者要求补 Computer 的恢复入口，单独 PR）
- 日期：2026-10-12
- 关联：PLG-017、ERR-001、STA-003、0084

## 背景

0084 规定：运行时异常退出、SIGKILL、异常信号退出或输入释放失败，都会关闭启动准入，
进入 `failed`，不能把进程退出当作身份已落盘的证明。原来的唯一恢复方式是重启整个
Akashic 或 Workload。这条边界保护的是两件事：旧输入状态不能残留到新会话，主 profile
同一时刻只能有一个写入者。但对用户来说，它是一条死路。

## 决定

`failed` 状态增加人工恢复入口"重启电脑"（gateway `POST /restart`，面板在出错时
提供这个按钮）。它只从 `failed` 出发，由现有生命周期 owner 执行：

```text
failed ─→ stopping ─┬─ driver 正常收尾成功 ──────────────┐
                    └─ 收尾失败 → 强制结束 driver 子进程 ─┤
                                                         ▼
                           SIGKILL 整个运行时进程组，确认组内没有存活进程
                                                         ▼
                                   sleeping ─→ 与普通唤醒相同的启动路径
```

- 能正常收尾就正常收尾，让还活着的 Chromium 有机会把登录状态写回磁盘。
- 强制收尾只结束 driver 自己创建的东西：JS worker、原生输入进程、匿名 headless
  Chromium 及其临时目录。持有的接管占用归还，所属 Session 收到匿名浏览器关闭通知。
- 运行时进程组包含 Xvnc、桌面、主 Chromium 和推流。整组结束后，旧的 X server
  和浏览器都已不存在，旧输入状态不可能残留。确认组内没有任何存活进程后，主
  profile 才会被再次打开，单一写入者不受影响。
- 启动失败按 0084 原规则处理：收尾成功回到休眠，收尾不确定回到 `failed`。重启本身
  失败时，状态回到 `failed`，并带上原因。

不做的：

- 不把 `failed` 自动改成 `sleeping`，也不自动重试。异常退出可能反复出现，是否重启由用户决定。
- 不删除或迁移主 profile。重启电脑接受出错前最后一刻未落盘的浏览器改动可能丢失，
  界面会明确说明这一点。
- driver 关闭准入但生命周期仍是 `ready` 的情况（例如接管释放失败），这次不并入
  `failed`，仍需重启 Workload。

## 验收

- 生命周期：非 `failed` 状态拒绝重启；只杀掉组长时，子进程仍存活，状态进入 `failed`。
  重启后旧进程组全部退出，以新的进程组回到 `ready`。正常收尾成功时不走强制收尾。
- 匿名浏览器强制收尾：所属 Session 收到 `restart` 关闭通知，headless 进程退出，
  临时目录删除。
- 面板：出错时显示"重启电脑"和"复制详情"；重启期间显示"正在重启电脑"，不会被中间
  的 `stopping` 状态说成"正在休息"；完成后恢复观看。
