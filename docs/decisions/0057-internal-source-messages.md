# 0057 · Subagent 与 Wake 保留完整内部消息

- 状态：accepted
- 日期：2026-09-06
- 关联条款：SEC-011、SES-003～SES-005、MEM-001～MEM-002
- supersedes：0041 对 Subagent/Wake 内部推理采用 in_memory 的选择

## 背景与决定

完整工具调用必须先保存原 binding 与参数，才能在崩溃后查询原效果。旧内部执行只保存部分 control Turn 记录，不能提供完整 Message 恢复事实。维护者确认两类来源使用独立内部 Session 正常落库；可观察合同由 SEC-011 拥有。这是独立批准，不扩大 0055 原本只适用于 Scheduler 的授权。

## Subagent 回传

同步调用直接结算原 ToolResult；异步调用先结算接纳回执，终态后交给主回复程序。主回复使用当前对话、模型配置和工具，将子任务结果作为低信任上下文材料；不追加伪造的用户 Input 或第二条同调用 ToolResult。

```text
┌───────┐  调用工具  ┌──────────┐
│ 主回复 │ ────────→ │ Subagent │
└───┬───┘           └────┬─────┘
    │ 同步：等待结果       │ 独立内部消息
    │ 异步：先收回执       │ 保存终态
    ▼                     ▼
┌─────────────────────────────┐
│ 主回复空闲后读取结果 → 回复用户 │
└─────────────────────────────┘
```

每个 job 在父 Session 使用自己的来源身份，主回复与用户输入共用 Conversation 的 Task 准入。新输入撤销旧回复的提交权；排空、完成用户回复后再处理原结果。已保存的主回复 UUID 就是恢复身份，发送失败不重新生成答案。发送使用原任务固定的渠道 binding 和地址；默认发送策略只消费自己负责的来源，不能替其他来源保存空选路。未知效果保持原回执，在后续消息触发或启动时查询；没有自动循环重试策略。

## 理由与影响

复用 Message、Task 和普通回复程序后，来源仅保留自己的准入、业务选择、完成回传和 ACK。隐藏、投递与学习分别执行原有准入规则，不需要另一套临时消息库或执行器。既有历史不补造，正常新增消息只追加；备份覆盖内部消息、binding、工具及发送回执，没有自动减少策略。

## 验收

- 独立工作不读入另一次内部推理；Wake 明确取得的目标聊天历史仍可读。
- 内部消息不进入默认列表、投递和学习。
- 工具结果、最终回传或通知已经提交后，恢复不重复其效果。
- 取消、失败、未知发送和 EventMail 确认保持真实状态与原提交次序。

实施与恢复边界见 [Message/plugins 分层合同](../design/0902-reviewed-v4.md)。


## 2026-09-07：未配置 Wake 发送目标时暂停新准入

维护者授权执行者记录选项、按推荐方案继续，并在完成后 review；经 Terra/xhigh 讨论采用下列选择。

| 选项 | 结果 | 选择 |
|---|---|---|
| 暂停新职责准入，只维护 Content 池 | 不产生新的内部模型执行、领域领取或发送；配置目标后按当前职责继续 | 采用 |
| 仍运行模型，将无法发送的分享作为跳过结算 | 可以保留无目标模型演练，但会在没有通知用户时消耗已领取职责 | 不采用 |

新 Request 必须带明确目标和原 Sender binding；不能先保存空目的地，再用未来配置补填。Runtime 启动时先恢复已经保存且带原目标的请求，然后仅在当前配置有目标时启动新职责准入。移除当前目标不会撤销原来已接纳的发送。

无目标期间五分钟 Content 维护继续，Alert/Drift 不领取。Alert pending 的到期投影可延至重新启用职责检查时提交，原 envelope 仍保留；没有自动删除。隔离验证使用受控目标和 Sender，不再通过缺少发送目标来表示测试模式。此项取代 0040 对无目标 `wake:default` 执行的旧选择。
