# 0097：冻结请求增量属于一次 ReAct 执行

- 状态：proposed
- 日期：2026-10-09
- 关联：CTX-001、SES-005、STA-002；[0092](0092-model-generation-recovers-until-output.md)

## 背景与决定

每个工具步保存完整历史会反复编码和写入已有请求行。准确重放仍要求在模型调用前
保存完整可恢复的请求，不能在重启后用当前材料重新组装。

使用已有 `request-delta-v1` 格式，只引用同一次 ReAct 执行在固定 OwnerStore 中
已经提交的 `(prep_key, attempt)`。基线不是按 Session 命名的共享缓存；执行结束、
取消或重启即释放，新执行的第一次准备保存完整请求。

```text
┌─────────────────────┐       ┌────────────────────────┐
│ 当前冻结请求        │──────▶│ 同类型 JSON 前缀比较   │
└─────────────────────┘       └────────────┬───────────┘
                                          ▼
┌─────────────────────┐       ┌────────────────────────┐
│ 本次执行已提交请求  │──────▶│ 原条目引用 + 新尾部    │
└─────────────────────┘       └────────────┬───────────┘
                                          ▼
                              同事务核对来源并耐久提交
                                          │
                              成功后推进基线，再调用模型
```

相同冻结对象可直接复用；其他值比较完整 JSON 结构，区分整数、浮点、布尔和正负零。
只压缩数组共同前缀；材料和标量每次完整保存。最多连续引用十五层，下一条保存完整起点。
恢复仍使用原读取器：引用缺失、范围错误或链过长必须报错，不重建猜测内容。

## 状态与失败边界

生成准备由来源 owner 增加；已有 attempt 内容写一次，后续只追加 attempt、请求身份和
启动标记。增量链依赖此不变量，未来 writer 不得原位替换被引用条目。事务失败不推进
内存基线；取消先沿既有存储合同排空物理提交，不能发布尚未提交的引用。

本次不迁移或减少旧准备、Message、工具回执和模型账。不改变 provider 请求、digest、
估算或外部效果屏障。恢复依靠原 sessions.db 与 models.db；前一版本已支持该增量格式，
不需要把既有记录转换成新格式。

## 未选方案与代价

不使用进程级 Session 基线：同名 Session 可属于不同数据库。普通 Python 相等不能
证明 JSON 类型一致，尤其 `1 == 1.0 == True` 与正负零。

不搬动 system 行以取得对象身份命中：这会影响不同 adapter 的空白处理和估算。
不增加新的数组段格式或内容寻址块：已有表示可以准确表达共同前缀，新格式会扩大恢复面。

每次写入仍需线性检查行身份，恢复最多读取十五条前驱；完整检查点仍保存完整历史，
因此不能宣称累计写入已变为严格线性。若需要更长链或改变条目保留协议，应另行设计。

## 验收

真实 ReAct 工具链跨越多次完整检查点；相同 Session/Input/owner 名称的两个独立数据库
并行运行。工具 schema 轮换整数、浮点、布尔和正负零，Prompt 中途改变。关库重开后
逐请求比较真实 driver 输入，并核对已有 Message 内容、身份和顺序以及实际工具文件。
端到端回放另比较完整 provider 请求，性能收益由隔离 A/B 证明。
