# 0134 · 摘要按消息身份累计覆盖

- 状态：accepted / implemented for review

- 关联：CTX-007、MEM-011、SES-005、Issue #1705

## 问题与决定

另一个来源有未完成轮次时，Reply 会隐藏它的消息。此前为了让摘要在请求视图与真实日志
中都连续，将摘要上限固定在第一条隐藏消息之前。主对话在此位置之后的已结算批次永远
不能进入摘要，只能反复缩写旧摘要，直到硬容量不足。工具都有回执但来源没有终态时也会发生。

摘要继续由 Session 的唯一 compaction owner 发布，但覆盖以按日志顺序排列的消息身份
为准。请求视图中的已结算批次可以跨过隐藏来源；隐藏消息既不送摘要模型，也不记作 omitted。
Model 投影只替换精确覆盖的消息，保留当前工作 Input，并检查覆盖与原文不会切开工具配对。

```text
完整日志 ──┬── 隐藏的开放来源 ──→ 保留原文与运行状态
           │                          │ 后来结束
           └── 可见且已结算消息 ←─────┘
                        │
              尚未覆盖的安全批次
                        ▼
               摘要 + 未覆盖原文
```

后来可见的旧消息仍属于未覆盖材料。下一代可以把旧身份插入累计覆盖列表中间，但不能
撤回或重排父代已覆盖身份。真实模型输入与 omitted 仍精确划分本代新增覆盖。
Markdown 只有在完整 Turn 已闭合且所有消息都实际被覆盖时才取得学习资格；沿父链读取
真实模型输入，后来补入的来源不漏学，已学完整 Turn 不重复学习。

## 参考与取舍

本地 Codex `97239fd052` 的 `compact.rs` 在摘要超窗时缩小请求后重试；本地 Claude Code
`591087e` 的 `grouping.ts` 按 API 批次切分，避免悬挂调用把后续批次锁成一整块；DeepSeek
Harness `477b4f4205` 的 `compaction-basic/src/region.ts` 在开放 Turn 内按工具配对边界选取范围。
Claude Code 是本地恢复及修改过的源码，不代表官方发行版的已验证行为。

采用共同的“压缩已结算批次并取得实际进展”原则，但不照搬删除请求头部或补造工具结果。
本项目多个来源交错共用日志，需保留隐藏来源的未来可见性。自动 abandon 会改变任务事实；
把隐藏消息算作 omitted 会吞掉后来完成的内容；只抑制重复提示不能恢复超窗会话。

代价是覆盖校验和增量计算必须按身份集合进行，不能再用一个末尾 seq 表示。若以后来源
改为独立日志或独立摘要 owner，应重新评估是否仍需要跨来源的稀疏覆盖。

## 持久状态与恢复

- Message 正常只追加，没有原位更新、逻辑失效或物理减少；摘要路径没有正文写权限。
- compaction 新增不可变 v3 记录；沿既有 parent CAS 事务更新 Session head。旧 v0/v1/v2
  字节保留，旧父链仍按原前缀规则验证，v3 按有序包含关系验证；没有 SQL schema 迁移。
- 旧摘要不是删除或失效，历史使用引用仍解析到原记录。新旧代都保留真实输入与省略分区。
- 新增 v3 后旧二进制不能解释新 head，因此不能只回退代码。部署前须按 BAK-001 保存恢复点；
  回退正式状态需另行批准并核对部署后的新增消息，禁止为回退自动倒退 head 或删除新记录。
- Markdown 沿原草稿与 receipt 协议写入；本变更不自动清理档案或 receipt。

## 验收

`scripts/compaction_open_source_scenario.py` 使用真实 Channel、Reply、工具投影、摘要与 SQLite，
仅模型对端固定。覆盖未完成来源的调用已有回执及尚无回执两种情况：主对话连续硬超窗后
恢复、冷启动同一状态后继续、后台完成后原文重新出现及后续学习。逐阶段核对原消息完整
行、身份和顺序，检查没有把隐藏消息送给模型或写进累计覆盖。

既有 `scripts/compaction_workflow.py` 继续检查父摘要单独缩写、巨大批次、摘要过长后的
缩写与裁切、provider 容量拒绝、软失败继续及真实硬容量失败阻断。
