# 0119 · 运行诊断本地可用，外部接入独立消费

- 状态：accepted；前端决定由 [0120](0120-runtime-diagnostics-is-operations-only.md) 替代
- 日期：2026-10-14
- 关联：PLG-015、PLG-016、ERR-001；补充 [0042](0042-plugin-diagnostics-preserve-domain-owners.md)

## 背景与决定

容器内存总量不能说明具体进程或代码分配位置。用户需要安装 Akashic 后即可查看
近期曲线和定位材料，不应先部署外部监控服务；未来仍可接入更长保留期和集中告警。

0042 的操作身份、诊断 facade 和错误语义保持不变。新增普通内置诊断插件，消费已有
受限结构化日志并采集进程指标。它拥有有界临时记录、手动剖析和本地页面，Core 不解释
具体插件的队列、缓存或业务计数。业务 owner 沿原 `measure` 报告有限数值。

```text
┌─────────────────────────┐    ┌──────────────────────┐
│ 原有插件操作与有限数值  │    │ OS / GC / 任务采样   │
└────────────┬────────────┘    └──────────┬───────────┘
             └────────────┬──────────────┘
                          ▼
             ┌────────────────────────┐
             │ 诊断插件的有界内存记录 │
             └────────────┬───────────┘
                          │ 版本化只读值 + 游标 + 缺口
              ┌───────────┴──────────────┐
              ▼                          ▼
       ┌──────────────┐         ┌────────────────────┐
       │ 页面与导出   │         │ 未来独立外部适配器 │
       └──────────────┘         └────────────────────┘
```

外部适配器主动拉取，并独立拥有发送、重试、队列和配置，不在业务诊断调用中运行
外部 callback。当前只实现真实页面与导出共用的读接口，不预建 exporter 注册框架、
专用时序数据库或外部供应商配置。读者落后必须看见缺口；断开不能形成发送背压。

## 代价与未选方案

- 固定容量的内存窗口会在高日志量下缩短可回看时间，退出即丢失。它是定位材料，
  不承担审计与业务恢复。需要持久留存时由显式外部消费者负责。
- OS 指标存在平台差异；缺席显示状态，不能归零或阻止其他诊断功能。cgroup 可能
  包含同组其他进程，不能默认当作 Akashic 独占内存。
- 常驻堆扫描或完整分配追踪可能放大性能问题，因此只常驻低频 OS 和小计采样。
  Python 分配追踪手动限时开启；它给出分配位置，不证明当前持有者或插件独占量。
- 不把 RSS 增量记到每次 operation：并发、共享对象和 allocator 都使这种归因失真。
- 不新增 telemetry 领域事件总线；原诊断记录已经拥有身份和边界，第二套事件模型
  会复制事实。也不直接要求 Loki/Grafana，使基本诊断依赖外部部署。

## 状态与验收

记录和最后一轮剖析只由诊断插件在内存增加、更新、限额淘汰；换代、停用或退出清空。
没有业务数据 writer、迁移或持久诊断清理。导出只响应用户下载，不自动发送。
详尽字段、不可用状态和扩展合同由[插件 README](../../plugins/runtime_diagnostics/README.md)维护。

验收走真实插件组合和 HTTP：OS 分配反映到曲线、调用栈找到实际分配位置、定时停止、
重复启动拒绝、非本 owner tracer 保留、慢读者缺口、导出不含正文、无 UI 独立读取、
关闭后任务与回调退出。浏览器核对真实宿主权限、导出、剖析、亮暗主题和 320px 窄屏。
