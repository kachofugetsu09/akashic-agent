# 0092 Computer 观看与操作分开

- 状态：proposed（维护者要求实现并提交 stacked PR，待代码评审）
- 关联：PLG-017、WEBUI-008、0084、0088

## 背景与选择

现有面板把每个观看窗口注册成 Selkies primary controller，第二个窗口会踢掉前者。匿名浏览器打开 Akashic 时，活动通知又会打开电脑，形成新的 controller。移动端同样被工具区遮挡。

观看连接默认使用 Selkies viewer；主桌面与真实匿名页面各有标签。匿名页面通过所属 BrowserContext 的 CDP 获取画面，不复制个人 profile。用户选择观看目标与用户接管输入是两件独立的事。

```text
┌───────────────────────────────┐
│ 对话：活动徽标，由用户打开     │
├───────────────────────────────┤
│ 主桌面 │ 匿名 A / 页面 │ 匿名 B│
├───────────────────────────────┤
│ 只读观看           [接管操作] │
└───────────────┬───────────────┘
                │ 当前 generation
┌───────────────▼───────────────┐
│ Computer owner：单一输入权限  │
│ 观看互不干扰；接管暂停 Agent  │
└───────────────────────────────┘
```

Computer driver 拥有临时人工操作权限。接管先阻止新的 Agent 操作，等待已发操作结束并释放按住的输入，再允许人工输入。另一观看者不会自动取得权限；操作连接断开时先释放输入再恢复 Agent。切换目标和关闭面板释放接管。没有新的权限持久化状态；服务重启不恢复人工操作权限。

暂停不保证外部调用无限存活：上游取消或断开仍执行现有取消和清理协议，并给出明确失败，不伪造完成。浏览器 Context 继续遵守 Turn 的关闭规则。主 profile、既有消息和历史附件不由显示路径写入或裁切。

## 理由与代价

复制整台桌面会复制身份与生命周期，仍不能解决同一桌面的鼠标冲突。只增加前端标签不能修复 primary 踢人。用观看者队列抢 primary 则继续把观看误当操作。保留 H.264 桌面输入与画面，匿名页面使用真实页面画面和 CDP 输入。

第一版 Computer Agent 操作整体暂停，避免无法分类的通用 CDP 调用绕过人工接管。它不承诺隔离同一操作系统里任意外部程序产生的输入。将来有多个独立 Agent 操作 owner 时，需要重新评估权限粒度，不能按标签外观推断输入已隔离。

## 验收

两个独立浏览器观看主桌面持续收到画面；观看点击不产生输入；明确接管后输入生效，第二位观看者保持画面且不能抢占。匿名 A/B 具有真实独立身份、页面和画面；关闭后目标消失。移动端活动后聊天继续可用，关闭工具区后新活动不重新展开。隔离 E2E 和生产部署分别记录，开 PR 不代表 hua-home 已更新。
