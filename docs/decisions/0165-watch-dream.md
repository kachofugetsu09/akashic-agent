# 0165 值班：见闻和记忆分开，每天单独一轮整理记忆

状态：proposed / implemented for review

## 背景

读了线上的记忆：39 个专题全是按地方或事情分的，最大的一份每行一个地方，后面跟一串"某天几点看到某个数"；同一个数在两份专题里各记一次、还对不上；把几处放在一起才看得出的认识，全部加起来只有三四句；便签里一条猜测都没有。它在记"最后一次看到了什么"，没有在写"这个人是什么样"。

原因在提示词：

- 让它把去过的地方整理成专题时，要求每处写"上次哪天看到了什么"，记忆的骨架就成了探访记录。
- 要它把看到的东西带日期补进专题的话出现了五处，要它把几处放在一起说的只有一句。
- 猜测只许留便签，印证了才许进记忆。它学到的是记读数安全、下判断有风险。
- 整理记忆只是每日复盘七件事里的半句，复盘还要纠正值班员、探访、接来源、收尾对话。

对照了两份做法：一份把按天追加的日志和提炼后的记忆分成两层，由一轮只做这一件事的后台回合从日志里合并、删掉被推翻的、修剪索引；另一份给了一条经验：记忆只放查不回来的东西，查得到的只留去处。

## 决定

1. 新增见闻 `watch/journal/日期.md`，由后台回合自己追加：在哪、几点、看到了什么。各处的读数、清单、当天的内容记在这里。
2. 记忆专题只留查不回来的：他说过的话、对他这个人的认识、一条路是怎么走通的。提示词里五处"看到的补进专题"都改成记进见闻；去过的地方那份专题每处只写做什么、怎么进去、接没接成来源，哪天去过由足迹记。
3. 每日复盘跑完的当天，单独再跑一轮整理记忆（会话名带 `dream`，足迹里记作"整理记忆"）。它不带开口和办事的那段说明，只读不查，做六件事：读现有记忆；翻上次以来的见闻、时间线、足迹和对话；重写一份主语是用户本人的专题，每句带依据，只有一处依据的标明是猜的；把专题里再看一眼就能知道的读数挪进见闻、合并重复、改掉被推翻的；保持 MEMORY.md 只放明说和印证过的事；把他这阵子在意的事在嘱托的「留意」里各留一行，让值班员用得上。
4. 每日复盘不再负责综合：用户明说要记住的话仍然当场写进 MEMORY.md，其余看到的、想到的记进见闻。
5. 聊天时的提示里加一句：以前某天的数或记录到见闻里搜。

## 已知限制

- 见闻靠它自己记，不记就没有；系统只在足迹里记它去过哪。
- 猜测现在会进专题（标明是猜的），主对话里的它读得到，可能把猜的当真说出来。MEMORY.md 和值班员不受影响。
- 整理时把读数从专题挪进见闻靠它照做；挪漏了，那个数就只剩事件和账本里的原始记录。
- 每天多一轮主模型的后台回合。复盘没跑成的那天不整理；整理失败当天不重试。
- 见闻不清理。
