# 0116 · 常驻 Markdown 档案超额后自动剪枝

- 状态：accepted
- 日期：2026-10-13
- 关联条款：MEM-001～MEM-004、MEM-012、MEM-014
- 勘误：0052 的自动写入仅来自 checkpoint 限制，不再排除既有档案的容量维护。

## 决定与理由

维护者明确要求超额后由 agent 判断条目重要性，压缩或舍弃较低价值内容，让线上自行恢复；仅拒绝新草稿会让后续学习反复失败。继续使用 `MEMORY.md` 和原有章节、文档身份，不要求先改名为 `PROFILE.md`。

Markdown owner 在跟随唤醒时检查已有档案，在提炼的内存副本上检查新增结果。超额才调用模型；按长期价值压缩、合并或舍弃条目，目标为约八成配额，提交前必须满足硬配额。未超额章节和其他手写章节不属于剪枝范围。

```text
┌─────────────────────────────┐
│ 当前档案 / 本批提炼后的副本  │
└─────────────┬───────────────┘
              ▼ 超额
┌─────────────────────────────┐
│ 模型选择 prune / merge 操作  │
│ 原文、章节与最终配额校验     │
└─────────────┬───────────────┘
              ▼
┌─────────────────────────────┐
│ draft → 写前副本 → 当前文件  │
│ applied / 冲突 / 可见失败    │
└─────────────────────────────┘
```

保留旧事实的单纯移入 topics 不是默认策略：它无法完成维护者明确授权的价值筛选。也不按字符串尾部直接截断；合法结构不能替代语义压缩。模型判断可能有误，这是自动遗忘的代价；逐次写前副本和操作 receipt 提供恢复依据，且不删除来源 Message。

普通提炼仍须引用真实消息；容量维护只解释已有条目，不借剪枝制造新事实。`prune` 引用一条旧原文，带 `line` 时压缩，省略时舍弃；`merge` 继续要求至少两条旧原文。维护操作只由超额校验路径接纳，普通提炼不能申请此权限。

## 状态与失败

MEMORY/SELF 由 Markdown owner 原位发布，剪枝允许其正文减少。draft、写前副本和 applied receipt 正常只增加，不自动清理。Session、Akasha、topics 和其他文件不获得任何减少授权。
模型等待期间不持文件提交锁；提交时叠加到当前内容，旧条目被改写时遵循原冲突协议。模型输出不合格时先要求修正，持续失败或可重试文件冲突交给 follower 延迟重试。原生工具与外部编辑器仍不参与后台锁，既有并发覆盖限制不因此消失。

验收必须从真实插件和模型边界触发：非法草稿不写入、已有档案超额、提炼新增导致超额、故障重试、写前副本及未涉及文件保全；正式部署另外核对一次真实超额触发与 receipt。若将来要求所有事实永久保留，应重新评估自动遗忘并改为显式归档策略。
