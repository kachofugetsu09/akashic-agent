# 0116 · 常驻 Markdown 档案超额后自动剪枝

- 状态：accepted
- 日期：2026-10-13
- 关联条款：MEM-001～MEM-004、MEM-012、MEM-014
- 勘误：0052 的自动写入仅来自 checkpoint 限制，不再排除既有档案的容量维护。

## 决定与理由

维护者明确要求超额后由 agent 判断条目重要性，压缩或舍弃较低价值内容，让线上自行恢复；仅拒绝新草稿会让后续学习反复失败。继续使用 `MEMORY.md` 和原有章节、文档身份，不要求先改名为 `PROFILE.md`。

Markdown owner 在跟随唤醒时检查已有档案，在提炼的内存副本上检查新增结果。超额才调用模型；按长期价值压缩、合并或舍弃条目，目标为约八成配额，提交前必须满足硬配额。未超额章节和其他手写章节不属于剪枝范围。

```text
┌─────────────────────────────┐
│ 当前档案 / 本批提炼后的副本  │
└─────────────┬───────────────┘
              ▼ 超额
┌─────────────────────────────┐
│ 模型选择 prune/merge/demote  │
│ 原文、章节与最终配额校验     │
└─────────────┬───────────────┘
              ▼
┌─────────────────────────────┐
│ draft → 写前副本 → 当前文件  │
│ applied / 冲突 / 可见失败    │
└─────────────────────────────┘
```

超额维护优先完成价值筛选，同时支持用 `demote` 将 `MEMORY.md` 中属于具体工具、项目或设备的细碎条目下沉到 `topics/`，不再因配额紧张一律丢弃长尾细节；定期整理（consolidate / Dreaming）除 `merge` 外还支持 `prune`（精简冗长单条或修复失效的 `[[slug]]` 链接）、`demote` 与 `promote`（将跨对话普遍适用的核心原则从 `topics/` 上浮到 `MEMORY.md`）。也不按字符串尾部直接截断；合法结构不能替代语义压缩。模型判断可能有误，这是自动维护的代价；逐次写前副本和操作 receipt 提供恢复依据，且不删除来源 Message。

普通提炼仍须引用真实消息；容量维护与定期整理只解释已有条目，不借维护制造新事实。`prune` 引用一条旧原文，带 `line` 时压缩，省略时舍弃（未超额整理禁止对 `MEMORY.md` 省略 `line`，且不得清空主题文件）；`merge` 继续要求至少两条旧原文；`demote` 与 `promote` 在 `MEMORY.md` 和可写 `topics/` 之间迁移条目。`markdown-profile-writes.db` 同时维护条目级时间戳 `entry_timestamps`（维护性改写、合并与升降级继承原条目时间戳），供浮现提示与矛盾整理判断真实新旧。维护操作只由超额剪枝或定期整理校验路径接纳，普通提炼不能申请此权限。

## 状态与失败

MEMORY/SELF 由 Markdown owner 原位发布，剪枝允许其正文减少。draft、写前副本和 applied receipt 正常只增加，不自动清理。Session、Akasha、topics 和其他文件不获得任何减少授权。
模型等待期间不持文件提交锁；提交时叠加到当前内容，旧条目被改写时遵循原冲突协议。模型输出不合格时先要求修正，持续失败或可重试文件冲突交给 follower 延迟重试。原生工具与外部编辑器仍不参与后台锁，既有并发覆盖限制不因此消失。

验收必须从真实插件和模型边界触发：非法草稿不写入、已有档案超额、提炼新增导致超额、故障重试、写前副本及未涉及文件保全；正式部署另外核对一次真实超额触发与 receipt。若将来要求所有事实永久保留，应重新评估自动遗忘并改为显式归档策略。
