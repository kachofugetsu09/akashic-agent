# 0129 · 模型只留全局默认，插件在自己的设置里选模型

- 状态：proposed / implemented for review
- 日期：2026-10-22
- 关联：RUN-010；替代 models 的 default / agent / fast / vision 四角色

## 背景

models 把聊天模型分成 default、agent、fast、vision 四个角色。这四个名字是一个封闭集合，硬编码在四处：
`store.MODEL_ROLES`、数据库 CHECK、设置 HTTP 的 Literal、前端 `module.js`。
插件只能借用其中一个，实际用法也和名字对不上：

- fast 只有会话标题在用，设置页却写着「总结提炼、分类打标与后台小任务」；
- agent 只给对话主回合用，压缩、记忆整理和主动消息走的是 default，用户猜不出改哪个会影响哪里；
- 子任务、外置插件（如 github-watch）没有地方选模型；
- 看图是 `_select_chat_models` 里的特判。

## 决定

1. **models 只管注册和全局默认。** 聊天绑定只剩 `default`；旧库里 fast/agent/vision 的行不再读取，原样保留以便回滚。
2. **插件在自己的配置里声明模型选择。** 配置字段类型是 `ModelChoice`，三选一：
   - 跟随默认模型；
   - 跟随当前对话（本次执行冻结的会话选择；不在对话里时等于默认）；
   - 指定一个已注册模型及思考强度。
3. **每个用途用 `ModelUse` 声明业务差异，models 统一执行。** `ModelUse` 包含：
   - `use_id`：记进调用出处（`descriptor.role`）；
   - `follows`：允许的跟随方式；
   - `needs`：模型必须具备的能力，`image` 或 `context_window`。

   指定的模型被删除、停用、连接不可用或不满足 `needs` 时回到默认模型；默认模型也不满足时明确失败，并提示去该插件设置里指定模型。
4. **两条取用路径：**
   - `execution.use(use, choice)`：在本次执行里取模型，连接按需追加进执行的驱动作用域，随执行一起关闭；
   - `chat_models.resolve(use, choice, session)`：把选择解析成交给另一回合的 `ChatModelSelection`，经 `model.selection` 进入那一回合。子任务、主动消息走这条。
     「跟随对话」用调用方从所属对话读到的选择（`MODEL_SELECTION.read`/`read_saved`），不从执行上下文推断：
     工具的 prepare 不在会话执行的上下文里，验收时靠上下文推断的版本让子任务落回了默认模型。
5. **设置页共用 `ModelField`。** 候选由 `ModelUse.options` 从 models 目录给出：只列可用、满足能力的模型，并标出默认模型是否够用。插件只需写一行字段和一行 `model_options`。

## 各插件的业务含义

| 插件 | 可选 | 默认 | 能力门槛 | 说明 |
| --- | --- | --- | --- | --- |
| 对话（reply） | 会话里的模型胶囊 | 默认模型 | — | 不加插件设置，主模型就是会话选择或默认模型 |
| 上下文压缩 | 跟随对话 / 默认 / 指定 | 跟随对话 | 已确认窗口 | 摘要输入按摘要模型自己的窗口裁剪；回退目标是本轮模型与默认模型中与主选不同的那个；取不到配置的模型时用本轮模型并留提示，不阻断回复 |
| 看图 | 默认 / 指定 | 默认 | image | 跟随对话没有意义：对话模型能看图就不会调用这个工具 |
| 会话标题 | 默认 / 指定 | 默认 | — | 原 fast 的唯一用处 |
| 长期记忆 | 默认 / 指定 | 默认 | — | 后台提炼、合并、精简 |
| 子任务 | 跟随对话 / 默认 / 指定 | 跟随对话 | — | 在父调用的 prepare 里解析并写进请求，恢复时不重选 |
| 主动联系（wake） | 跟随对话 / 默认 / 指定 | 跟随对话 | — | 跟随对话 = 沿用接收对话保存的选择，与改动前一致 |

## 取舍

- **旧角色不迁移进插件配置。** models 不能也不该改写别的插件的配置。
  本机所有实例只绑了 default（只读核对过各实例的 `model-registry.sqlite3`），所以实际损失只在单独配过 agent/fast/vision 的实例上：
  - 对话改用 default；
  - 看图在 default 不能看图时会提示去「看图」设置里选模型。

  旧行保留，回滚到旧版本即恢复。
- **子任务默认改为跟随对话。** 改动前子任务跑在独立 Task 里，读不到父回合的选择，实际总是用 agent/default。
  现在用户在输入框换了模型，子任务也会跟着换。想省钱可以在子任务设置里改回「跟随默认」或指定模型。
- **执行中途追加连接**：
  - 会话执行在入口只打开主模型的连接；压缩、看图需要别的模型时，在同一执行的驱动作用域里追加并登记关闭 Effect。
  - 冻结的是目录 revision，追加连接不会读到新目录。
  - 驱动注册取追加时刻的注册，入口和追加之间驱动插件热更新的话，两者可能来自不同的驱动代次。
  - 与「入口一次性冻结全部角色」相比，未配置的角色不再在每轮入口白开连接。
- **binding_id 的命名空间按各自驱动计算。** 之前主模型的命名空间由整组角色的驱动决定，会因为别的角色改配置而变；现在只取决于自己的驱动。
- **外置插件**（如 github-watch）用同一个 `ModelChoice` + `resolve` 就能接入，本次只改内置插件。
