# 0093 匿名浏览器可复用，脚本错误不丢进度

- 状态：proposed（维护者要求改善 Agent 完成任务的流畅度并提交 PR）
- 日期：2026-10-06
- 关联：PLG-017、0084、0092

## 背景与决定

旧实现把任意工具异常当作 Session 中断，找不到元素和变量重复声明也会清掉所有匿名页面。
每个匿名 SDK 又返回相同的 ID `1`，按 ID 找回时误选主浏览器。现场任务因这些行为反复重建。

匿名实例返回实际 Context 的稳定 ID，`get` 和 `list` 使用同一实例；参考 SDK 的内部 ID
留在协议 adapter 内，不修改 SDK 或复制其对象状态。关闭或过期 ID 明确失败。

```text
创建 → 同一 Turn 内按 ID 复用 → 继续观察并操作
           ├─ 脚本报错、结算成功 → 保留页面与绑定
           ├─ 闲置 10 分钟       → 回收并明确报告
           └─ 取消或清理不确定   → 原有中断协议
```

只有 worker 明确报告脚本已结束，且 supervisor drain 和输入释放都成功，才保留绑定。
不按错误文字猜测能否恢复。调用取消、超时、worker 退出和结算 hook 失败仍重置；输入
释放不确定时停止 workload，不启动第二个 writer。外部已提交效果不因脚本失败而回滚。

每份匿名 Context 独立计时，创建或操作完成后开始 10 分钟闲置期限。正在执行的 RPC 与
人工接管持有实例；纯观看、截图和目录轮询不刷新期限。回收会移除 service hook 和显示
目标。Turn 结束仍立即关闭，不跨 Turn 借用身份或页面。最后一个实例释放临时 headless
进程及其数据。既有消息、附件和个人 profile 不由该协议改写。

## 理由与验收

单纯延长 Turn 结束后的存活期无法解决错误清理和错误 ID，还会延长临时身份生命周期。
无限保留则容易占满八个名额。采用可复用的 Turn 实例，加有限的闲置回收。

真实 Chromium 验证：脚本与选择器错误后页面和绑定可继续使用；两个匿名 ID 不同且
找回正确实例；闲置实例被回收，活跃操作与人工接管不被回收；过期 ID 明确失败；
Turn 结束和取消继续释放资源。生产观察与隔离验证分别记录。
