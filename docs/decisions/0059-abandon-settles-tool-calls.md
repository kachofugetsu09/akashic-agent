# 0059 · 明确放弃结算工具调用，不等待物理清理

- 状态：accepted
- 日期：2026-09-07
- 关联条款：RUN-003、RUN-008、SES-003～SES-005、SH-002
- 调整：[Message/plugins 设计](../design/0902-reviewed-v4.md) 第 7.4 节原先等待真实结果或 unknown 的 abandon 语义

## 背景与决定

原回复链在来源取消后一直等待工具和 Shell 清理，不能及时开始新工作。维护者明确批准只改变 `Control.abandon`；暂停、恢复和普通新输入继续沿用原路径。

工具回执由 Tools 独占。来源只接纳控制、撤销旧回复提交权，不扫描工具或改写其回执。Tools 从日志恢复和消费被放弃调用；已提交结果保留，未启动的追加 denied，已启动但没有结果的追加 interrupted。结果与回执同事务提交，迟到返回只能读取这一个终态。

```text
┌ 来源：追加 Control.abandon，撤销旧回复提交权 ┐
└────────────────────┬───────────────────────┘
                     ▼
┌ Tools：唯一结果 + 回执 → 协作取消原效果 Task ┐
└──────────┬────────────────────┬────────────┘
           ▼                    ▼
┌ 旧等待者退出，新回复可开始 ┐  ┌ 原效果与清理继续持有资源 ┐
└──────────────────────────┘  │ 实际退出后释放重启许可   │
                              └────────────────────────┘
```

## 理由与影响

等待超时不证明远端失败，取消协程也不保证外部效果撤销。interrupted 明确记录停止等待，不授权自动重跑。先提交终态再发取消信号，无需根据事件循环速度猜测一个“已经完成但还未提交”的结果；取消合作期不成为消息语义。

prepare 之前增加 requested 回执，用于固定请求与结果消息身份。已有 prepared/started/done 继续按原版本读取，不批量修改旧回执。默认结果身份有一个公共生成函数；自定义结果身份从既有回执恢复，普通调用仍不能更换已固定目的地。旧回执没有保存 `reply_id` 时，只在原 request hash 与默认结果身份精确匹配，或 done 结果指针保存了真实 message ID 时恢复。旧 prepared/started 使用自定义身份却未保存映射时，hash 无法逆推出身份；Tools 保留原回执、记录 `legacy_tool_reply_identity` Incident 并继续结算其他调用，不猜测身份或重跑效果。

效果和 Shell 清理由独立 Task 保留 generation 与必要的 child permit。新 Shell binding 保存分区标记，以最近的 abandon 消息区分旧新进程集合；同段的 PTY 续接不受影响。旧无标记归档维持原释放接口。只靠把旧清理放到后台而仍共用整个 source owner 会误杀新进程，因此不采用。

## 持久化与恢复

本改动只追加 Control/ToolResult，并由 Tools 原位推进自身回执到 done；不改写任何旧消息、调用参数、binding 或归档。没有自动减少协议，没有新增 SQL 表或迁移。进程重启由日志重新识别被放弃调用，不查询或重发其外部效果；物理进程恢复仍由现有宿主 owner 负责。

恢复保留完整 Session DB、owner_records 与实际绑定/归档。本 PR 不改正式 workspace，不触发部署；源码恢复点是实施前栈顶。若已经运行新版数据，回退程序必须能够读取 requested/interrupted，不能假称回退源码已回滚外部效果。

## 验收

- 不响应取消的工具尚未退出时，新回复可以完成；第二个未开始工具不能执行。
- 已提交真实结果保持不变，interrupted 之后的迟到返回不追加第二条结果，也不唤醒新推理。
- 启动追赶覆盖未开始和 started 回执，即使后续工作已经完成也不漏结算；其他 source 不受影响。
- 结算事务失败不留下半条结果，也不先取消效果。
- 旧 Shell 清理被阻塞时新进程可运行；旧清理结束不杀新进程，重启许可保留到真实清理结束。
- 暂停、新输入和未知效果的现有回归保持通过；暂停后再放弃可以释放清理等待。
