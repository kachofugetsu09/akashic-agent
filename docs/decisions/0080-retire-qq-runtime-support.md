## 背景与决定

维护者明确要求移除全部 QQ 运行支持，包括旧 NcatBot Channel 和独立 OneBot Sender。
删除两个插件及其设置、引导源码和随插件分发的前端产物，从默认安装清单移除它们。
删除 NcatBot 直接依赖、只由它引入的 psutil/qrcode 锁记录和 NapCat 部署示例。
其他旧锁记录保持，避免本次清理连带改变无关依赖。

```text
┌─────────────────────────┐
│ 默认安装 / 源码插件发现  │
└────────────┬────────────┘
             ▼
┌─────────────────────────┐
│ 保留渠道与 Sender 插件  │
│ 不再包含 QQ 接入与发送  │
└─────────────────────────┘
```

## 影响与状态边界

- QQ 消息接收、发送、群过滤、设置与引导不再提供；不添加兼容 facade。
- 旧渠道配置迁移命令只处理 Telegram，不再创建 QQ plugin-data，也不删除旧 QQ 配置。
- 现有 QQ 会话、Message、附件、凭据、plugin-data、安装 cache 与代码归档全部保留。
  本改动不增加、更新、逻辑失效或物理减少这些正式状态；各原 owner 继续拥有它们。
- 已安装实例的旧选择不会因源码删除自动换代；正式卸载、发布、旧数据删除另行授权。
  本次没有重启服务、连接 provider 或发送消息。
- 保留旧 config.yaml 与 NapCat runtime 的忽略规则，避免遗留登录数据被误加入 Git；交流群入口与邮箱保留。
- 设计与验收中的 QQ 记录保留为历史证据，不能作为现行支持合同。

## 验收与恢复

源码发现和默认安装清单均不含 QQ 插件；设置与引导无法再由这两个插件贡献。
剩余 Telegram 配置迁移在一次性目录核对，旧 QQ 字段逐项保留。
概念基线与静态检查的执行结果由交付报告记录，不代替生产换代证据。
恢复点是变更基线 `ef99aaef` 与 `/tmp/akashic-remove-qq-before-20260928.tar`。
源码恢复不代表已安装状态或正式业务数据的恢复。
