# 0083 · 缩短流程，保留设计意图和行为证据

- 状态：accepted
- 日期：2026-10-01
- 关联条款：WBK、GOV-001～GOV-004、BAK-001、TST-001～TST-006
- supersedes：原九阶段流程、强制 Terra/xhigh 与 agent 概念 Gate、change-intent 表格及 checker 待办、单测新增例外、无差别文件备份；部分替代 [0002](0002-context-reduction-is-a-nondestructive-projection.md) 的验收实施机制，补充 [0074](0074-deployment-policy-belongs-to-operator.md) 的备份选择。

## 背景

上下文事故把“缩小模型输入”实现成删除窗口外消息，连验收预期也跟着改变。教训是保护用户意图、数据边界和窄接口，而不是要求更多表格或另一个模型签字。原流程在阅读、合同、评审和 PR 中重复记录同一事实，专项规则挤进通用入口，仍可能掩盖一条危险的数据变化。

维护者明确要求亲自做架构与概念评审、禁止编写单测、限制每张 PR 新增量、按实际数据风险尽量少备份，同时保存可复用的设计理由。

## 决定与理由

1. 执行流程只保留理解边界、实现验证、交付。每个任务必读项目设计原则，按行为与状态读取相关条款、有效 decision 和真实实现。高风险改动在开工说明中写出改变、保持、依据和验证；不重复填表。
2. 取消强制 agent 概念评审、指定模型与审查回执，由维护者判断设计。执行者仍需理解并遵守现行设计，不能把“没有 Gate”解释为可自行改变受保护语义。
3. 禁止新增或改写单测，包含原概念回归例外；真实运行、集成场景或 E2E 观察目标和受保护结果，预期来自已批准合同。既有测试与 CI 保留，本地按改动做相关检查，不重复整套；本决策不授权降低既有断言。
4. PR 先讲问题、结果、理由和实际验证。默认新增约 500 行以内，删除不限；较大任务按完整行为拆 stacked PR，不能用删除抵消新增。行数限制降低阅读负担，不替代高风险语义说明。
5. 源码、文档和纯前端更新不额外备份。正式操作可能破坏无法可靠重建的数据时，先备份受影响部分及必要关联；部署按完整目标版本和待迁移判断，不只看最后一张 PR。发布器的可选全状态备份行为不变。
6. PR 保存本次取舍；可复用选择进入 decisions，说明适用条件、重要替代方案与重议条件。执行手册引用理由，历史记录保留并标注被替代范围，不成为第二份现行流程。

## 没有采用的方案与代价

- 只留下“实现、测试、提 PR”：缺少共同语义，可能重演窗口删除事故。因此保留短的必读原则和相关决定，而非只保留工具命令。
- 用单测全绿或另一模型通过代替意图核对：实现与断言可能同错，审查也不授予语义变更权限。因此维护者评审与真实结果证据各自承担职责。
- 每次全状态备份：把纯代码更新变成大数据复制与停机，备份也不能证明修改被授权。因此按实际不可恢复风险选择范围；代价是部署者要核对写入和恢复边界。
- 每个修改都新建 ADR、完整风险表或 E2E 套件：增加平行事实和维护负担。普通局部理由保留在 PR，专项内容仅在命中时展开。

PR 表达参考 Redis 的[贡献指南](https://github.com/redis/redis/discussions/11127)和实际正文：[模块列表增长唤醒](https://github.com/redis/redis/pull/15876)以短段落说明触发与修复边界；[TLS 接口替换](https://github.com/redis/redis/pull/15227)说明失败条件和关键兼容取舍。借鉴其因果说明，不移植其测试政策或自动生成的附加摘要。

## 影响与验收

仅改变协作合同与文档；消息只追加、插件边界、数据授权和运行语义保持。CI、测试、发布器和正式数据不在本次改动范围。

文档验收检查链接、现行规则冲突及代表任务的阅读路径：窗口缩减须找到非破坏性投影与重开回读；纯前端修改不触发数据备份；不可重建数据迁移须核对写入及局部恢复；大改动须按依赖拆分，不能把数据删除藏进大量减行。

这些检查只证明文档一致、入口可达，不能证明未来 agent 一定理解。新流程的实际效果要从真实任务中的误解、遗漏和返工观察，不把文档通过称为行为等价证明。

## 何时重新考虑

若真实任务仍反复漏读同一边界，先改进该边界的入口、反例与接口权限；若约 500 行造成无意义中间层，由维护者判断合理拆分或具体例外。只有出现明确的新失败路径，才考虑增加针对性约束，不恢复一整套无差别关卡。
