# 0001 · 项目工作手册是协作共享现实

- 状态：superseded by [0033](0033-local-agent-instructions-are-not-project-documents.md)
- 日期：2026-07-16
- 关联条款：WBK-001～WBK-006、COM-001～COM-004、GOV-005

## 背景

Akashic Agent 的关键语义分散在维护者记忆、代码、普通测试、重构账本和旧会话中。新 agent 进入项目时只能自己补齐空白。多 agent 和多个 worktree 会把这种偏差放大：每个执行者从不同基线和不同材料出发，各自形成一份私有项目理解。

上下文窗口也不应装入全部历史。自动注入过时记忆会稀释当前事实，完全不提供历史又会迫使 agent 再次猜测。

## 决定

仓库采用版本化项目工作手册：

```text
┌───────────────┐
│ INDEX.md      │  每个新会话的阅读入口与路由
└───────┬───────┘
        ▼
┌───────────────┐
│ projectneed   │  长期需求和语义不变量
└───────┬───────┘
        │ 约束
        ▼
┌───────────────┐      ┌───────────────┐
│ AGENTS.md     │      │ decisions/    │
│ 协作纪律       │      │ 理由和勘误     │
└───────┬───────┘      └───────┬───────┘
        │                       │
        └──────────┬────────────┘
                   ▼
           ┌───────────────┐
           │ NOW.md        │  当前未完成事项
           └───────────────┘
```

新会话先读取 `INDEX.md`，再按索引渐进读取当前工作手册和真实实现。历史会话和记忆按明确主题查询，并用当前事实复核。执行者只加载任务相关材料；评审者可以展开全部相关证据。

## 理由

工作手册让核对成为开工流程，降低 agent 用假设填空的概率。条款 ID 提供稳定引用，避免每次转述都再次定义需求。`NOW.md` 采用完成即剔除的规则保持短小，决策记录保留推理和勘误，两者不会争夺同一个功能。

## 影响

- `AGENTS.md`、工作手册和核心设计文档必须进入版本控制。
- `INDEX.md` 是唯一默认入口；新增、移动或废弃文档时必须同步更新路由。
- worktree 开工和验收都要核对目标分支上的工作手册版本。
- 同一份权威文档同一时刻只有一个 owner 修改。
- 已完成事项从 `NOW.md` 删除，不能把热点文档变成周报。
- 旧记忆不自动拥有高于当前文档和代码的优先级。

## 验收

- 新会话只读工作手册即可指出长期语义、当前接手点和相关决策入口。
- 任何需求都能用稳定 ID 引用，不需要复制大段原文。
- `NOW.md` 中没有已完成章节或历史流水账。
- 同一条长期需求只在 `projectneed.md` 有权威表述。
