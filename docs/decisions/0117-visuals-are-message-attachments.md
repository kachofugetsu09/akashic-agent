# 0117：可视化是普通消息附件

状态：提议，随本次 PR 栈评审。

## 问题与选择

聊天中的交互图需要独立更新参数，且不能因后续 token、回复完成或主题切换而丢失状态。
如果把图表协议加入 Loop，或让生成插件另调模型和维护第二套回复队列，会复制现有工具、消息和生命周期机制。

选择普通 `visuals` 插件：模型通过已有工具协议提交完整 HTML，插件预检成功后用 Ledger 的
`ARTIFACT_IMPORT` 发布不可变 JSON 文件，返回普通文本和 `artifact_ref`。
失败沿工具结果返回，模型可以在后续正常调用中修正；没有隐藏的模型调用、自动修复循环或新持久表。

```text
┌──────────────┐     ┌───────────────────┐     ┌────────────────────┐
│ 现有模型输出 │ ──▶ │ visuals 工具预检  │ ──▶ │ Ledger 不可变附件  │
└──────────────┘     └───────────────────┘     └─────────┬──────────┘
                                                       ▼
┌──────────────┐     ┌───────────────────┐     ┌────────────────────┐
│ 独立 iframe  │ ◀── │ 可选插件 renderer │ ◀── │ 通用附件插槽与链接 │
└──────────────┘     └───────────────────┘     └────────────────────┘
```

## 独立的事实与 owner

- Ledger 独占附件字节、身份和消息引用；插件只获得导入能力，不获得 SQL、消息 writer 或删除能力。
- Tools 独占调用和结果结算。若导入成功后进程中断，未被引用的附件也保留；未知结果不重新执行原调用。
- Visuals 独占 HTML 合同、预检浏览器和展示脚本。UI 通过可选子 Fiber 登记，缺席不阻止工具工作。
- 聊天宿主只提供 `message.attachment` 插槽和普通下载链接。匹配由 renderer 的 `accepts(block)` 决定。
  带附件的工具结果使前文、图、后文按 Message 顺序出现，不改持久消息顺序。
  同一图文回复的思考和已完成工具收进首段上方，正文与附件留在原位；仅末尾显示回复时间。
  这些规则适用于工具附件，不按可视化文件名建立宿主特例。
- 主题目录独占图表系列色 `--ak-chart-1` 至 `--ak-chart-6`，不借用成功、警告等状态颜色。

`akashic.visual.v1` 保存 `title`、`summary`、`html`，文件名后缀为 `.akashic-visual.json`。
宿主把真实消息来源和工具名传给附件插槽；Visuals 只认领 `render_visual` 的结果，
不能靠用户上传的文件名获得执行资格。没有调用记录的分页保留文字和下载，加载调用后才可执行。

生成内容使用原生 HTML、CSS 和 JavaScript，自行选择 SVG、Canvas 或 DOM。
原理、机制和参数试验由文档自己负责绘制、计算与交互；宿主只提供主题 token、标准排版和隔离容器。

数据图例外：frame 内联宿主自写的 `window.ak` 图表工具包，文档只给数据、选型与注释，
坐标、刻度、标签避让、窄屏重排和悬停/键盘读数由工具包负责。实测让模型自己手写坐标系时，
注释互相遮挡、窄屏文字缩到 6px、读数缺失是常态；交给成熟第三方库又会引入它的默认观感和体积。
工具包与 frame 同版本构建、同一份代码用于预检与展示，不是 iframe 外的脚本协议，也不读宿主数据。
输入不一致（长度不符、非有限数字）直接抛错，经预检交回模型修正。
图内文字与数字使用界面无衬线字 `--ak-type-ui`，它是系统字体而非第三种品牌字体；说明正文仍用阅读字体。
附件保存的是调用 `ak` 的 HTML，旧附件在新 frame 中按当时的 API 名称执行，因此 API 只增不改。

源文档只增加，不原位更新；参数、DOM 和 Canvas 是当前 iframe 的临时状态。
禁用、卸载、页面关闭或刷新可减少这些临时状态，没有任何附件自动减少协议。
恢复依靠原附件和既有 workspace 备份，按保存的 hash/size 核对；没有数据库迁移。

## 生命周期与限制

预检浏览器按插件 activation 复用，单调用创建独立无登录 context，最多两次并发，无等待队列。
预检有 20 秒预算，关闭 context 后等待检查任务退出；插件 effect 负责关闭浏览器和 driver。
禁用先关闭新接纳，已有作用域排空后才释放资源，不能用撤下 UI 冒充工具已停止。

客户端仅执行完整附件，每次挂载创建一个 iframe。后续消息和主题变化不重建它；禁用立即卸载，
重新启用从原文档的初始参数开始。没有刷新、跨设备或禁用后的任意 JavaScript 状态恢复承诺。
其他客户端即使没有 renderer，也能读取摘要并取得 JSON 源文件。

iframe 使用 opaque origin、`allow-scripts` sandbox 和 CSP；不给生成代码宿主查询、认证或执行桥。
预检拒绝全部网络。客户端 CSP 限制连接、资源、嵌套 frame 和表单，但这不是完整的出站网络隔离：
浏览器仍可能允许子 frame 自身导航。浏览器沙箱也不提供可证明的 CPU/内存配额。
字体使用共享阅读字体名称及本机 serif 回退，不从生成内容加载远程字体。
预检覆盖脚本错误、初始窄屏布局和滑块边界，不能证明任意脚本的数学正确性或所有后续交互。

如果后续产品要求可恢复的交互状态，先定义明确的数据合同与保存动作；不抓取任意 DOM/JS heap。
若要求严格网络与资源隔离，重新评估独立执行服务，不把 CSP 的局部限制描述成完整保证。
