# Mobile 媒体批次：B3、B5、B8、B10

本批次只补齐被动会话的媒体链路，不修改可靠性协议、插件 UI 或正式 workspace。实现继续复用现有 `AttachmentDraftStore → AttachmentUploadCoordinator → WebSocket` 和 `AttachmentDownloadCoordinator → MediaCacheStore`，没有增加第二套上传下载队列。

## 交付范围

### B3：一条消息多附件草稿

- 系统文档选择器仍可一次选择最多 10 个文件；Room 中每个附件独立保存 ID、SHA-256、offset 和状态。
- 输入区按附件逐项显示文件名、精确进度、已传输大小、等待连接、失败和完成状态。
- 失败项同时提供“重试”和“移除”，不再因显示重试而遮蔽移除动作。
- 失败和断线不会清空整批草稿；发送仍只在全部附件 ready 后使用现有一条 `message.send.media_refs` 提交。

### B5：图片查看器

- 点击已缓存图片进入整屏暗色查看面，不改变普通聊天的浅色基调。
- 支持双指缩放、单指平移、双击在 100%/200% 间切换，以及 50% 步进的无障碍缩放按钮；范围固定为 100%–400%。
- 左上角返回附着于查看器；保存和分享位于右上角，不占用聊天消息动作区。
- 分享继续复用 `FileProvider + ACTION_SEND`；保存使用系统 `CreateDocument`，在 IO dispatcher 从私有缓存复制到用户选择的 URI。

```text
┌──────────────── 图片查看器 ────────────────┐
│ ←  文件名                         保存  分享 │
│                                             │
│              双指缩放 / 拖动                │
│                                             │
│                 [−  150%  ＋]               │
└─────────────────────────────────────────────┘
```

### B8：大文件与后台传输

- `MobileConnectionService` 继续拥有 WebSocket 和同一传输协调器；切会话、退到后台和 Activity 重建不会更换传输 owner。
- 上传按服务端确认的 1 MiB 窗口推进 Room offset；断线或进程恢复时继续调用既有 `attachment.begin`，由服务端返回 `next_offset`。
- 10 MiB 以下沿原策略直接上传；10 MiB 及以上遇到计费网络时停在已确认 offset，等待用户点“使用当前网络继续”。
- 从计费网络回到非计费网络会撤销一次性许可并自动恢复持久化队列；许可不会写入长期配置。
- 会话输入区展示同一上传的暂停/后台状态；前台服务通知展示附件数、文件名和同一进度。

```text
系统文件 URI
    │ 私有复制 + SHA-256
    ▼
Room attachment_transfers ── confirmed offset ──┐
    │                                           │
    ├─ 非计费网络 / 小文件 ─────────────────────┤
    └─ 计费网络 + ≥10 MiB ── 用户确认 ─────────┤
                                                ▼
                                  既有 WebSocket coordinator
                                                │
                    ┌───────────────────────────┴──────────┐
                    ▼                                      ▼
              会话状态投影                         前台服务通知
```

## Material 3 设计复核

### Better UI

| Before | After |
| --- | --- |
| 失败附件只能重试，移除动作消失 | 同一附件行提供独立重试和 44 px 移除目标；动作仍附着于所属附件 |
| 图片仅有普通 Dialog 和原生关闭按钮 | 独立整屏查看任务面；返回、保存、分享固定在顶栏，缩放固定在底部 |
| 大文件进度只存在于附件行 | 仅在大文件传输时增加一个流程面板，并与系统通知共享真实 offset；未制造附件卡片墙 |
| 图标动作缺少一致按压反馈 | 查看器和传输主动作使用可中断的 `scale: 0.96`，触控目标不小于 44 px |

### Better Colors

| Before | After |
| --- | --- |
| 附件状态只有通用灰字和蓝色进度 | 正常/运行继续使用既有 primary；真实失败只使用 error；计费许可使用 primary container，不引入装饰性警告色 |

### Better Typography

| Before | After |
| --- | --- |

## Kill AI Slop 限定审查

扫描器对 `frontend/chat/src` 给出 55 个候选，但本批次新增代码只命中圆形图标按钮、整屏查看器和等宽进度数字：

- 圆形返回/保存/分享按钮是 Material 3 顶栏动作，44 px 形状表达动作类别，不是全页胶囊化。
- 图片查看器使用单一深色平面、无渐变、无辉光、无玻璃模糊；暗色只服务沉浸查看任务。
- 上传百分比和字节数使用等宽数字避免进度跳动；正文和控件继续使用系统无衬线字体。
- 大文件流程面板只在真实传输中出现，颜色表示传输许可状态；附件项没有再套独立卡片。

因此本批次没有确认的 AI 模板化问题，无需为了清除扫描器误报改变既有 Material 3 语义。扫描器报告中的 shimmer、tool、showcase 等命中均为本批次外的既有代码，留给各自功能批次处理。

## 独立 Review 修复

- 发送按钮同时要求全部草稿为 `ready`；Web 生成请求 ID，只有原生完成本地消息和 outbox 持久化并回调成功后才清空输入与引用。
- 附件仓库的 mutex 是删除和 `failed → pending` 的幂等所有者；快速重复操作只会成功一次，UI 在首个点击同步进入 busy。
- 上传协调器从持久化队列选择第一条 eligible 记录；计费网络暂停的大文件不会阻挡后续小文件，active 项在确认窗口暂停后立即继续调度。
- 图片查看器打开时创建同文档 history entry，并把所有权同步给原生 `BackHandler`；系统返回只执行 WebView `goBack()`，由 `popstate` 关闭查看器，不重建会话或改变滚动位置。

## Pixel 7 真机验收序列

主线程合并后使用隔离 gateway/workspace 执行；本 worktree 不操作 ADB 或正式 workspace。

1. 在 Wi-Fi 下选择图片、PDF、GIF 三个附件，确认三项各自进度；上传中切换会话再返回，进度不能归零。
2. 人为让其中一项上传失败，确认其他项不受影响；失败项可分别“重试”和“移除”，剩余附件仍能组成一条消息发送。
3. 选择 12–20 MiB 文件，在 Wi-Fi 开始后切到移动网络；最多完成当前 1 MiB 确认窗口后暂停，界面与通知显示相同百分比。
4. 点“使用当前网络继续”，退到桌面并锁屏 30 秒；通知进度继续增长，回应用后仍是同一 attachment ID 和 offset。
5. 上传完成后断网重连并发送，服务端消息只含一次每个 `media_ref`；下载文件 SHA-256 与原文件一致。
6. 打开已缓存图片：双指从 100% 放大到约 250%，单指平移，双击复位；系统返回和左上角返回都回到原消息滚动位置。
7. 点保存，系统文件选择器出现；保存后比较 SHA-256。点分享，系统 chooser 出现，接收应用只能读取这一个 `content://` URI。
8. 清理媒体缓存后再次打开旧消息，必须显示“缓存已清理/重试”，不能打开过期私有路径。

发布门结论必须同时满足：无重复 `media_ref`、断点 offset 不回退、文件 SHA-256 一致、系统 URI 授权不泄漏、前后台状态一致、logcat 无 `FATAL EXCEPTION`/WebView render crash。
