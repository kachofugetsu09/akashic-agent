# 2026-07-16 移动端可靠性批次

本批覆盖 A2、A4、A7、A9 和 A10。目标是在不增加第二套消息协议的前提下，把既有 outbox、canonical 合并、Room 投影和最终消息通知组织成完整的移动端体验。

## 实现范围

### A2：乱序合并与每会话阅读位置

- 继续复用 `MessageDao` 已有的 `serverSeq + createdAt` 合并顺序；本批没有新增消息排序协议。
- Room v5 新增 `conversation_read_states`，按会话保存最后已读时间、首个可见消息和相对视口偏移。
- WebView 用首个可见消息作为锚点，不保存脆弱的绝对 `scrollTop`；本地失败消息被服务端历史归位后仍能恢复到同一语义位置。
- 回到底部时才推进已读水位；首次进入旧会话只建立当前历史基线，不把全量历史误报为新未读。

### A4：可理解的待发送队列

- 复用消息投影中的 `pending` 状态，不新增 outbox 镜像或取消协议。
- 单条待发送消息继续只在消息下方显示状态；累计两条及以上时，composer 上沿出现可展开入口。
- 展开内容是同一主题区内的平面列表，显示预览和发送时间；队列恢复后入口自动消失。

### A7：会话抽屉信息补齐

- `ConversationDao.observeSummaries` 一次投影标题、最后消息、时间、未读数、Agent 运行态和阅读锚点。
- 抽屉保持平面列表；当前项使用 primary state layer，未读使用蓝色数字，运行态只使用一个无光晕的紫色点。
- 时间使用 tabular figures，预览单行截断；信息附着在所属会话，不增加独立状态卡片。

### A9：通知跳转与快捷回复

- 最终消息通知同时携带 `sessionId + messageId`；点击后先切换会话，再定位并点亮对应消息。
- 通知通过 Android `RemoteInput` 提供纯文本快捷回复，直接写入指定 mobile 会话的既有 outbox。
- 快捷回复不切换当前前台会话、不消费附件草稿，也不新增旁路发送协议。

### A10：可靠性发布门

- `verify-reliability-gate.sh` 串联 Web 状态测试、TypeScript 类型检查、Android unit test 和 instrumentation APK 编译。
- 所有 Gradle 任务通过 `/tmp/akashic-gradle.lock`、`--no-daemon --max-workers=1` 串行运行，避免并发构建引发 OOM。
- instrumentation 覆盖本地失败消息夹在服务端序列之间的顺序、持久化阅读水位、会话未读和 Room 4 → 5 迁移。

## Pixel 7 验收操作序列

1. 安装该分支 debug APK，使用隔离 workspace 配对；确认正式 workspace 未被写入。
2. 进入有至少 20 条消息的会话，滚到中段，记录顶部第一条可见消息；切到另一会话再返回，目标消息和相对位置应恢复。
3. 在中段等待 Agent 产生新回答；抽屉对应会话显示蓝色未读数，当前会话出现固定未读分隔；回到底部后两者清零。
4. 关闭 Wi-Fi，连续发送三条带不同短文本的消息；第一条只显示自身“待发送”，第二条开始 composer 上沿出现队列入口。
5. 展开队列，核对三条预览和时间；恢复 Wi-Fi，观察消息按创建时间落回对话且只发送一次，队列入口自动消失。
6. 在消息发送、服务端落库后和 ACK 前分别切断网络；每次恢复后核对：无重复用户消息、无重复 Agent Turn、无 event sequence gap。
7. 切到其他会话或退到桌面，触发一个最终回答通知；点击通知，必须进入正确会话并居中点亮该回答。
8. 再触发通知，在通知栏输入快捷回复；打开应用后核对文本只出现在通知所属会话，当前会话的附件草稿未被消费。
9. 杀掉应用进程后重新打开；重复步骤 2，确认 Room v5 阅读锚点仍然生效。
10. 保存截图、logcat 和本地 DB 查询结果；只有三者的 session/message identity 一致才通过本批真机门。
