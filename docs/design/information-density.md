# 信息密度判定

状态：proposed（2026-11-07 起试行）。规则落在 [frontend/design.md](../../frontend/design.md) §1.1；本文写依据、测量方法和阈值来源。

## 1. 要回答的问题

界面"挤"或"空"不是一个数。同一屏字很多可以很舒服（结论段落），字不多也可以很累（十几个同形状的过程行、三个各占一行的低频入口）。判定分三层，自上而下：

1. **拓扑**：每条信息该不该常驻、放在哪一层、默认展开还是收起。大多数密度问题出在这里，不在间距。
2. **度量**：同一份内容改前改后，用脚本量结构指标，防止"感觉更好"其实更乱。
3. **主观校准**：用户本人按固定问卷给 A/B 打分；度量与主观冲突时以主观为准，回头修阈值。

## 2. 依据

| 来源 | 取用的结论 |
|---|---|
| Krug《Don't Make Me Think》 | 页面要自明；删掉不帮任务的字（happy talk、说明性废话）；同一件事只给一条明显的路。 |
| Tullis 1983, *The Formatting of Alphanumeric Displays*（Human Factors 25） | 四项格式特征：整体密度、局部密度、分组、布局复杂度。搜索时间最强的预测因子是**分组的数量与大小**；整体密度在显示任务所需信息的前提下越低越好，用留白降低局部密度。 |
| Rosenholtz 等 2005/2007, Feature Congestion、Subband Entropy | 视觉杂乱可以从图像算出；JPEG 体积与 Feature Congestion 高度相关，可作廉价代理。 |
| Ström《UI Density》 | 视觉密度本身不可靠；要看**价值密度** = 用户得到的价值 ÷（花掉的时间 + 占用的空间），时间密度（等待、滚动）同样算成本。 |
| Lewis & Sauro 2024, *Measuring the Perceived Clutter of Websites*（PWCQ） | 杂乱感分"内容杂乱"和"设计杂乱"两维，五题即可稳定测量；杂乱主要拉低外观评价。 |
| NN/g 渐进披露、底部抽屉 | 高级、低频的信息放到二级界面；不要用层层点击换取首屏干净；浮层要有明确关闭与返回。 |
| Hoober 握持研究、WCAG 2.5.8 | 单手握持最常见、握法频繁切换，静态"拇指区"只是近似；触控目标 44pt/48dp，最小 24px。 |
| Tufte 数据墨水比 | 不承载信息的墨（重复标签、装饰框）先删。 |

## 3. 拓扑：每条信息先定三个属性

| 属性 | 取值 | 决定什么 |
|---|---|---|
| 频率 | 每次都看 / 有时看 / 很少 | 常驻、一步可达（折叠行、菜单、悬停工具栏）、二级页面 |
| 状态 | 常态 / 异常 | 常态不写字（成功、未开启、默认值）；异常冒泡到上一层，恢复后退回 |
| 范围 | 本段 / 本轮 / 本会话 / 账号 | 摆在哪一层：消息行、轮次摘要、标题行、侧栏或设置 |

由此得出的放置规则写在 design.md §1.1。手机上悬停不存在：靠悬停显现的信息必须有点按入口，不能只在桌面可达。

## 4. 度量

脚本：`scripts/ui-density/measure.mjs`（Playwright 打开页面、按步骤操作、每个状态输出一行 JSON；`density-metrics.mjs` 在每个 frame 里采集文字行框、图标与可操作控件，合并到 8px 网格）。

| 指标 | 含义 | 来源 |
|---|---|---|
| `taskDistance` | 最后一个问题气泡到其后第一段末条回复的距离（px） | 价值/时间密度 |
| `overallDensity` | 有墨的 8px 格 ÷ 全部格 | Tullis 整体密度 |
| `localDensity` | 每个有墨格周围 ±10 格（≈5° 视角）的墨迹占比均值 | Tullis 局部密度 |
| `groups`、`groupMedianCells` | 间隙 ≤16px 视为同组后的连通块个数与中位大小 | Tullis 分组（接近律） |
| `layoutEntropy` | 文字行左缘位置的取值熵（bit） | Tullis/Bonsiepe 布局复杂度 |
| `actions` | 视口内可操作控件数 | Hick |
| `touchUnder44`、`touchUnder24` | 短边 <44px 的控件占比、<24px 的个数 | Fitts、WCAG 2.5.8 |
| `duplicateActions` | 视口内读屏名相同的控件 | Krug：同一件事一条路 |
| `clutterBpp` | 视口截图 JPEG(q75) 每像素比特 | Rosenholtz 杂乱代理 |

用法：同一份内容（隔离实例 + 模拟模型真实发送，或 `serve-desktop-fixture.mjs`）在改前改后各跑一遍，桌面 1440×900 与手机 390×844 都跑。

## 5. 阈值（初版，待主观校准）

绝对门槛只给有依据的几条；其余指标只做同内容 A/B 比较。

| 规则 | 门槛 | 依据 |
|---|---|---|
| 落定轮次的问到答距离 | ≤ 视口高的 25%（桌面 225px、手机 211px） | 结论应在提问后的首屏；改前实测 580px / 620px |
| 同名重复动作 | 0 | Krug |
| 手机 <24px 控件 | 0 | WCAG 2.5.8 |
| A/B：分组数、`clutterBpp` | 改后不升；升了必须换来更短的问答距离 | Tullis、Rosenholtz |

参考区间（只作对照，不当门槛）：同一脚本的 JPEG 代理在竞品**首页**截图上，桌面 ChatGPT 0.29–0.31、Gemini 0.30–0.32、Grok 0.20–0.22、Le Chat 0.20、Perplexity 0.40；手机 0.37–0.70。本项目改前的生产首页桌面 0.35。对话页还没有可比的公开参照。

首批改动的实测（6 步排查的一轮，隔离实例）：

| | 问到答 | 分组数 | 分组中位 | bpp | 重复动作 |
|---|---|---|---|---|---|
| 桌面 改前 → 改后 | 580 → ≈110px | 18 → 12 | 9 → 46 | 0.341 → 0.272 | 5 → 0 |
| 手机 改前 → 改后 | 620 → 首屏 | 5 → 5 | 30 → 30 | 0.781 → 0.606 | 4 → 0 |

## 6. 主观校准

用户本人对 A/B 截图（或可点原型）逐对回答下列五题，1（完全不同意）到 5（完全同意）。内容杂乱两题、设计杂乱三题，仿 PWCQ 的两维结构改写为聊天产品：

1. 这一屏有很多我此刻不需要的信息。
2. 我得找一会儿才能看到想要的那句话（结论、状态、按钮）。
3. 这一屏看起来乱。
4. 东西挤在一起，分不清哪些是一组。
5. 同样的东西重复出现了好几次。

总分越低越好。A/B 的主观差与度量方向不一致时记下来，按差异修正阈值或加指标；累计十对以上再把第 5 节从"初版"改成正式门槛。

## 7. 已知限制

- 指标只看视口里看得见的东西，不看信息是否"找得到"；收得太深（多层点击）不会被度量惩罚，要靠拓扑规则与主观第 2 题兜住。
- 分组用固定 16px 间隙，对规则线、底色块分组不敏感。
- JPEG 代理受字体平滑、图片内容影响，只在同内容 A/B 时可比。
