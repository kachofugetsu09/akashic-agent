# Akasha：保持经历演化的成本优化

状态：实现、本地完整重建、串行复测和独立概念 Gate 已完成；未部署。源码基线 `adf1ff30`。本文记录实验边界，不把有限语料等价升级为所有输入上的证明。

## 目标与判断顺序

Akasha 的目标是让有出处的过去经历参与理解当前需要。一个输入既有表面对象，也有使它在此刻出现的语境。歌曲可以连到曾经辨认歌词的过程；睡眠、焦虑与面试可能属于同一段生活。不能先按话题把这种联系删掉，再用更整齐的列表宣布质量提升。

核心闭环可以写作 `S(t+1) = F(S(t), E(t), feedback(t))`：已经发生的经历塑造当前状态，当前的学习塑造未来。这里需要保留的不只是 top-k，还包括上下文、经验分布、惊奇度、关联竞争、抑制、记忆反馈、时间尺度与后续可塑性。单独查询临时计算 `R(S,q)`，不提交 `F`。

```text
┌───────────────────────┐
│ 已发布状态 S(t) + 新经历 │
└───────────┬───────────┘
            ▼
┌───────────────────────┐
│ 情境线索 → 扩散 → 情景补全│
└───────────┬───────────┘
            ▼ 提交经历
┌───────────────────────┐
│ 关联更新、反馈、时间与遗忘 │
└───────────┬───────────┘
            ▼ 完整校验与耐久发布
┌───────────────────────┐
│ S(t+1) 与消费进度一起前进 │
└───────────────────────┘
```

评价分为两层。机制层比较完整状态转移、全部历史召回和重启后的下一步；体验层将召回正文放回原 Session 前后各十条，分别判断联系是否成立、正文是否传达联系、此刻是否有用、呈现负担如何。未知关系保留为未知。相同正文、分数与顺序只能证明本次质量没有改变，不能证明旧结果都好。前后文帮助判断，不冒充引擎已经返回的内容。

用户偏好可以作为外层实验选择的反馈；本轮没有训练一个奖励模型，也没有用人工标签重写内部学习律。传统机器学习适合以后拟合成本或预测候选风险，不能替代历史证据与独立保留集，更不能用这些观察 query 训练后又把它们当泛化证明。

## 怎样约束“哲学不变”

令 `P` 把紧凑表示还原成旧实现的逻辑状态。希望满足的不是一个平均检索分数，而是：

- 初始状态对应：`P(S_new(0)) = S_old(0)`。
- 每次提交对应：`P(F_new(S,e,f)) = F_old(P(S),e,f)`。
- 每次查询对应：`R_new(S,q) = R_old(P(S),q)`，并且查询前后 `P(S)` 不变。
- 发布与恢复对应：恢复后的 `P(S)` 与发布前相同，消费进度与图同时前进。

若这些条件对所有可达状态成立，顺序归纳就能保证过去到未来的整个轨迹对应。本轮用不改变数值与次序的表示变换建立理由，再用完整历史、独立合成输入与故障场景查找反例。有限测试不能证明条件对所有状态成立，尤其分块数值依赖 BLAS 的规约选择，因此明确保留平台边界。

近似优化需要另设许可误差与体验评价，不能只用向量误差小或 top-k 重合率高冒充此合同。一个很小的阈值分歧可能改变后续关联竞争，使误差随经历传播。本轮没有让传统监督学习或 RL 去拟合并替换 `F`。

## 文献如何变成候选

| 抽象问题 | 一手来源 | 本次采用或拒绝的方向 |
|---|---|---|
| 显式记忆为什么是动态闭环？ | [Hippocampal Explicit Memory, §6](https://arxiv.org/html/2606.11245v1#S6) | 保留输入与既有记忆共同生成下一状态。它是立场论文，不是本系统更优的数学证明 |
| 怎样减少计算过程的内存搬运？ | [FlashAttention](https://arxiv.org/abs/2205.14135) | 借鉴分块与重算思想，删除合成向量缓存，限制混精度临时数组。没有移植 attention 算法 |
| 完整相似分数是否一定应该换索引？ | [To Index or Not to Index](https://arxiv.org/abs/1706.01449) | 先优化完整计算。ANN/top-k 即使保持命中，也可能改变尾部分布与未来学习，本轮不替换 |
| 动态稀疏图如何兼顾空间与更新？ | [Packed Compressed Sparse Row](https://people.csail.mit.edu/hjxu/papers/pcsr.pdf) | 采用紧凑数值列、复用邻接顺序，未引入整套 PCSR 或重编号逻辑身份 |
| 不可变值如何共享空间？ | [Enhanced Hash-Consing](https://arxiv.org/abs/1210.1611) | 每个图共享词项计数值，恢复时共享重复来源标签；没有全局常驻缓存 |
| 跨话题联系有什么认知依据？ | [Temporal Context Model](https://memory.psych.upenn.edu/files/pubs/HowaKaha02.pdf)、[Predictive Map](https://www.nature.com/articles/nn.4650) | 检查经历与状态转移；不把 Akasha 等同于这些模型，也不据此编造个人因果 |
| 怎样复用历史而保住一致快照？ | [SQLite backup](https://www.sqlite.org/backup.html)、[atomic commit](https://www.sqlite.org/atomiccommit.html) | 复制一致快照到私有文件，仅重写变化材料，保留原有完整校验和发布边界 |
| 数学相同是否必然逐位相同？ | [ExBLAS](https://github.com/riakymch/exblas) | 否。改变求和形状可能改变浮点规约；必须检查长期演化，而非只看单次误差小 |

这些文献提供可检验的假设。没有同条件的 Mem0、Zep 或其他系统任务对照，本轮不宣称 Akasha 从数学上或总体效果上优于它们。

## 实现与被拒绝的实验

- 特征池按需重算合成语境，直接分配目标矩阵；容量以 256 行增长。保留 float32 输入与原归一化舍入，语境运算保留 float64。
- 混精度矩阵乘法按行分块，短尾块并入前块。朴素分块在 56 项检查中有 14 项不一致；修订后同机 120 项逐位一致；随后扩展到 1～3072 维、容量边界的 672 项也逐位一致。不能承诺不同 BLAS、线程或架构逐位一致。
- 同宽 basin 批量做逐行运算，保持原事件输出顺序和 `math.log`。没有候选截断或改阈值。
- 图数值列与倒排表用紧凑可追加缓冲区；值精度、边遍历顺序和节点身份不变。第一次邻接复用误把 hub 数量当连续事件槽，状态对照拒绝了该候选；修订版保留空槽。
- 查询保存拓扑引用并在 `finally` 还原，避免为撤销临时容量再扫描一遍图。时钟同样沿原只读契约还原。
- 连续消费复用历史快照行。第一版私有文件逐行外键检查产生重复扫描，单次发布反而约 5.3 秒，已拒绝。当前在私有文件末尾统一核对全部外键。

没有量化、降维、ANN、学习率调整、主题过滤、历史正文裁切或推迟在线学习。输入正文、向量与 SessionDB 均保持原样。

## 连续快照的 owner 与恢复边界

唯一 writer 仍是 `MessageConsumer`，持有原 `WriterLease`。普通连续消费把上次已发布 `Consumption` 传给 writer；完整重建继续从空库写完整快照。复用的前提是旧 Turn、证据和召回不可变，旧事件只因图容量增长平移 hub 的运行时编号。该前提属于连续消费者，不用于任意状态导出。

| 对象 | 正常增加或更新 | 减少与恢复 |
|---|---|---|
| SessionDB / Message / 固定向量 | 本改动不写入 | 不删除、不迁移 |
| Turn / feedback / event evidence / recall 历史行 | 从新消费后缀追加；旧事件 hub 编号随容量平移 | 连续路径不删历史；原文件在替换前可恢复 |
| 图边、hub、时钟、context、burst、metadata | 在私有候选库中整批替换成当前内存状态 | 只删除候选文件内的旧派生表示；最终逻辑图仍含现行全部状态 |
| 已发布 Akasha 文件 | 校验完成 → file fsync → replace → directory fsync | 替换前失败保留旧文件；替换后失败可能已经发布新文件，重新读取磁盘状态恢复 |

只读事务先核对出处与配置，再用 SQLite backup 复制同一版本。候选连接关闭逐行外键检查以避免删除 hub 时重复扫描；CHECK/UNIQUE 仍执行，发布前必须通过完整 `foreign_key_check`。不在正式连接上关闭检查。候选失败可留下具名临时文件，沿用原恢复协议。

连续路径省略每次 VACUUM，空闲页可复用；磁盘文件布局和文件哈希允许不同，schema、全部行与逻辑状态须相同。完整重建仍 VACUUM。恢复不需要新版本 schema，旧程序仍可读取新文件。

## 验证与成本口径

本地冻结语料为 5619 个 Turn、42 个 Session、1024 维向量；冻结 SessionDB 约 946.58 MiB，已发布图约 16.72 MiB。没有访问或部署线上。本地完整重建原版与生产图有已有微小差异，因此候选对照固定的本地原版，不能称为逐位复现线上。

原版完整重建耗时 1194.51 秒，早期 B2 为 1115.03 秒，累计 H 为 680.62 秒，最终 J2 为 662.23 秒。三轮完整候选的数据库、逻辑状态及 11 个历史 query 的 150 个引擎命中与原版相同。最终数据库 SHA-256 为 `9841d7c37bf00f3f2b30f88556ee3a998277678e145df8714a2b3a6de4ad1ff4`，逻辑状态为 `81c1b948950bf2fa37e95dc9a3d1addb28c75fb05efa91e352710fa3d1703116`。测量期间存在其他诊断负载，此项是整轮观测，不是严格隔离的统计加速比。

完整重建在结尾执行完整 writer；连续复用路径另外通过真实最后一条学习和逐次恢复的合成场景验证，不能把前者冒充每一步都在线落盘的耗时。

272 条公开合成经历补充 remember/forget、长间隔、跨 Session、部分缺向量、9 个独立 query、16 次恢复，候选与原版摘要一致。每次增量发布与完整 writer 比较所有表和 schema。成功/失败查询不改耐久状态；file fsync、replace、directory fsync 故障均验证旧或新完整版本。

## 后台执行与因果顺序修复（2026-09-29）

本节记录后续修复；上文 #816 的表示、算法和耐久发布协议保持原样。
冷恢复不能占住 Core 事件循环，但每张图的学习仍必须满足
`S(t+1) = F(S(t), E(t), feedback(t))`。

```text
┌─ Core 事件循环：Web 请求、Probe、连接保活继续执行
│
└─ Akasha Task 持有本图锁与 binding，await 后台同步阶段
     └─ S(t) → 准备材料 → 学习 → 耐久发布 S(t+1)
                                      └─ 完成后才准备下一条经历
```

`MessageConsumer.load` 在后台按原 binding 和 `state.applied` 顺序恢复，
每条的 `previous` 只含已经完成的前缀。`consume` 继续固定日志上界、沿原顺序
补齐向量；材料准备、学习与发布作为同一个后台阶段完成后再处理下一条。
事件时间继续来自原始消息。查询与学习仍由 `MessageMemory` 的原串行锁保护：
`retrieve` 内部有临时时钟和拓扑，不能因“查询不学习”就并发共享同一实例。
显式查询仍固定已发布副本，按原身份保存、恢复实际 Recall。

`run_memory_job` 保留取消后先排空线程的规则。异步构造的消费者必须被调用方
接管，或在取消时显式关闭；不能在线程完成前释放 binding、图锁或 writer。
重建的最终校验、替换与回执作为一段后台工作排空，防止取消落在替换与回执之间。
失败后的恢复仍依赖完整磁盘状态；在线发布没有改成延后落盘。

验证使用 `tests/test_akasha_execution.py` 的受控线程事件：

- 卡住第 t 次发布，内存进度和磁盘进度按边界检查；t+1 的材料准备、同图查询
  和第二个消费者均等待。放行后观察到 `(previous, published) = (0,0), (1,1)`。
- 替换前或替换后发布失败，后继不得学习；不以回滚内存指针假装磁盘未变化。
- 恢复保持前缀顺序；连续取消和 provider 卸载等待真实 worker 结束。
- 构造、学习及重建发布期间取消，writer 不提前释放，完成的资源不泄漏，
  已发布重建仍有回执。
