# 侧栏项目开合与搜索基准

`measure-sidebar.mjs` 通过真实 UI 展开、折叠项目，搜索和清空会话列表。
完成条件来自真实项目、会话和置顶 API 的完整集合；空壳、占位和此前 DOM 快照都不作为目录真值。

```sh
node scripts/webui-performance/measure-sidebar.mjs \
  --url http://127.0.0.1:2236/ --browser /usr/bin/chromium \
  --auth /path/to/private-playwright-state.json \
  --output /tmp/sidebar-new --runs 3 --profiles lan,weak
```

从仓库根目录运行。无认证的隔离实例可省略 `--auth`；认证文件使用 Playwright storageState 格式，
脚本只复制 Cookie。输出目录必须不存在，权限为 0700；报告权限为 0600，内含真实会话标题和项目数据，
截图也可能含私人内容，不能直接作为公开 PR 附件。

## 输入与完成条件

- 每种设备新建浏览器上下文：1440/390px、CPU 1/4；预热字体、启动读取和 21 秒后台启动窗口。
  局部展开状态从默认值开始，置顶状态仍来自真实服务。
- LAN 为 20ms、100Mbps，弱网为 800ms、1Mbps；CDP 不模拟丢包或真实软键盘。
- 项目目录与置顶目录先加载完整。会话接口必须返回完整单页目录；出现分页游标就失败，
  不把未加载的会话当成不存在。每个设备单独保存 API 输入与摘要，目录变化不会被静默丢弃。
- 每轮逐项目展开、折叠，再做全匹配、窄匹配、无匹配搜索，每次搜索之后清空。
  项目内的完整标题集合、搜索匹配集合以及清空后的最近会话集合，都与 API 对照。
- 从真实 `pointerdown` 或 `input` 事件计时。`contentMs` 为正确集合和控件状态到齐后两帧；
  `settledMs` 再等待有限的 `DocumentTimeline` 动画与两帧。
- `nav-fade-top`、`nav-fade-bottom` 等滚动时间线依赖滚动位置，不会靠等待时钟结束；
  名称单独记录在 `scrollDrivenAnimations`。循环动画同样不充当结束时刻。
  普通展开、颜色和缩放过渡仍计入稳定时间，不关闭动画以获得更低分数。
- 请求开始、完成、HTTP 状态和错误单独记录。悬停预取与后台轮询可能与动作重叠，
  不能据此声称它们都是内容完成的依赖。

`complete` 只表示所有指定动作都已执行并通过内容与错误校验，**不表示 300ms 达标**。
失败样本和截图保留，进程非零退出；后续未执行动作不能算作通过。
使用 `settledMs` 检查 300ms 目标，同时保留正文时间，以区分内容成本和过渡成本。

## 执行主机目录是另一条读取路径

另一个只读筛选在真实页面完成 18 次目录表单读取。表单每次打开均读取最新状态；
两项固定目录检查和一项未绑定项目的目录浏览均返回 `available`。
正常网络的表单显示中位数约 59ms，最新结果约 110～127ms；
弱网表单显示仍约 59ms，最新结果约 885～910ms，动画稳定约 918～944ms。
浏览器每次打开发一次 `project.directory` 或 `directory.browse`，另有独立后台轮询。
这里不能把已知路径或表单外壳出现当作最新目录结果已经到齐。

这部分证据位于 `/home/huashen/.local/share/akashic-performance/20261031-sidebar/project-directory-screen-v2`，
为桌面正常 CPU 的三轮筛选，独立于上面的侧栏基准；没有创建项目或提交目录绑定。
