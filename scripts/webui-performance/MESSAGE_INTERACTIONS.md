# 消息操作配对测量

`compare-message-interactions.mjs` 比较同一真实隔离服务上的两份聊天制品。
覆盖长消息展开/折叠、引用/取消、放回输入框/清空、完整正文复制；窄屏另测操作栏显示/隐藏。
基准使用真实 HTTP、历史 API、WebSocket、React 组件和浏览器剪贴板，不替换接口响应。

## 运行

先在基线与候选源码中各运行 `npm run build:dashboard`、`npm run build:chat`，
把 `static/chat/` 分别复制到两个独立的制品目录。
记录两份源码提交、未提交补丁和构建环境；整个配对期间冻结制品。

在候选 checkout 启动一次性服务，使用尚不存在的 state 路径和空闲端口：

```sh
.venv/bin/python scripts/webui-performance/serve-startup-runtime.py \
  --state /tmp/message-check-state --port 24706 \
  --switch-session-messages 50 --sessions 20 --message-interactions
```

上例先生成 50 条富文本记录，再追加两条长消息目标。当前尾页请求为 `page_size=50`，
默认加载的是末尾 48 条富文本记录和两条目标消息，不能据此声称同时渲染了全部 52 条。
加载更早历史与更短会话须分别验证。

在另一个终端运行：

```sh
node scripts/webui-performance/compare-message-interactions.mjs \
  --state /tmp/message-check-state \
  --baseline /tmp/message-build-baseline \
  --candidate /tmp/message-build-candidate \
  --browser /usr/bin/chromium \
  --output /tmp/message-check-results --runs 7
```

输出目录必须不存在。脚本核对隔离服务标记、进程、路径，再更换它自己的聊天静态文件；
不会发布到正式服务。每次更换后通过实际 HTTP 比对全部 JS/CSS 字节，结束时恢复基线。
检查 `report.json` 的 `complete`、`restoredBaseline`、所有样本及异常字段。
服务退出后还须检查 state 中 `integrity.json` 的消息摘要前后一致。
报告和截图留在私有目录，不提交真实账号状态或用户内容。
可用 `--width 1440` 或 `--width 390` 单独复核某个视口；报告保留实际宽度与计划样本数，
单视口结果不能声明覆盖完整矩阵。

## 计时与判定

- 宽度 1440/390、高度 900，CPU 原速/四倍减速；普通网络为 20ms、100Mbps，
  弱网为 800ms、1Mbps（上下行相同）。这是 Chromium 模拟配置，不代表所有真实设备。
- 每个宽度/CPU 组合创建两份独立浏览器上下文，字体与模块预热后，按轮交替 A/B、B/A。
  默认 7 轮共 1232 个操作；每个精确的操作、消息类型、网络、设备、版本组合各 7 个样本。
- 窄屏工具栏最初隐藏，插件要在工具栏进入可见区域后才挂载。预热先真实触摸输入框，
  等待本夹具的“模型设置”入口及无模型提示出现，再移开焦点、等字体和请求完成。
  程序 `focus()` 按产品设计不展开窄屏输入卡，不能用它代替触摸。
  报告保存这项前置条件；首次聚焦的插件加载属于冷操作，需另测，不能称作热路径。
- 从真实 `pointerdown` 或 `input` 开始，正文/草稿/光标/引用/剪贴板满足独立原文校验，
  再经过两帧记为 `contentMs`。有限时间轴动画结束且两帧几何稳定后记为 `settledMs`。
  不等待随滚动位置变化的动画走到终点。
- 每个操作记录请求、错误、样式/布局/脚本耗时和留白几何。热操作下载 JS/CSS/字体，
  或出现请求失败、页面错误、非预期写请求，都使该次运行失败。
- 比较中位数时按宽度、CPU、网络、操作及消息类型分别分组，不能把快操作平均进慢操作。
  当前候选预先固定的收益门槛：CPU×4 下，引用、取消、编辑、清空在每个设备/网络组合
  的稳定耗时同时降低至少 20% 和 100ms；其他操作的内容/稳定耗时退步不得超过
  `max(25ms, 基线的 10%)`。验收门槛须在运行前确定，保留失败结果。
- 300ms 绝对目标另行统计每个样本及超标操作。相对收益通过不等于达成 300ms；
  每组 7 个样本也不能证明稳定的 p95 或所有输入规模上限。

## 证据边界

本测量只覆盖已加载长会话中的消息操作。网络配置确实应用于浏览器，但不依赖网络的
热操作变快，不能证明冷启动、断线重连或服务端保存完成也变快。
需另验贴底/翻阅位置、短屏、已有草稿追加与撤销、其他历史规模及实际线上页面。
本脚本不发送消息、不调用模型，不覆盖真实软键盘、IME、附件上传或全部插件 UI。

输入卡高度仍由 `useComposerClearance` 测量；阅读区留白和返回按钮仍消费实际增量。
候选仅阻断无关正文和输入卡对子树变量的继承，不能用隐藏正文、减少返回数据、
缩短既定动画或改变正确性断言换取分数。

## 本次候选结果

基线为 `8b0f0afa`，候选只增加上述 CSS 继承边界。固定制品的完整热矩阵共 1232 次，
由 V2 的 560 次桌面有效样本与 V3 的 672 次窄屏样本组成。V2 随后的窄屏预热失败
原样保留；V3 修正真实触摸前置条件。两批计时函数、原文、服务与制品字节一致，
每个组合仍有 7 个样本，不能将它写成一次完整运行成功。

CPU×4 的 24 个目标分组全部通过预设收益门槛，其他操作无超门槛退步，
所有配对留白几何一致。但稳定耗时超过 300ms 的样本仍有基线 315/616、候选 223/616。
12 条富文本加两条长消息的独立短历史复核为 528 次：88 个分组各版本各 3 次，
全文校验通过、几何差异为零、所有分组无超门槛退步；超 300ms 为 95/264 → 64/264。

独立功能验证包括 32 次长/短屏贴底与翻阅位置、12 次已有草稿追加与原生撤销/重做，
以及正式页面中 16 次仅浏览器 CSS 注入的功能检查，均通过；正式服务未部署候选。
另测 24 次页面已加载后的首次工具栏触摸，全部完整就绪时间仍超过 300ms。
候选弱网完整就绪中位数约为 CPU×1 的 1048ms、CPU×4 的 1660ms，未把网络等待删除。
这些结果支持减少样式重算，不支持全部交互或真实手机已达到 300ms。
