# 连接生命周期爬坡

沿用 [启动基准](STARTUP.md) 的真实 Runtime、100 条消息、浏览器和网络档位。
本轮基线是 main `3cb8a396` 加 #1346/#1347 及可选回复服务缺席修复 `4339d787`。
原始恢复点为 `3688ef6e`。初次筛查发现缺席的回复服务会断开整个连接，不能作为健康性能基线。
先冻结测量脚本，再逐项替换聊天构建；不与上一轮旧 main 的绝对耗时混比。

```text
页面生命周期 ── 聊天连接 ── 订阅、心跳、断线恢复
插件目录修订 ── 必要的订阅重建
界面激活进度 ── 界面消费者刷新
```

第一项减少同一目录的界面通知和回调身份变化造成的连接重建；从空白页首次进入会话复用目录连接。
真实目录修订仍刷新订阅；实际断线、发送确认与幂等重试保持现行合同。
不改正式状态；测试服务退出时校验完整消息摘要。

改实现前固定接受标准：

- 基线和最终候选各 7 对冷/热样本、3 个网络档位；使用 `compare-chat-startup.mjs` 交错 A/B 次序，逐轮旋转网络档位。
- 全部历史读取、草稿和订阅成功；累计建连中位数至少降低 50%。
- 字体加载完成后，最后一条连接必须收到回复状态（允许明确不可用），且仅存活一条连接、真实 ping 成功。
  此检查不计入 ready 耗时，但失败会使整个样本失败；不能用短暂显示历史掩盖断线循环。
- 各档相邻对的 ready 差值中位数不退化超过 `max(100ms, 基线中位数的 10%)`；耗时没下降就只报告连接工作减少。
- 单独验证多标签页、实际断线、会话切换、目录刷新与卸载，不将故障样本混入性能采样。
- 保留 `socketsAtReady`、页面关闭前的累计/存活数、峰值、帧类型数量与字节、完整 URL 请求次数。
  峰值包括尚未握手完成的连接；请求数不是 TCP 连接数。字体完成后的关闭时点与原基准一致。
- 报告记录聊天实际入口摘要，防止只验证 dashboard 而误测旧聊天制品。

样本仅访问固定测试会话，不记录正式会话或鉴权信息。浏览器故障注入只用于独立验收。

初次串行采样遇到同时运行的高 CPU 工作，LAN 耗时逐轮漂移；不以这组时延接受或拒绝候选。
正式对照固定 Node/Chromium CPU 亲和性为 0–7，隔离 Runtime 所有线程为 8–15，记录每对采样前后的宿主 load average。
这只能减少异构核心调度差异，不能独占 CPU；因此报告相邻对的变化中位数，不宣称生产性能。
driver 在每次采样前核对同一目录、浏览器、锁文件和 harness 摘要，实际聊天制品按入口摘要区分。
运行前保存当前测试制品，完成或失败时恢复。源码 checkout 身份只描述采样环境，不能代替实际制品身份。

```bash
taskset -c 0-7 node scripts/webui-performance/compare-chat-startup.mjs \
  --url http://127.0.0.1:24142 --browser /absolute/chromium \
  --baseline /absolute/baseline-chat --candidate /absolute/candidate-chat \
  --runtime-chat /absolute/test-state/plugins/akashic_clients/static/chat \
  --output /absolute/results/paired --runs 7
```
