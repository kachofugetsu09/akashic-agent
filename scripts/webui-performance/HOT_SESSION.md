# 热会话切换与脚注选择器

本轮只改变脚注引用附近段落的 CSS 匹配方式。原规则先找含脚注引用的父节点，再选它的段落；
新规则直接选引用之前或之后的兄弟段落。普通段落、脚注内容和历史保留规则不变。

Chromium 样式失效追踪显示，旧规则让没有脚注的普通段落也随着代码块挂载反复失效。
这与下载耗时分开：预热后的切换不应再发起 JS、CSS 或字体请求。

## 复现

使用一次性 Runtime，不连接正式 workspace 或模型账号：

```sh
npm run build
.venv/bin/python scripts/webui-performance/serve-startup-runtime.py \
  --state /tmp/hot-session-new --port 24694 \
  --switch-session-messages 2000 --sessions 40 \
  --reading-markdown scripts/webui-performance/reading-footnotes.md
```

另开终端，把 `--build` 填成该 Runtime 的 `chat-app.build` 值：

```sh
node scripts/webui-performance/measure-hot-session.mjs \
  --url http://127.0.0.1:24694 --build <build> --browser /usr/bin/chromium \
  --output /tmp/hot-session-result-new --runs 3
node scripts/webui-performance/verify-footnote-layout.mjs \
  --url http://127.0.0.1:24694 --build <build> --browser /usr/bin/chromium \
  --output /tmp/footnote-result-new
```

输出目录必须不存在。Runtime 收到 SIGINT 后生成 `integrity.json`，完整消息行摘要必须前后一致。
比较两个版本时分别构建并冻结资源，逐字节核对安装结果；不能用同大小、同 mtime 代替内容相等。
不得同时运行两个计时浏览器，也不在计时期间构建。

## 固定口径

- 同一 Chromium，1440×900，CPU 1/4 倍节流；LAN 20ms/100Mbps，弱网 800ms/1Mbps。
  这是 CDP 网络仿真，没有覆盖真实移动网络丢包、生产外置插件或所有 WebSocket 行为。
- 真实 API、账本历史和渲染器；2,000 条固定富文本历史与 100 条普通历史，显示尾页各 50 条。
- 留在富文本会话等高亮、字体和 20 秒启动预热完成，再切回普通会话。热样本如仍请求静态资源即失败。
- `contentMs`：真实点击到正确末条可见、50 条消息与可用输入框到齐，再过两帧。
  `richMs`：同一次点击到末条代码真正高亮，再过两帧；普通消息也保留第二次采样。
  这不是整段历史所有离屏代码的完成时间，也不是服务端新鲜状态确认时间。
- 请求时间以点击前的监听起点为零；保留方法、路径、完成状态或错误，多观察一秒。
  尚未结束的请求没有完成时间；下一场景开始前等待网络空闲。
- 失败样本和未完成报告保留，进程非零退出；不从分母剔除失败，不用 DOM 安静或占位出现代替正文完成。
- 正式 A/B 固定 7 对，AB/BA 交替，网络顺序也轮换；每个 CPU/网络/内容类别各 7 个样本。
  本轮保留条件是富文本中位数至少改善 15%，普通文本中位数退步不超过 100ms，零失败。
  **这只是本轮候选取舍条件，不替代全交互热路径 300ms 的最终目标。**

## 行为与结果

脚注验收使用真实保存的 Markdown：开头、结尾、中间、多个和重复引用，以及列表、引用块、多段脚注与代码块。
在 1440px 和 390px 下，同一 DOM 的旧、新规则几何与截图像素一致；每个引用都能点击跳转、按 Enter 返回原引用，URL 不变。
此验证不冒充真实模型流式生成验收。

首次构建 A/B 在候选预热时失败，记录保留于 `/tmp/akashic-hot-session-paired-20261031`，
不纳入有效性能结果。原因是复制后把所有文件设成相同 mtime：磁盘内容虽正确，同路径、同大小的入口
仍命中 Runtime 的旧 gzip 缓存，浏览器收到旧入口后请求不存在的旧 chunk。
正式 v2 对两份冻结构建使用不同但足够旧的 mtime，并在每次浏览器运行前核对所有 JS/CSS 的
HTTP 解压字节与冻结文件完全一致，恢复时再次核对。它测的是浏览器热路径，不把服务端压缩缓存预热
称为冷启动；这个实验缺陷不等于已经证明正式部署存在同一问题。
删除脚注样式的诊断实验不作为产品收益证据。
