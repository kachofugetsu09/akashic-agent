# 点击交互基线

不发消息，只回放界面上的点击：切会话、开设置、开面板、切标签、切回窗口。记录每次点击后界面多久稳定、发了哪些请求、是否闪过读取态。目标是找出"每次点都重新读一遍"的地方。#1572 的插件配置缓存问题就属于这一类。

## 口径

- **实例**：隔离的本地实例，数据是生产库的只读副本（`sessions.db` 3.5GB、近万条消息的大会话、297 个附件）。用 sqlite 备份 API 以 `mode=ro` 拷出，不连生产。
- **网络**：浏览器经本地 TCP 延迟代理访问，每个方向 +60ms（RTT 120ms），不限带宽。慢链路对比另加 10Mbps 上限。
- **工具**：`measure-clicks.mjs`，Playwright + CDP，视口 1440×900。每个场景每轮的步骤：
  1. 整页重新加载，执行 `setup` 步骤；
  2. 测"首开"；
  3. 用 `back` 步骤在同一页面内回到点击前的状态；
  4. 再测"重开"。

  默认 5 轮取中位数。
- **指标**：
  - **稳定（doneMs）**：从点击到最后一次 DOM 变化，之后 800ms 内不再变化。同值的属性写入不计，例如每次 scroll 都 `classList.remove` 一个本来就没有的 class。
  - **读取态**：出现"正在读取 / 加载中"等文字，或 `aria-busy`、skeleton、spinner 的轮数。
  - **请求 / KB**：点击后 HTTP 请求的数量与传输量（`encodedDataLength`）。插件查询按 `query:插件.方法` 归类。
- **只读**：场景不发消息、不保存设置、不启停插件。

```bash
node scripts/webui-performance/measure-clicks.mjs \
  --origin http://127.0.0.1:5420 --storage state.json --runs 5 \
  [--only 'settings|focus'] [--out report.json] [--big '9879 条消息'] [--mid '208 条消息']
```

- `--storage` 是 Playwright 的 storageState，保存登录 Cookie。
- `--big` / `--mid` 是侧栏里大、中两个会话行可访问名称的正则片段，按被测数据替换。
- "切回窗口"场景依次派发 `blur`、`visibilitychange`、`focus`，模拟从别的窗口切回来。
- A/B 对比时两套实例共用同一份数据副本，main 与分支交替各跑 1 轮，重复 5 次后取中位数，以抵消机器负载的漂移。
- 两侧数据必须一致。在其中一侧发消息验收会多出会话，侧栏和用量列表随之不同，曾让分支凭空慢了 60–100ms。所以验收放在测量之后做，或者测量前用备份 API 重新同步数据库。

## 交互清单

清单有两个来源：广度爬虫在主页、会话页、设置、插件面板逐层点击所有可见的可点击元素，共采到 88 条记录；再加上对各插件前端读取路径的代码排查。"每次重读"指没有模块级缓存，每次挂载都重新请求。

| 区域 | 可点击 | 点击后加载 | 原状态 |
|---|---|---|---|
| 侧栏 | 会话行 | 消息尾页 + 各插件对新会话的查询（`chat.models` 129KB、`usage.status`、`directory.current`、`bridge.state`） | 尾页有缓存；插件查询每次重读 |
| 侧栏 | 新会话 / 新对话 | `chat.models`、项目列表 | 每次重读 |
| 侧栏 | 项目展开 / 收起、主题、快捷键 | 无 | — |
| 侧栏 | 插件面板 | 各面板短值 | 打开、关闭时各刷新一次 |
| 输入框 | 选择模型、思考强度 | 无（用已加载的目录） | — |
| 输入框 | 新会话的项目下拉 | 每个项目一次 `scope.badge` | N+1 |
| 输入框 | 工作目录、添加文件 | 目录列表 | 每次重读 |
| 消息 | 工具步骤展开、更早步骤、已思考 | 本轮的 `turn.message` / `recall.turn` 插槽 | `cache:"none"` |
| 消息 | 附件预览、可视化卡片 | `/api/chat/artifacts/{id}` | 无缓存头，切会话就重下 |
| 设置 | 打开功能设置、模型 | `models/catalog` 423KB | 每次重下 |
| 设置 | 缓存效率、插件列表 | `cache-usage`、`plugins` | 插件列表已用 `ctx.data.resource` |
| 设置 | 插件配置（13 张卡片） | 每张卡片一次 config GET + 插件设置的 forms | 每次重读，闪读取态 |
| 设置 | 点进插件卡片 | 表单配置 | 每次重读，闪读取态 |
| 设置 | 新手引导 | 目录 → 每步一次状态（两段往返） | 每次重读 |
| 插件面板 | 用量：概览 / 会话 / 上下文 | `usage.insights`、`usage.session`、`usage.spread` | `cache:"none"`，切标签就重挂载 |
| 工作台 | 打开、改动、网站、新标签页 | 改动列表、站点 | 网站页切会话就重读当前制品 |
| 工作台 | 浏览器标签 | 画面流与 iframe | 每次激活都重建（本地无 computer，未测） |
| 窗口 | 切回窗口 | `visibilitychange` 与 `focus` 各触发一次，所有订阅者读两遍 | 重复读取 |

改名会重读整个目录。只有 3 个模块用了 `ctx.data.resource`。

## 问题与对应 PR

| 问题 | PR | 效果（RTT 120ms，5 轮中位数，main→PR） |
|---|---|---|
| 附件框长高也做 300ms 过渡，图表压住回复、整页抖；附件无缓存头 | #1674 | 不再压字和抖动；切回大会话 192→130KB（附件 304）；稳定时间不变 |
| 插件配置卡片与表单每次挂载都重读 | #1675 | 重开插件配置 530→7ms，读取态 5/5→0/5；点进卡片请求 7→3–4 |
| 切回窗口时 focus 与 visibilitychange 各读一遍；`chat.models` 每次重传整个目录 | #1676 | 会话页切回窗口 313→163ms、257→4KB；切会话 128→3KB |
| JSON 接口既不压缩也不带校验头 | #1677 | 10Mbps 下切中等会话 298→204ms、新会话 262→171ms；模型目录 423KB→304 |
| 新手引导目录与状态每次重读 | #1678 | 重开 377→2ms |
| 用量面板每次打开、切标签都闪读取态 | #1679 | 重开面板 147→4ms；切标签读取态 5/5→0/5 |

还没做的：

- 新会话项目下拉的 `scope.badge` N+1；
- 每轮 `turn.message` / `recall.turn` 插槽的缓存；
- 侧栏面板打开、关闭时的刷新；
- 插件配置首开仍有 13 个 GET，要合并需要新的批量接口；
- 新手引导首开的目录→状态 N+1，要改服务端接口；
- 工作台网站页、浏览器标签的重建。

## 已排除

- **打开工作台**：旧口径测出约 330ms，0 个请求。时间线显示这 300ms 是展开过渡期间聊天区每帧 scroll，`NarrowReadingChrome` 每次都 `classList.remove("is-reading")`，产生同值属性写入。排除这类写入后实际 20–32ms。
- **切会话的界面稳定时间**：#1676 之后，不限带宽时基本不变（186→181ms）。剩余时间主要是插件查询往返，以及大会话的 CPU 渲染（见 [SWITCH.md](SWITCH.md)）。
