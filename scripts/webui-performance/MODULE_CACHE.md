# 模块缓存与弱网重开

`webHost.ts` 的本机模块摘要表示“这个版本执行过”，不保证浏览器仍有对应 URL 的 HTTP 缓存。首访通过 bootstrap 内联字节执行模块，URL 预热延后 20 秒；提前重开、缓存逐出或省流量模式都会留下“有提示、没缓存”的组合。旧路径直接 URL import，再次下载当前 bootstrap 已携带的字节。

```text
┌───────────────────────────┐
│ 当前 bootstrap 与模块描述符 │
└─────────────┬─────────────┘
              ▼
        本机提示 + HTTP 缓存
          ┌───┴────┐
          │ 命中   │ 未命中
          ▼        ▼
       URL import  校验当前内联字节后 import
          └───┬────┘
              ▼
       原有依赖顺序激活插件
```

缓存探测使用同源 `only-if-cached`，不会补发网络下载；Chromium 的未命中可能抛 TypeError，其他实现可返回 504。未命中撤回本轮提示，让原有空闲预热补齐。目录换代不复用同一文档中的模块实例。依据：[MDN Request.cache](https://developer.mozilla.org/en-US/docs/Web/API/Request/cache)。

## 重现

按 [STARTUP.md](STARTUP.md) 构建并启动真实隔离 Runtime；不使用正式 workspace。相同服务、消息、插件目录和浏览器下，分别安装基线与候选 dashboard 产物。切换前核对 fixture 进程及端口，只替换其 `plugins/ui/static/dashboard`，用 `rsync -a --checksum --delete`，并将资产 mtime 统一到 `1767225600`。保留初始产物，实验后按内容恢复。

```bash
node scripts/webui-performance/measure-module-cache.mjs \
  --url http://127.0.0.1:24682 --browser /usr/bin/chromium \
  --output /absolute/new/result --profile weak --cpu 1
```

每次使用新浏览器 context，固定 1440×900、已完成引导、`akashic:startup-benchmark` 的 100 条真实消息。初访不节流，随后依次测：

- `early-reload`：20 秒预热前立即重开；初访超过 20 秒则失败，不能冒充缺缓存样本。
- `cached`：真实下载全部内容寻址模块并等待字体后重开。
- `evicted`：清空该浏览器的 HTTP 缓存，保留本机提示后重开。

就绪要求固定尾页消息出现、草稿写入读回并清空、完成绘制、无版本错配或模块激活错误。该指标不是首个加载提示，也不代表模型回复或所有插件数据均已刷新。资源记录区分网络字节与缓存读取；缺缓存探测虽出现在浏览器请求事件中，但不向源站下载模块。初始化、取证及交互失败保留在报告，缺样本返回非零。

LAN 参数为 20ms、下行 100Mbps；弱网为 800ms、上下行 1Mbps。CDP 不模拟丢包或运营商链路。服务为本地真实 Runtime，含 28 个 Web 模块，无模型账号，不发送消息；不等同于生产的外置插件组合验收。
