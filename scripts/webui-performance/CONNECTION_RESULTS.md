# 聊天连接爬坡结果

2026-10-14；基线、方法和冻结标准见 [CONNECTIONS.md](CONNECTIONS.md)。

84/84 个样本通过；累计 WebSocket 建连中位数从 5 降为 2（减少 60%）。
每个页面稳定后只有一条连接，真实 ping、回复状态、历史末条和草稿均通过。

| 网络 / 缓存 | 相邻对 ready 差值中位数 | 相邻对百分比中位数 |
|---|---:|---:|
| lan/cold | +134 ms | +3.8% |
| lan/warm | +146 ms | +4.4% |
| latency/cold | -598 ms | -9.5% |
| latency/warm | -358 ms | -6.9% |
| limited/cold | -272 ms | -3.2% |
| limited/warm | +232 ms | +5.6% |

全部满足预设的 `max(100ms, 基线中位数 10%)` 退化门槛。
主要确定收益是连接工作减少；不能称为所有网络都更快。宿主仍有其它高 CPU 工作，相邻差值与各组绝对中位数不可混用。

独立功能验收：

- 生产构建五个标签页各建连 2 次；切断真实 TCP 后各重连 1 次，约 1.05 秒恢复。
- 草稿保留，消息/摘要订阅恢复；元数据通知使用最新的置顶刷新回调；切回已有会话可跟随；关闭页面后连接释放。
- 完整开发页面重复读取真实目录 3 次，无重连；修改隔离副本中已激活的 Projects 模块并执行正式 SIGHUP 扫描后，只重连 1 次，历史和回复状态恢复，目录切换没有 HTTP 错误。
- 聊天类型检查与生产构建通过；恢复构建产生的插件制品变更，不提交生成文件。
